# Chapter 1: Introduction

## Purpose of This Document

This document explains how to use MCDM (Multi-Criteria Decision Making) to determine which individuals, trials, or candidate solutions obtained through multi-objective optimization should be considered for adoption.

MCDM is a methodology for comparing, evaluating, and ranking candidate alternatives while simultaneously considering multiple evaluation criteria. For problems where the quality of a solution cannot be judged by a single number, MCDM organizes the values for each criterion, their relative importance, and the decision-maker's preferences, and supports decision-making in an explainable manner.

This document treats MCDM not merely as a set of formulas and algorithms, but as a technical component that bridges the outputs of multi-objective optimization with the decision-making process. Specifically, it covers: handling the Pareto front, the correspondence between objective functions and evaluation criteria, constraint processing, weighting, normalization, representative MCDM methods, interpretation of results, and design considerations for system implementation.

## Overview of MCDM

MCDM is a framework for judging which alternative is most desirable overall in situations where multiple evaluation criteria exist.

For example, when a multi-objective optimization is run to "maximize accuracy while minimizing processing time and cost," the result is often not a single best individual but a set of trade-off candidates. The individual with the highest accuracy may be disadvantaged in processing time or cost, while the one with the lowest cost may lack sufficient accuracy.

In MCDM, these multiple perspectives are defined as evaluation criteria and used to assess each individual. The relative importance of each criterion is then reflected as weights, and an overall evaluation or ranking is computed for each individual.

Typical elements handled in MCDM are as follows.

| Element | Description |
| --- | --- |
| Alternatives | The candidates under comparison. In multi-objective optimization, these correspond to individuals, trials, candidate solutions, design proposals, etc. |
| Evaluation criteria | The perspectives used to assess alternatives. Includes objective functions, constraint margins, risk, stability, etc. |
| Criterion values | The value each individual holds for each evaluation criterion. |
| Weights | The relative importance of each evaluation criterion. |
| Evaluation method | The method used to compute an overall score from criterion values and weights. |
| Ranking | The ordering of alternatives based on their overall scores. |

An important point about MCDM is that the decision process can be made explicit. Because it is possible to explain which criteria were used, which were prioritized, and which calculation method was used to produce the ranking, MCDM is well suited for building consensus among stakeholders and for verifying results.

## Intended Audience

This document is intended for the following readers.

- Engineers who want to understand decision-making methods that use multiple evaluation criteria
- Developers implementing MCDM in systems or analysis tools
- Analysts who want to select candidate individuals from multi-objective optimization results
- Designers who want to compare methods such as AHP, TOPSIS, VIKOR, and PROMETHEE
- Users who want to make the decision-making process—including criteria design and weighting—explainable

While this document touches on the mathematical background of MCDM, its primary goal is to build a practical understanding for real-world use. For this reason, each chapter explains not only the formulas but also the meaning of input data, how to interpret results, and implementation considerations.

## Terminology Definitions

The main terms used in this document are defined below.

| Term | Description |
| --- | --- |
| MCDM | Abbreviation for Multi-Criteria Decision Making. A collective term for decision-making methods that compare and evaluate alternatives based on multiple evaluation criteria. |
| Alternative | A candidate subject to evaluation. In optimization, corresponds to a trial or solution. |
| Evaluation criterion | A perspective used to assess alternatives. Also referred to as an objective function, indicator, or attribute. |
| Individual | A single candidate solution generated by an optimization algorithm. May be used interchangeably with trial, solution, or design proposal. |
| Pareto front | The set of non-dominated solutions that are not dominated by any other individual. The primary set of candidates from multi-objective optimization results. |
| Pareto dominance | The relationship in which one individual is at least as good as another in all objectives and strictly better in at least one objective. |
| Decision matrix | A matrix of criterion values arranged for each combination of alternative and evaluation criterion. |
| Weight | A value representing the relative importance of an evaluation criterion. Typically handled so that weights sum to 1. |
| Benefit criterion | An evaluation criterion where larger values are more desirable. Examples: performance, quality, profit. |
| Cost criterion | An evaluation criterion where smaller values are more desirable. Examples: price, time, risk, loss. |
| Normalization | The process of converting criterion values with different units or scales into a comparable form. |
| Overall score | The aggregate evaluation value for each alternative obtained by integrating multiple evaluation criteria. |
| Sensitivity analysis | Analysis to examine how changes in weights or criterion values affect the ranking results. |

## How to Read This Document

To get an overview of MCDM, reading Chapters 2 through 4 first will provide an understanding of basic concepts, the relationship with multi-objective optimization, and the idea of building a candidate set from the Pareto front.

For those who want to implement calculations, focusing on Chapters 5 through 10 will cover the design of evaluation criteria, weighting, MCDM methods, normalization, and the overall flow of evaluation computation.

For guidance on practical adoption and operational considerations, refer to Chapters 11 through 14, which cover interpretation of ranking results, sensitivity analysis, explainability, and design considerations for system implementation.

This document treats MCDM not as a mechanism that automatically determines the single correct answer, but as a technology for organizing multiple decision-making inputs and making decisions explainable. In the final decision, it is necessary to verify not only the computed results but also the assumptions, the validity of the evaluation criteria, and stakeholder consensus.
