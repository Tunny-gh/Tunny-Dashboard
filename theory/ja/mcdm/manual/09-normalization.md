# 第9章 最適化結果データの正規化

## 正規化が必要な理由

MCDMでは、複数の評価基準を同時に扱います。評価基準ごとに単位や値の範囲が異なるため、そのまま合計したり距離を計算したりすると、値のスケールが大きい基準が過度に強く影響します。

例えば、価格が「円」で数十万の値を取り、品質スコアが「1〜5」の値を取る場合、単純に数値を足し合わせると価格の影響が支配的になります。これは価格が本当に重要だからではなく、単位とスケールが大きいだけです。

正規化は、異なる単位や範囲を持つ評価値を、比較可能な尺度に変換する処理です。正規化により、各評価基準の値を同じ土台で扱えるようになります。

正規化が必要になる主な理由は次のとおりです。

| 理由 | 説明 |
| --- | --- |
| 単位の違い | 円、秒、割合、スコアなど異なる単位を比較するため。 |
| スケールの違い | 値の範囲が大きい基準が過度に影響することを防ぐため。 |
| 評価方向の違い | 大きいほど良い基準と小さいほど良い基準をそろえるため。 |
| 手法の前提 | TOPSISやWSMなど、正規化済みの値を前提とする手法に対応するため。 |
| 説明可能性 | 各基準がどのように総合評価へ寄与したかを説明しやすくするため。 |

正規化は便利な処理ですが、どの方式を選ぶかによって結果が変わる場合があります。そのため、正規化方式は計算上の都合だけで選ぶのではなく、評価基準の性質やMCDM手法の前提に合わせて選ぶ必要があります。

## Min-Max正規化

Min-Max正規化は、評価値を指定された範囲、一般的には0から1に変換する方法です。MCDMでは、ベネフィット型基準とコスト型基準で式を分けて使います。

ベネフィット型基準、つまり値が大きいほど望ましい基準では、次の式を使います。

$$
r_{ij} = \frac{x_{ij} - x_j^{\min}}{x_j^{\max} - x_j^{\min}}
$$

コスト型基準、つまり値が小さいほど望ましい基準では、次の式を使います。

$$
r_{ij} = \frac{x_j^{\max} - x_{ij}}{x_j^{\max} - x_j^{\min}}
$$

ここで、$x_{ij}$ は代替案 $i$ の評価基準 $j$ に対する評価値、$x_j^{\min}$ は基準 $j$ の最小値、$x_j^{\max}$ は最大値です。正規化後の値 $r_{ij}$ は0から1の範囲になります。

例として、処理速度が大きいほど良い場合を考えます。

| 代替案 | 処理速度 | Min-Max正規化後 |
| --- | ---: | ---: |
| A | 100 | 0.00 |
| B | 150 | 0.50 |
| C | 200 | 1.00 |

一方、処理時間が小さいほど良い場合は、値の向きを反転します。

| 代替案 | 処理時間 | Min-Max正規化後 |
| --- | ---: | ---: |
| A | 10 | 1.00 |
| B | 20 | 0.50 |
| C | 30 | 0.00 |

Min-Max正規化の強みは、結果が0から1に収まり、直感的に解釈しやすいことです。WSMやAHPの加重和スコアでは、正規化後の値をそのまま重み付きで合計しやすくなります。

一方で、Min-Max正規化は外れ値に敏感です。非常に大きい値や非常に小さい値が1つでもあると、他の値が狭い範囲に押し込まれ、差が小さく見えることがあります。

## ベクトル正規化

ベクトル正規化は、各評価基準の列をユークリッドノルムで割る方法です。TOPSISでよく使われます。

評価基準 $j$ について、正規化値 $r_{ij}$ は次のように計算します。

$$
r_{ij} = \frac{x_{ij}}{\sqrt{\sum_{i=1}^{m} x_{ij}^2}}
$$

ここで、$m$ は代替案の数です。各列をベクトルとして見たとき、その長さが1になるように変換します。

例として、ある基準の値が次のように与えられているとします。

| 代替案 | 評価値 |
| --- | ---: |
| A | 3 |
| B | 4 |

この列のユークリッドノルムは次のとおりです。

$$
\sqrt{3^2 + 4^2} = 5
$$

したがって、正規化後の値は次のようになります。

| 代替案 | 評価値 | ベクトル正規化後 |
| --- | ---: | ---: |
| A | 3 | 0.60 |
| B | 4 | 0.80 |

ベクトル正規化は、距離計算と相性がよい方法です。TOPSISでは、ベクトル正規化後に重みを掛け、正理想解・負理想解との距離を計算します。

ただし、ベクトル正規化では、正規化後の値が必ず0から1の範囲で直感的な「達成率」になるわけではありません。また、負の値を含む場合や、値の方向がコスト型である場合は、手法の定義に従って理想解・反理想解の扱いを明確にする必要があります。

## コスト型基準の処理

MCDMでは、評価基準ごとに値の望ましい方向が異なります。性能や利益のように大きいほど望ましい基準もあれば、価格、時間、リスクのように小さいほど望ましい基準もあります。

コスト型基準を適切に処理しないと、本来は小さいほど良い値が、計算上は大きいほど良い値として扱われてしまいます。これはランキング結果を根本的に誤らせます。

代表的な処理方法は次のとおりです。

| 方法 | 説明 | 主な用途 |
| --- | --- | --- |
| 反転型Min-Max | 最大値からの差を使って0〜1に変換する | WSM、AHPの加重和 |
| 理想解で処理 | コスト型では最小値を正理想解、最大値を負理想解とする | TOPSIS |
| ギャップで処理 | 最適値と最劣値との差を使う | VIKOR |
| 逆数変換 | $1 / x$ などで小さい値を大きい値に変換する | 比率的な評価。ただしゼロに注意 |

例えば、Min-Max正規化では、ベネフィット型とコスト型で式を分けることで、正規化後はどちらも「大きいほど良い」値として扱えます。

| 代替案 | コスト | 正規化後 |
| --- | ---: | ---: |
| A | 100 | 1.00 |
| B | 150 | 0.50 |
| C | 200 | 0.00 |

このように変換すれば、低コストの代替案ほど高い正規化値を持ちます。

TOPSISでは、必ずしもコスト型を事前に「大きいほど良い」へ変換する必要はありません。評価方向に応じて、コスト型では最小値を正理想解、最大値を負理想解として扱います。重要なのは、どの段階で評価方向を反映するかを明確にすることです。

## 外れ値・極端解の影響

多目的最適化結果には、特定の目的だけが非常に優れた極端解が含まれることがあります。極端解はパレートフロントの端を理解するうえで重要ですが、正規化では注意が必要です。

例えば、Min-Max正規化では最大値と最小値が基準になります。極端に小さいコストや極端に高い性能を持つ個体が1つあると、他の個体の正規化値が狭い範囲に押し込まれ、差が見えにくくなることがあります。

確認すべき点は次のとおりです。

| 確認項目 | 説明 |
| --- | --- |
| 極端解の妥当性 | 実測値、シミュレーション値、入力ミスのどれかを確認する。 |
| 制約状態 | 極端解が制約ギリギリまたは実行不能でないか確認する。 |
| 正規化への影響 | 極端解の有無で上位個体が大きく変わらないか確認する。 |
| 候補集合の範囲 | 全個体、非劣解集合、上位候補だけのどれで正規化するかを決める。 |

実務では、極端解を除外するのではなく、まず可視化して意味を確認します。そのうえで、採用候補として不適切な場合は候補集合から外す、または感度分析で極端解を含む場合と含まない場合を比較します。

## 正規化方式による結果への影響

正規化方式は、MCDMの結果に影響します。同じ評価行列、同じ重み、同じMCDM手法を使っても、正規化方式が異なればスコアやランキングが変わる場合があります。

主な影響は次のとおりです。

| 影響 | 説明 |
| --- | --- |
| 外れ値の影響 | Min-Max正規化は最大値・最小値に強く依存する。 |
| 距離の解釈 | ベクトル正規化はTOPSISのような距離計算と相性がよい。 |
| 比率の扱い | WPMでは比率的な差を扱いやすいが、0や負値に注意が必要。 |
| スコア範囲 | 0〜1に収まる方式は説明しやすいが、方式ごとの意味は異なる。 |
| ランキング安定性 | 正規化方式を変えると順位が入れ替わる場合がある。 |

例えば、Min-Max正規化では、評価値の範囲内で相対的な位置を見ます。ベクトル正規化では、列全体をベクトルとして扱い、各値の大きさを列全体の長さに対する比率として扱います。どちらもスケールをそろえる方法ですが、数値の意味は異なります。

正規化方式を選ぶ際は、次の点を確認します。

- 使用するMCDM手法で標準的に使われる正規化方式は何か
- 評価値に外れ値が含まれていないか
- 0や負の値を含む評価基準があるか
- 正規化後の値をどのように説明するか
- 正規化方式を変えても上位候補が安定しているか

実務では、正規化方式を固定する前に、いくつかの方式で結果を比較することが有効です。特に上位候補が正規化方式によって大きく入れ替わる場合は、評価基準の設計、外れ値、重み、手法の前提を再確認します。

## 実装時の注意点

正規化処理をシステムに実装する場合は、数式だけでなく、例外ケースの扱いを明確にする必要があります。

代表的な注意点は次のとおりです。

| 注意点 | 対応例 |
| --- | --- |
| 最大値と最小値が等しい | その基準は代替案を区別しないため、正規化値を0または一定値にする。 |
| 列ノルムが0 | ベクトル正規化でゼロ除算を避け、正規化値を0として扱う。 |
| 欠損値がある | 補完、除外、エラーのいずれかを明確にする。 |
| 負の値がある | 手法が負値を許容するか確認し、必要ならMin-Max変換する。 |
| 評価方向が未設定 | 計算を実行せず、ベネフィット型・コスト型の指定を求める。 |

正規化はランキング結果の前提になるため、実装では正規化方式、評価方向、例外処理をログや結果メタデータとして残すことが望ましいです。これにより、後からランキング結果を再現し、なぜその結果になったのかを説明しやすくなります。
