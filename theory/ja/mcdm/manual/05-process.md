# 第5章 多目的最適化結果に対するMCDMプロセス

## プロセスの概要

MCDMは、評価値を入力してスコアを計算するだけの処理ではありません。適切な結果を得るには、問題の定義、評価対象の整理、評価基準の設計、データ収集、重み付け、評価計算、結果の解釈を一連のプロセスとして扱う必要があります。

多目的最適化結果にMCDMを適用する流れは次のとおりです。

```text
1. 問題設定
2. 個体・トライアル・候補解の定義
3. 制約条件と候補集合の整理
4. 評価基準の設定
5. 最適化結果データの整備
6. 重み付け
7. 評価・順位付け
8. 上位候補の解釈
```

この順序は、単なる作業手順ではなく、意思決定の前提を段階的に明確にするための構造です。後の工程で問題が見つかった場合は、前の工程に戻って見直します。例えば、ランキング結果が直感と大きく異なる場合、計算手法だけでなく、評価基準、重み、入力データの品質を確認する必要があります。

## 問題設定

最初に行うべきことは、何を決めたいのかを明確にすることです。MCDMでは、問題設定が曖昧なまま評価基準や重みを決めると、計算結果の解釈が難しくなります。

問題設定では、少なくとも次の点を整理します。

| 項目 | 確認内容 |
| --- | --- |
| 意思決定の目的 | どの個体を採用候補として選ぶ、順位付けする、または比較するのか。 |
| 利用場面 | 結果をどの業務・分析・判断で使うのか。 |
| 制約条件 | 必ず満たすべき条件や除外条件はあるか。 |
| 意思決定者 | 誰の判断や選好を反映するのか。 |
| 結果の使い方 | 最上位個体を採用するのか、上位N個体を候補として残すのか、説明資料に使うのか。 |

例えば「最適化結果から最良のトライアルを選ぶ」という問題でも、目的が異なれば評価の仕方は変わります。性能を最大化したいのか、コストとのバランスを取りたいのか、リスクを避けたいのかによって、評価基準や重みは異なります。

問題設定では、計算前に「何を良いとみなすのか」を言語化することが重要です。

## 個体・トライアル・候補解の定義

代替案は、MCDMで比較・評価する対象です。多目的最適化結果を扱う場合、代替案は個体、トライアル、候補解、設計案などに相当します。

代替案を定義する際は、比較対象として妥当な範囲にそろえる必要があります。性質が大きく異なる候補を同じ評価行列に入れると、ランキング結果が解釈しにくくなります。

代替案の定義で確認する点は次のとおりです。

- 比較対象が同じ目的に対する候補であること
- 評価に必要なデータを取得できること
- 明らかに制約を満たさない個体を除外すること
- 重複する候補や同一条件の候補を整理すること
- 評価時点での前提条件をそろえること

制約を満たさない代替案は、MCDMの計算に入れる前に除外するのが基本です。例えば、予算上限を超える案や、必須要件を満たさない製品は、総合評価で上位になったとしても採用できません。このような条件は評価基準として扱うのではなく、事前のフィルタ条件として扱うほうが分かりやすい場合があります。

多目的最適化では、候補集合としてパレートフロント上の個体を使うのが基本です。ただし、測定誤差、制約余裕、未評価の定性基準を考慮するために、パレートフロント近傍の個体やdominated solutionを含める場合もあります。その場合は、候補集合に含めた理由を記録します。

## 評価基準の設定

評価基準は、個体を比較するための観点です。多目的最適化では、目的関数がそのまま評価基準になることが多いですが、制約余裕、安定性、実装容易性、再現性などの派生指標を加えることもあります。

評価基準には、定量的なものと定性的なものがあります。

| 種類 | 例 | 扱い方 |
| --- | --- | --- |
| 定量基準 | 価格、処理時間、精度、利益、リスク値 | 数値として直接扱いやすい。 |
| 定性基準 | 操作性、保守性、導入しやすさ、サポート品質 | スコア化や段階評価が必要になる。 |

また、評価基準には評価方向があります。

| 評価方向 | 説明 | 例 |
| --- | --- | --- |
| ベネフィット型 | 値が大きいほど望ましい | 性能、品質、利益、精度 |
| コスト型 | 値が小さいほど望ましい | 価格、時間、リスク、損失 |

評価基準を設定するときは、次の点に注意します。

- 意思決定の目的に直接関係する基準を選ぶ
- 似た意味の基準を重複して入れない
- 測定方法やスコア化方法を明確にする
- ベネフィット型かコスト型かを明示する
- 後で説明できる粒度にする

評価基準が多すぎると、重み付けや結果の解釈が難しくなります。一方で、重要な基準が抜けると、ランキングが意思決定の実態を反映しなくなります。必要十分な基準を選ぶことが重要です。

## 最適化結果データの整備

評価基準を設定したら、各個体に対する評価値を整備します。評価値は評価行列として整理され、MCDMの計算入力になります。

評価行列の基本形は次のとおりです。

| 個体 | 基準1 | 基準2 | 基準3 |
| --- | ---: | ---: | ---: |
| A | 10 | 0.80 | 5 |
| B | 12 | 0.75 | 3 |
| C | 8 | 0.70 | 6 |

データ収集では、値の正確性だけでなく、比較可能性も確認します。単位、測定条件、集計期間、評価方法が異なると、同じ評価基準として比較できない場合があります。

確認すべき点は次のとおりです。

- 欠損値や異常値がないか
- 単位が統一されているか
- 測定条件がそろっているか
- minimize / maximize の方向が目的ごとに記録されているか
- 制約違反や実行不能個体の扱いが決まっているか
- 定性評価を数値化した根拠が明確か
- 最新のデータか、評価時点がそろっているか

欠損値がある場合は、補完する、対象から除外する、別の評価基準に置き換えるなどの対応を検討します。どの対応を選んだかは、後で結果を説明できるように記録しておく必要があります。

## 重み付け

重み付けは、評価基準ごとの相対的重要度を定める工程です。重みはMCDMの結果に大きく影響するため、設定方法と根拠を明確にする必要があります。

重みの例は次のとおりです。

| 評価基準 | 重み |
| --- | ---: |
| コスト | 0.30 |
| 性能 | 0.40 |
| リスク | 0.20 |
| 納期 | 0.10 |

多くの場合、重みは合計が1になるように正規化して扱います。ただし、実装上は比率だけを使う手法もあります。その場合でも、説明資料では合計1の形にそろえると解釈しやすくなります。

重み付けには、次のような方法があります。

| 方法 | 説明 |
| --- | --- |
| 等重み | すべての評価基準を同じ重要度として扱う。 |
| 専門家判断 | 専門家や意思決定者が重要度を直接設定する。 |
| AHP | 一対比較により重みを求める。 |
| エントロピー法 | データのばらつきに基づいて客観的に重みを求める。 |

重みは意思決定者の価値判断を表すため、唯一の正解があるとは限りません。そのため、重みを変えたときにランキングがどの程度変化するかを確認する感度分析が重要になります。

## 評価・順位付け

評価・順位付けでは、評価行列、評価方向、重みを用いて、各代替案の総合スコアや順位を計算します。

一般的な計算の流れは次のとおりです。

```text
1. 評価行列を作成する
2. 評価値を正規化する
3. 重みを適用する
4. MCDM手法に従ってスコアを計算する
5. スコアまたは選好関係に基づいて順位を作成する
```

どのようにスコアを計算するかは、使用するMCDM手法によって異なります。例えば、TOPSISは理想解との距離に基づいてスコアを求めます。VIKORは妥協解の考え方に基づいて順位付けを行います。PROMETHEEは代替案間の選好関係を使ってランキングします。

評価・順位付けの段階では、計算結果だけでなく、次の情報もあわせて確認します。

- 上位案と下位案のスコア差
- 重みの影響が大きい評価基準
- 特定の基準だけで極端に有利な代替案
- 欠損値や外れ値の影響
- 手法を変えた場合の順位の安定性

ランキングは意思決定を支援する情報であり、最終判断そのものではありません。特にスコア差が小さい場合は、順位だけで結論を出すのではなく、評価基準ごとの内訳を確認する必要があります。

## 結果の解釈

MCDMの最後の工程は、計算結果を解釈し、意思決定に使える形に整理することです。ランキングが得られても、その理由を説明できなければ、関係者の合意形成や実務での採用は難しくなります。

結果の解釈では、次の点を確認します。

| 確認項目 | 説明 |
| --- | --- |
| 上位案の理由 | どの評価基準がスコアに寄与したか。 |
| 下位案の弱点 | どの評価基準が不利に働いたか。 |
| 重みの影響 | 重要度の設定がランキングにどの程度影響したか。 |
| 順位の安定性 | 重みやデータを少し変えても順位が安定するか。 |
| 実務上の制約 | 計算上は上位でも、採用できない制約がないか。 |

結果を説明する際は、単に「A案が1位」と示すだけでは不十分です。なぜA案が上位になったのか、どの基準で優れているのか、どの前提条件に依存しているのかを示す必要があります。

また、MCDMの結果は評価基準、重み、データ、手法に依存します。これらの前提が変われば結果も変わるため、結果を固定的な正解として扱うのではなく、意思決定の根拠を整理するための材料として扱います。

実務では、最終的な結論とあわせて、次の情報を記録しておくと再現性と説明可能性が高まります。

- 使用した評価基準
- 各評価基準の評価方向
- 評価値の取得元と取得時点
- 重みの設定方法
- 使用したMCDM手法
- ランキング結果
- 感度分析の結果

これにより、後から判断の妥当性を検証しやすくなり、同様の意思決定を繰り返す際にも利用しやすくなります。
