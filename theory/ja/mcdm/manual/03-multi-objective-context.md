# 第3章 多目的最適化とMCDMの位置づけ

## 多目的最適化で得られるもの

多目的最適化は、複数の目的関数を同時に扱いながら、候補となる個体、トライアル、設計案を探索する手法です。単一目的最適化のように一つの最良値へ収束するのではなく、互いにトレードオフを持つ複数の候補解を得ることが多くなります。

例えば、性能を最大化し、コストとリスクを最小化したい場合、性能が高い個体はコストも高くなり、コストが低い個体は性能が不足することがあります。このような状況では、すべての目的で同時に最良となる個体は通常存在しません。

多目的最適化の出力として重要なのは、単一の答えではなく、選択候補の集合です。MCDMは、この候補集合から、意思決定者の価値判断に合う個体を選ぶために使います。

## 探索と選択の違い

多目的最適化とMCDMは、役割が異なります。

| 項目 | 多目的最適化 | MCDM |
| --- | --- | --- |
| 主な役割 | 良い候補解を探索する | 候補解を比較し選択する |
| 入力 | 探索空間、目的関数、制約条件 | 候補集合、評価基準、重み、選好 |
| 出力 | 個体集合、パレートフロント、目的関数値 | スコア、ランキング、選択理由 |
| 判断の性質 | アルゴリズムによる探索 | 意思決定者の価値判断の反映 |

探索段階では、できるだけ多様で有望な個体を見つけることが重要です。選択段階では、その中から採用可能で、目的に合う個体を説明可能な形で選ぶことが重要です。

## 目的関数・制約・評価基準の関係

最適化で使った目的関数は、MCDMの評価基準として使えることが多いです。ただし、目的関数と評価基準は常に同じではありません。

| 種類 | 例 | MCDMでの扱い |
| --- | --- | --- |
| 目的関数 | 精度、コスト、処理時間、重量 | 評価基準として使う |
| 制約条件 | 上限コスト、最小強度、許容リスク | フィルタまたは評価基準として扱う |
| 派生指標 | 安定性、余裕度、実装容易性 | 必要に応じて追加基準にする |
| メタ情報 | トライアル番号、世代、探索条件 | 説明や追跡に使う |

制約を満たさない個体は、MCDMの前に除外するのが基本です。一方で、制約違反の程度を比較したい場合や、許容範囲内で余裕の大きい個体を選びたい場合は、制約余裕や違反量を評価基準として扱うこともあります。

## MCDMを適用するタイミング

MCDMは、通常、最適化の探索後に適用します。代表的な流れは次のとおりです。

```text
1. 多目的最適化を実行する
2. 個体ごとの目的関数値と制約状態を取得する
3. 採用不能な個体を除外する
4. パレートフロントまたは候補集合を作る
5. 評価基準、評価方向、重みを設定する
6. MCDMでスコアとランキングを計算する
7. 上位候補を可視化し、最終選択を行う
```

探索の途中でMCDMスコアを使うこともありますが、その場合は最適化アルゴリズムの探索挙動に影響します。本書では、まず探索後の個体選択にMCDMを使う場面を前提にします。

## MCDMで決めること、決めないこと

MCDMは、個体選択を説明しやすくするための道具です。MCDMの1位が常に採用すべき個体であるとは限りません。

MCDMで整理できることは次のとおりです。

- 複数目的を同じ土台で比較する
- 目的ごとの重要度を重みに反映する
- 上位候補の理由をスコアや寄与で説明する
- 重みを変えたときの順位変化を確認する
- 候補集合の中から意思決定に使う個体を絞り込む

一方で、MCDMだけでは決めきれないこともあります。

- 目的関数に含めていない実務上の制約
- 評価値に現れていないリスク
- データ取得時点や探索条件の妥当性
- 関係者がどのトレードオフを受け入れるか

したがって、MCDMの結果は最終判断そのものではなく、最終判断を説明可能にするための中間結果として扱います。
