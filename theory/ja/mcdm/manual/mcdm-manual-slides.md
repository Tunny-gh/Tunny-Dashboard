# 多目的最適化結果の個体選択に使うMCDM

## 技術説明書スライド

複数目的の探索結果から、説明可能な採用候補を選ぶための考え方と実装ポイント

---

# このスライドの目的

## 探索結果を選択判断につなげる

- 多目的最適化で得られた個体・トライアル・候補解を、MCDMで比較・順位付けする流れを理解する
- 評価基準、重み、正規化、手法選択がランキング結果に与える影響を整理する
- ランキングを最終判断そのものではなく、説明可能な意思決定材料として扱う
- 実装時に必要な入力検証、結果表示、ログ、再計算条件を確認する

---

<!-- _class: section-title -->

# 1. MCDMの全体像

## 何を比較し、何を説明する技術なのか

まず、MCDMの役割と単一基準評価との違いを整理します。

---

# MCDMとは

## 複数基準で候補を比較する枠組み

MCDM（Multi-Criteria Decision Making）は、複数の評価基準を同時に考慮して、代替案を比較・評価・順位付けするための方法論です。

| 要素       | 多目的最適化結果での意味           |
| ---------- | ---------------------------------- |
| 代替案     | 個体、トライアル、候補解、設計案   |
| 評価基準   | 目的関数、制約余裕、リスク、安定性 |
| 評価値     | 各個体が各基準に対して持つ値       |
| 重み       | 評価基準ごとの相対的重要度         |
| ランキング | 総合評価に基づく候補順位           |

---

# MCDMは自動？

## 設定が必要

- どの基準を使ったか
- どの基準を重視したか
- どの正規化方式を使ったか
- どの手法で順位を出したか
- 上位候補がどの前提に依存しているか

これらを明示し、意思決定を説明可能にするための支援技術です。

---

# 単一基準評価との違い

## トレードオフを扱う点が本質的に異なる

| 観点                | 単一基準評価       | MCDM                   |
| ------------------- | ------------------ | ---------------------- |
| 評価基準 (目的関数) | 1つ                | 複数                   |
| 比較方法            | 評価値を直接比較   | 複数基準を統合・比較   |
| 主要課題            | 値の大小判断       | トレードオフの扱い     |
| 重み付け            | 通常不要           | 基準の重要度を反映     |
| 説明対象            | なぜその値が良いか | 何をどれだけ重視したか |

MCDMでは、評価基準の選び方と重みの設定が結果の意味を決めます。

---

# 基本構造

## 候補、基準、重み、手法を組み合わせる

MCDMでは、候補を表に並べ、各候補を同じ評価基準で比較できる形にします。

| 要素     | 役割         | 例                              |
| -------- | ------------ | ------------------------------- |
| 代替案   | 比較対象     | 個体A、個体B、個体C             |
| 評価基準 | 比較する観点 | コスト、性能、リスク            |
| 評価方向 | 値の望ましさ | 小さいほど良い / 大きいほど良い |
| 重み     | 基準の重要度 | 性能0.40、コスト0.30            |
| 手法     | 統合の考え方 | WSM、TOPSIS、VIKOR              |

同じ最適化結果でも、重み・正規化・手法が変わるとランキングは変わります。

---

# 多目的最適化とMCDMの役割

## 探索する工程と選ぶ工程を分けて考える

| 項目       | 多目的最適化                           | MCDM                           |
| ---------- | -------------------------------------- | ------------------------------ |
| 主な役割   | 良い候補解を探索する                   | 候補解を比較し選択する         |
| 入力       | 探索空間、目的関数、制約条件           | 候補集合、評価基準、重み、選好 |
| 出力       | 個体集合、パレートフロント、目的関数値 | スコア、ランキング、選択理由   |
| 判断の性質 | アルゴリズムによる探索                 | 意思決定者の価値判断の反映     |

探索は候補を作る工程、MCDMは候補から選ぶ工程です。

---

# 適用タイミング

## フロー

本マニュアルでは、主に探索後の個体選択にMCDMを使う場面を扱います。

```text
1. 多目的最適化を実行する
2. 個体ごとの目的関数値と制約状態を取得する
3. パレートフロントまたは候補集合を作る
4. 評価基準、評価方向、重みを設定する
5. MCDMでスコアとランキングを計算する
6. 上位候補を可視化し、最終選択を行う
```

---

# MCDMで決めること・決めないこと

## 決めること

- 複数目的を同じ土台で比較する
- 目的ごとの重要度を重みに反映する
- 上位候補の理由をスコアや寄与で説明する
- 重みを変えたときの順位変化を確認する

## 決めきれないこと

- 目的関数に含めていない実務上の制約
- 評価値に現れていないリスク
- 関係者がどのトレードオフを受け入れるか

---

<!-- _class: section-title -->

# 2. 候補集合の作り方

## パレートフロントから比較対象を定義する

ランキング前に、どの個体をMCDMの対象にするかを明確にします。

---

# パレート支配と非劣解

## まず候補集合の土台を作る

最小化問題で、個体 $a$ が個体 $b$ を支配する条件:

$$
f_j(a) \le f_j(b) \quad \forall j
$$

かつ、少なくとも一つの目的 $k$ について:

$$
f_k(a) < f_k(b)
$$

他の個体に支配されない個体を非劣解、非劣解の集合をパレートフロントと呼びます。

---

# パレートフロントを候補集合にする

## 支配されない候補から比較を始める

支配されている個体は、少なくとも一つの別個体に対して、すべての目的で同等以下です。したがって、MCDMではパレートフロント上の個体を候補集合にするのが基本です。

| 状況                     | 対応                                |
| ------------------------ | ----------------------------------- |
| フロントの個体数が多い   | フィルタ、クラスタリング、上位N抽出 |
| 極端解が多い             | 膝点やバランス解を別途確認          |
| 制約ギリギリの個体がある | 制約余裕を評価基準に追加            |
| 近似探索でノイズがある   | スコア差や再評価も確認              |

---

# 劣解を含める場合

## 原則除外、ただし理由があれば比較対象に残す

原則として支配されている個体は除外できます。ただし、次の場合は比較対象に含めることがあります。

- 測定誤差やシミュレーション誤差があり、目的関数値の差が小さい
- パレートフロント上の個体が実務制約を満たさない可能性がある
- 目的関数に含めていない定性基準で優れる個体がある
- 探索途中の候補を広めに比較したい

含めた理由は記録し、上位に来た場合に説明できるようにします。

---

# 膝点・バランス解・極端解

## 上位候補の性格を見分ける

| 種類       | 説明                                         | 選択時の意味               |
| ---------- | -------------------------------------------- | -------------------------- |
| 膝点       | パレートフロント上で交換効率が悪化し始める点 | バランスよく採用しやすい   |
| バランス解 | 複数目的で極端な弱点が少ない点               | 説明しやすい               |
| 極端解     | 特定目的で非常に優れる点                     | 性能重視・コスト重視に合う |

MCDM手法と重みによって、どの性質の候補が上位に出やすいかが変わります。

---

# 個体選択の安全な順序

## 除外、候補化、ランキング、解釈の順に進める

```text
1. 採用不能な個体を除外する
2. パレート支配関係を確認する
3. 非劣解集合を候補集合にする
4. MCDMで候補をランキングする
5. 上位候補を可視化してトレードオフを確認する
6. 最終選択理由を記録する
```

パレート支配は目的関数だけの優劣、MCDMランキングは重み・正規化・追加基準を含む総合評価です。

---

# 3. プロセスと基準設計

## 結果の意味を決める前提を作る

問題設定、候補解、評価基準、制約条件を順に整理します。

---

# MCDMプロセスの全体像

## 計算前の前提整理が結果の質を決める

```text
1. 問題設定
2. 個体・トライアル・候補解の定義
3. 制約条件と候補集合の整理
4. 評価基準の設定
5. 最適化結果データの整備
6. 重み付け
7. 評価・順位付け
8. 上位候補の解釈
```

この順序は、意思決定の前提を段階的に明確にするための構造です。

---

# 問題設定で決めること

## 何を良い候補とみなすかを先に言語化する

| 項目           | 確認内容                               |
| -------------- | -------------------------------------- |
| 意思決定の目的 | 採用候補を選ぶ、順位付けする、比較する |
| 利用場面       | どの業務・分析・判断で使うか           |
| 制約条件       | 必ず満たす条件や除外条件               |
| 意思決定者     | 誰の判断や選好を反映するか             |
| 結果の使い方   | 最上位採用か、上位N候補の絞り込みか    |

計算前に「何を良いとみなすのか」を言語化します。

---

# 評価基準設計の位置づけ

## 基準はランキングの意味そのもの

評価基準はMCDMの前提そのものです。適切でなければ、高度な手法を使っても意思決定に役立つ結果は得られません。

| 観点       | 確認内容                           |
| ---------- | ---------------------------------- |
| 関連性     | 意思決定の目的に直接関係しているか |
| 測定可能性 | 数値または一貫した尺度で表せるか   |
| 比較可能性 | 同じ条件・同じ意味で比較できるか   |
| 独立性     | 他基準と過度に重複していないか     |
| 説明可能性 | なぜその基準を使うのか説明できるか |

---

# 目的関数と評価基準

## 最適化の目的関数だけでは足りない場合がある

| 最適化側の情報 | MCDMでの扱い               | 例                         |
| -------------- | -------------------------- | -------------------------- |
| 目的関数       | 評価基準として使う         | 精度、コスト、処理時間     |
| 制約条件       | 事前フィルタまたは評価基準 | 最大コスト、最小強度       |
| 制約余裕       | 追加評価基準               | 上限までの余裕、違反量     |
| 探索メタ情報   | 説明・追跡情報             | trial id、世代、パラメータ |
| 実務上の観点   | 必要に応じて追加           | 安定性、再現性、実装容易性 |

最適化の目的関数が、最終採用判断に必要な観点をすべて含むとは限りません。

---

# 定量基準と定性基準

## 数値化しやすさと実務上の重要度を分けて考える

| 種類     | 例                         | 注意点                     |
| -------- | -------------------------- | -------------------------- |
| 定量基準 | 価格、処理時間、精度、利益 | 単位や測定条件をそろえる   |
| 定性基準 | 操作性、保守性、導入容易性 | スコア化の基準を明確にする |

定性基準を数値化する場合は、評価者によるばらつきを抑えるためにスコアの意味を具体化します。

例: 保守性5段階評価なら「5」「4」「3」がそれぞれ何を意味するかを事前に定義する。

---

# ベネフィット型・コスト型

## 値が大きいほど良いとは限らない

| 評価方向       | 意味                   | 例                       |
| -------------- | ---------------------- | ------------------------ |
| ベネフィット型 | 値が大きいほど望ましい | 性能、利益、精度、品質   |
| コスト型       | 値が小さいほど望ましい | 価格、時間、リスク、損失 |

評価方向を誤ると、低コストや低リスクの代替案が不利に評価されるなど、結果が根本的に誤ります。

評価基準を定義する段階で、必ず評価方向を記録します。

---

# 制約条件と実行可能性

## 採用不能な候補はランキング前に扱いを決める

| 種類       | 説明                 | 推奨される扱い           |
| ---------- | -------------------- | ------------------------ |
| ハード制約 | 違反すると採用不能   | MCDM前に除外             |
| ソフト制約 | 満たすほど望ましい   | 評価基準として扱う       |
| 制約違反量 | 違反の大きさ         | 除外またはペナルティ基準 |
| 制約余裕   | 上限・下限からの余裕 | 安全側の評価基準         |

制約違反個体を含める場合は、結果表示で実行可能性を明示します。

---

# 評価基準の独立性

## 同じ観点を二重に評価しない

似た意味の基準を複数入れると、その観点の実質的な重みが大きくなります。

| 基準1    | 基準2      | 重複の可能性                   |
| -------- | ---------- | ------------------------------ |
| 処理時間 | 処理速度   | 同じ性能特性を逆方向から表す   |
| 初期費用 | 導入コスト | ほぼ同じ費用項目               |
| エラー率 | 信頼性     | 信頼性をエラー率で評価している |
| 保守性   | 運用負荷   | 運用負荷が保守性の一部         |

重複がある場合は、統合・削除・重み調整を検討します。

---

<!-- _class: section-title -->

# 4. 重み付けと手法選択

## 価値判断を数値化し、統合方法を選ぶ

重みの決め方と、代表的なMCDM手法の違いを確認します。

---

# 重み付けの役割

## 重みは意思決定者の価値判断を表す

重みは、評価基準ごとの相対的重要度を表します。

$$
\sum_{j=1}^{n} w_j = 1
$$

| 評価基準 | 重み |
| -------- | ---: |
| コスト   | 0.30 |
| 性能     | 0.40 |
| リスク   | 0.20 |
| 納期     | 0.10 |

重みは単なる計算パラメータではなく、意思決定者の価値判断です。

---

# シナリオ別重み

## 価値判断を複数パターンで比較する

| シナリオ     | 重み付けの考え方               | 適した確認             |
| ------------ | ------------------------------ | ---------------------- |
| 等重み       | すべての目的を同程度に扱う     | 基準線としての順位     |
| 性能重視     | 性能や品質を重視               | 高性能個体             |
| コスト重視   | コスト、時間、資源消費を重視   | 実装しやすい個体       |
| リスク重視   | リスク、制約余裕、安定性を重視 | 安全側候補             |
| バランス重視 | 最悪基準を避ける               | 極端な弱点が少ない個体 |

複数シナリオで上位に残る候補は、価値判断の変化に対して比較的安定しています。

---

# 重み付け手法

## 主観、合意、データのどれを重視するかで選ぶ

| 手法           | 適している場面                 | 主な注意点                       |
| -------------- | ------------------------------ | -------------------------------- |
| 等重み         | 初期分析、基準線               | すべて同じ重要度という仮定       |
| 専門家判断     | 業務上の価値判断を反映         | 主観性と説明責任                 |
| AHP            | 一対比較で重要度を整理         | 基準数が多いと入力負荷が大きい   |
| エントロピー法 | データから客観的に重みを求める | ばらつきと重要度を同一視する仮定 |

どの手法でも、重みの意味と根拠を記録します。

---

# AHPによる重み付け

## 一対比較で重みの根拠を作る

AHPは、評価基準同士を一対比較し、その比較結果から重みを求める方法です。

```text
1. 意思決定の目的を定義する
2. 評価基準を階層構造として整理する
3. 評価基準同士を一対比較する
4. 一対比較行列から重みを計算する
5. 整合性比を確認する
6. 重みを使って代替案を評価する
```

一般に、整合性比 $CR \le 0.10$ であれば比較は許容できる程度に整合していると判断します。

---

# エントロピー法

## データのばらつきから重みを求める

エントロピー法は、評価データのばらつきに基づいて重みを求める方法です。

```text
1. 評価値を非負値に変換する
2. 各評価基準の値を比例正規化する
3. 評価基準ごとのエントロピーを計算する
4. 多様度を計算する
5. 多様度を正規化して重みを求める
```

ばらつきが大きい基準ほど、代替案を区別する情報を多く持つとみなします。ただし、業務上の重要度と一致するとは限りません。

---

# 代表的なMCDM手法

## 手法ごとに「良い候補」の捉え方が違う

| 手法      | 読み方     | 主な考え方                           | 適した場面             |
| --------- | ---------- | ------------------------------------ | ---------------------- |
| AHP       | -          | 一対比較から重みを求める             | 重みの根拠を説明したい |
| TOPSIS    | トプシス   | 理想解に近く反理想解から遠い案を選ぶ | 総合的に理想へ近い案   |
| VIKOR     | ヴィコール | 全体効用と最大後悔から妥協解を選ぶ   | バランスのよい妥協解   |
| ELECTRE   | エレクトル | 支持・反対条件から優越関係を見る     | 候補の選別や除外       |
| PROMETHEE | プロメテ   | ペアワイズ選好からフローを計算       | 選好関係の説明         |
| WSM/WPM   | -          | 加重和・加重積                       | 単純な基準線や比率評価 |

---

# TOPSIS

## 理想解に近く、反理想解から遠い候補を選ぶ

TOPSISは、理想解に近く、反理想解から遠い代替案を高く評価します。

```text
1. 評価行列を正規化する
2. 重み付き正規化行列を作成する
3. 正理想解と負理想解を決定する
4. 理想解・反理想解までの距離を計算する
5. 相対的近接度をスコアとして計算する
6. スコア降順でランキングする
```

TOPSISスコアは通常0から1の範囲で、高いほど望ましい候補です。

---

# VIKOR

## 全体効用と最大後悔のバランスで妥協解を選ぶ

VIKORは、理想解に近い妥協解を求める手法です。

| 指標 | 意味                                     |
| ---- | ---------------------------------------- |
| S    | 全評価基準に対する重み付きギャップの総和 |
| R    | 最も悪い評価基準における重み付きギャップ |
| Q    | SとRを統合した妥協指標                   |

戦略パラメータ $v$ により、全体効用を重視するか、最大後悔を重視するかを調整します。$v = 0.5$ なら両者を同程度に扱います。

---

# PROMETHEE / ELECTRE

## PROMETHEE

- 代替案同士のペアワイズ比較に基づくアウトランキング手法
- 正のフロー、負のフロー、ネットフローで選好関係を表す
- PROMETHEE IIではネットフロー降順で完全ランキングを作る

## ELECTRE

- 支持度と反対度から、ある代替案が別の代替案を上回るか判定する
- 単純な総合スコアより、候補の選別や除外に向く
- 閾値設定と結果解釈が複雑になりやすい

---

# WSM

## 加重和法

$$
S_i = \sum_{j=1}^{n} w_j r_{ij}
$$

- 実装しやすく、説明しやすい
- 初期分析や基準線として有効
- 正規化方式の影響を受ける

---

# WPM

## 加重積法

$$
S_i = \prod_{j=1}^{n} r_{ij}^{w_j}
$$

- 比率的な差を反映しやすい
- $r_{ij} > 0$ が必要

---

# 手法選択の考え方

## 計算の高度さより説明したい内容で選ぶ

| 目的                           | 推奨手法  | 理由                     |
| ------------------------------ | --------- | ------------------------ |
| まず単純に総合スコアを作りたい | WSM       | 実装と説明が容易         |
| 理想解に近い候補を選びたい     | TOPSIS    | 距離で説明しやすい       |
| 妥協解を選びたい               | VIKOR     | 全体効用と最大後悔を両立 |
| 重みの根拠を整理したい         | AHP       | 一対比較と整合性確認     |
| 選好関係を詳しく見たい         | PROMETHEE | 代替案間の勝ち負けを分析 |
| 候補を選別・除外したい         | ELECTRE   | 優越関係に基づく絞り込み |

---

# 5. 正規化とランキング計算

## 異なる尺度をそろえてスコアを作る

評価値を比較可能な形に変換し、重み付きスコアと順位を作ります。

---

# 正規化が必要な理由

## 単位とスケールの違いをそろえる

評価基準ごとに単位や値の範囲が異なるため、そのまま合計したり距離を計算したりすると、スケールが大きい基準が過度に影響します。

| 理由           | 説明                                     |
| -------------- | ---------------------------------------- |
| 単位の違い     | 円、秒、割合、スコアを比較する           |
| スケールの違い | 値の範囲が大きい基準の過大影響を防ぐ     |
| 評価方向の違い | 大きいほど良い・小さいほど良いをそろえる |
| 手法の前提     | TOPSISやWSMなどに対応する                |
| 説明可能性     | 各基準の寄与を説明しやすくする           |

---

# Min-Max正規化

## 0から1の範囲に変換して直感的に比較する

ベネフィット型:

$$
r_{ij} = \frac{x_{ij} - x_j^{\min}}{x_j^{\max} - x_j^{\min}}
$$

コスト型:

$$
r_{ij} = \frac{x_j^{\max} - x_{ij}}{x_j^{\max} - x_j^{\min}}
$$

結果が0から1に収まり、直感的に解釈しやすい一方、外れ値に敏感です。

---

# ベクトル正規化

## 距離計算と相性がよい正規化

$$
r_{ij} = \frac{x_{ij}}{\sqrt{\sum_{i=1}^{m} x_{ij}^2}}
$$

各評価基準の列をユークリッドノルムで割る方法です。

- TOPSISのような距離計算と相性がよい
- 正規化後の値が必ず直感的な達成率になるわけではない
- 負の値やコスト型基準では、手法定義に従って理想解・反理想解の扱いを明確にする

---

# 外れ値と正規化方式の影響

## 正規化はランキングを変える前処理

| 影響             | 説明                                       |
| ---------------- | ------------------------------------------ |
| 外れ値の影響     | Min-Maxは最大値・最小値に強く依存          |
| 距離の解釈       | ベクトル正規化は距離計算と相性がよい       |
| 比率の扱い       | WPMは比率的な差を扱いやすいが0や負値に注意 |
| スコア範囲       | 0〜1は説明しやすいが方式ごとに意味が異なる |
| ランキング安定性 | 正規化方式で順位が入れ替わる場合がある     |

正規化方式を変えても上位候補が安定しているか確認します。

---

# 個体ランキング計算の流れ

## 評価行列から順位までを再現可能にする

```text
1. 最適化結果から候補集合を作成する
2. 採用不能な個体を除外する
3. 評価行列を作成する
4. 評価方向を定義する
5. 評価値を正規化する
6. 重みを適用する
7. MCDM手法に従ってスコアを算出する
8. スコアまたは選好関係に基づいてランキングを作成する
9. 上位N個体を比較し、結果を確認する
```

---

# 評価行列の例

## まだ総合評価はできない入力表

| 個体 | コスト | 性能 | リスク |
| ---- | -----: | ---: | -----: |
| A    |    100 |   70 |     20 |
| B    |    120 |   90 |     40 |
| C    |     80 |   60 |     30 |

この段階で総合的な優劣を判断してはいけません。

- コストとリスクは小さいほど望ましい
- 性能は大きいほど望ましい
- 単位と値の範囲が異なる
- 正規化と重み付けが必要

---

# 正規化後の評価行列

## すべての基準を同じ向きにそろえる

Min-Max正規化後、すべての基準を「大きいほど良い」値として扱います。

| 代替案 | コスト | 性能 | リスク |
| ------ | -----: | ---: | -----: |
| A      |   0.50 | 0.33 |   1.00 |
| B      |   0.00 | 1.00 |   0.00 |
| C      |   1.00 | 0.00 |   0.50 |

| 評価基準 | 評価方向       | 重み |
| -------- | -------------- | ---: |
| コスト   | 小さいほど良い | 0.30 |
| 性能     | 大きいほど良い | 0.50 |
| リスク   | 小さいほど良い | 0.20 |

---

# 重み付き評価行列とスコア

## 各基準の寄与を足し合わせる

$$
v_{ij} = w_j r_{ij}
$$

| 代替案 | コスト 0.30 | 性能 0.50 | リスク 0.20 | 総合スコア |
| ------ | ----------: | --------: | ----------: | ---------: |
| A      |        0.15 |      0.17 |        0.20 |       0.52 |
| B      |        0.00 |      0.50 |        0.00 |       0.50 |
| C      |        0.30 |      0.00 |        0.10 |       0.40 |

Aは総合バランス、Bは性能、Cはコストで強みを持ちます。

---

# 6. 解釈・検証・適用例

## 1位をそのまま採用せず、前提を確認する

ランキングの読み方、感度分析、実務での使い方を整理します。

---

# ランキングの読み方

## 順位だけでなく差と根拠を見る

MCDMのランキングは、評価基準、重み、正規化方式、計算手法に基づく相対順位です。

| 確認項目 | 内容                             |
| -------- | -------------------------------- |
| 順位     | どの代替案が上位・下位にあるか   |
| スコア差 | 上位案同士の差が十分に大きいか   |
| 寄与基準 | どの評価基準が順位に影響したか   |
| 前提条件 | 重み、正規化方式、評価方向       |
| 制約条件 | 上位案が必須条件を満たしているか |

---

# 1位をそのまま選ばない場合

## 上位候補は最終確認の対象として扱う

| 状況                       | 対応                             |
| -------------------------- | -------------------------------- |
| 1位と2位のスコア差が小さい | 同等候補として追加比較           |
| 1位が制約ギリギリ          | 制約余裕の大きい候補も確認       |
| 1位が極端解                | バランス解や膝点も候補に残す     |
| 重み変更で順位が変わる     | 複数シナリオで安定する個体を確認 |
| 未評価の実務リスクがある   | 最終判断前に追加評価             |

ランキングは「詳細確認すべき候補を絞る結果」として扱います。

---

# 感度分析

## 前提を変えて結論の安定性を確認する

感度分析は、重みや評価値を変化させたときに、ランキングがどの程度変わるかを確認する分析です。

| 方法           | 説明                              |
| -------------- | --------------------------------- |
| 重み変更       | 特定基準の重みを上下させる        |
| 等重み比較     | 重み設定の影響を見る              |
| 手法比較       | TOPSIS、VIKOR、WSMなどを比較      |
| 正規化方式比較 | Min-Maxとベクトル正規化などを比較 |
| 評価基準除外   | 特定基準を除外した順位変化を見る  |

上位候補の安定性を確認することが主目的です。

---

# 重み変更の説明例

## シナリオごとの1位を比較する

| シナリオ   | 重みの特徴       | 1位 | 備考               |
| ---------- | ---------------- | --- | ------------------ |
| 基準設定   | 通常の重み       | A   | 総合バランスが良い |
| コスト重視 | コスト重みを増加 | C   | 低コスト案が上位   |
| 性能重視   | 性能重みを増加   | B   | 高性能案が上位     |
| リスク重視 | リスク重みを増加 | A   | 低リスク案が維持   |

重み変更による順位変化を示すことで、最終判断がどの価値判断に依存しているかを説明できます。

---

# 適用例: バランス解選定

## 極端解ではなく採用しやすい候補を探す

精度を最大化し、コストと処理時間を最小化する最適化結果を想定します。

| 評価基準 | 評価方向       | 説明                   |
| -------- | -------------- | ---------------------- |
| 精度     | 大きいほど良い | モデルや設計の性能     |
| コスト   | 小さいほど良い | 実装・運用に必要な費用 |
| 処理時間 | 小さいほど良い | 実行にかかる時間       |
| 制約余裕 | 大きいほど良い | 採用後の安全側の余裕   |

TOPSISやVIKORを使うと、理想解に近い個体や最大後悔が小さい個体を見つけやすくなります。

---

# 適用例: 重みシナリオ

## 方針の違いが上位候補を変える

| シナリオ     | 重みの特徴                         | 想定される上位候補       |
| ------------ | ---------------------------------- | ------------------------ |
| 性能重視     | 精度や品質の重みを大きくする       | 高性能だが高コストの個体 |
| コスト重視   | コストや処理時間の重みを大きくする | 実装しやすい低コスト個体 |
| リスク重視   | 制約余裕や安定性の重みを大きくする | 採用リスクが低い個体     |
| バランス重視 | 各目的を比較的均等に扱う           | 極端な弱点が少ない個体   |

シナリオごとに上位個体が大きく変わる場合は、どの価値判断を採用するかを合意します。

---

# 上位候補の可視化比較

## 表だけでなく位置と形でトレードオフを見る

| 可視化           | 確認できること                     |
| ---------------- | ---------------------------------- |
| パレート散布図   | 上位個体がフロント上のどこにあるか |
| 並行座標         | 各目的・評価基準の強みと弱み       |
| ランキングバー   | MCDMスコア差と上位候補の近さ       |
| 重み感度チャート | 重み変更による順位変化             |

上位個体がパレートフロントの端に偏っている場合は、極端解を選んでいる可能性があります。

---

# 7. 導入とシステム実装

## 説明可能性と再現性を運用に組み込む

MCDMを継続利用するための合意形成、入力構造、ログ、再計算条件を扱います。

---

# 導入時の注意点

## 手法を選ぶ前に運用前提を確認する

| 項目     | 確認内容                             |
| -------- | ------------------------------------ |
| 目的     | 何を選定・比較・順位付けしたいのか   |
| 代替案   | 同じ探索結果または同じ条件の候補か   |
| 候補集合 | 全個体、非劣解集合、上位候補など     |
| 評価基準 | 意思決定に必要な観点が含まれているか |
| データ   | 取得元、単位、品質が明確か           |
| 重み     | 誰の価値判断を反映するのか           |
| 利用方法 | 最終決定か、候補の絞り込みか         |

---

# 説明可能性の確保

## なぜその候補なのかを後から説明できるようにする

関係者に説明すべき内容:

- なぜその評価基準を使ったのか
- 評価値はどこから取得したのか
- 重みはどのように決めたのか
- どのMCDM手法を使ったのか
- なぜその個体が上位になったのか
- パレートフロント上のどの位置にある個体なのか
- 制約条件を満たし、採用可能な個体なのか
- 重みや手法を変えても結論は安定しているのか

---

# 合意形成の進め方

## 目的、候補、基準、重みの順に合意する

```text
1. 意思決定の目的に合意する
2. 代替案の範囲に合意する
3. パレートフロントや候補集合の作り方に合意する
4. 評価基準に合意する
5. 評価値の取得方法に合意する
6. 重みの考え方に合意する
7. 結果の使い方に合意する
```

重みで意見が分かれる場合は、単一の重みを無理に決めず、複数シナリオで結果を比較します。

---

# システム実装の全体像

## 計算だけでなく条件管理まで設計する

```text
1. 入力データを受け取る
2. 実行可能性と候補集合を管理する
3. 評価基準と評価方向を管理する
4. 重みを設定または計算する
5. 正規化とMCDM計算を行う
6. スコアとランキングを返す
7. 計算条件と結果を記録する
```

同じ入力条件から同じ結果を再現できること、エラー時に原因を特定できること、結果の前提を説明できることが重要です。

---

# 入力データ構造

## 候補、基準、値、設定を一貫して持つ

| 要素          | 内容                                     |
| ------------- | ---------------------------------------- |
| alternatives  | 個体ID、トライアル番号、名称、メタデータ |
| criteria      | 評価基準ID、名称、単位、評価方向         |
| values        | 代替案 × 評価基準の評価値                |
| weights       | 評価基準ごとの重み                       |
| method        | 使用するMCDM手法                         |
| options       | 正規化方式、VIKORのvなど                 |

# 再計算が必要な変更

## ランキングに影響する設定変更を検知する

- 評価値が変わった
- 代替案が追加・削除された
- 候補集合や制約フィルタが変更された
- 評価基準が追加・削除・変更された
- 評価方向が変更された
- 重みが変更された
- 正規化方式が変更された
- MCDM手法または手法パラメータが変更された

表示順や色など、計算結果に影響しない変更では再計算が不要な場合があります。

# まとめ

## MCDMは説明可能な選択を支援する

- MCDMは、多目的最適化の探索結果を説明可能な個体選択に接続する技術
- 候補集合は、制約条件とパレート支配関係を確認して作る
- 評価基準、評価方向、重み、正規化方式がランキングの意味を決める
- 手法は「何を説明したいか」に応じて選ぶ
- 1位を機械的に採用せず、上位候補、感度分析、可視化で確認する
- 実装では、再現性、ログ、監査性、再計算条件を設計に含める

# 付録: 代表的な数式

## 実装と説明で参照する主要式

| 内容                  | 式                                               |
| --------------------- | ------------------------------------------------ |
| 重みの正規化          | $\sum_{j=1}^{n} w_j = 1$                         |
| 加重和スコア          | $S_i = \sum_{j=1}^{n} w_j r_{ij}$                |
| TOPSISスコア          | $\mathrm{score}_i = \frac{D_i^-}{D_i^+ + D_i^-}$ |
| PROMETHEEネットフロー | $\Phi^{net}(i) = \Phi^{+}(i) - \Phi^{-}(i)$      |

VIKOR:

$$
Q_i = v \cdot \frac{S_i - S^*}{S^- - S^*} + (1 - v) \cdot \frac{R_i - R^*}{R^- - R^*}
$$
