# 第2章 MCDMの基本概念

## 多基準意思決定とは

多基準意思決定（MCDM: Multi-Criteria Decision Making）は、複数の評価基準を同時に考慮して、複数の代替案を比較・評価するための意思決定手法です。

現実の意思決定では、評価したい対象を一つの尺度だけで判断できないことが多くあります。例えば、製品選定では価格、性能、信頼性、納期、保守性を同時に見る必要があります。最適化結果の選定では、目的関数が複数存在し、ある解はコストに優れ、別の解は性能に優れるといったトレードオフが発生します。

MCDMは、このような状況で評価基準を明示し、各代替案の評価値を整理し、必要に応じて基準ごとの重要度を反映して総合評価を行います。これにより、判断の根拠を説明しやすくなり、関係者間で評価の前提を共有しやすくなります。

MCDMの基本的な入力は、次の3つです。

| 入力 | 説明 |
| --- | --- |
| 代替案 | 比較対象となる候補。多目的最適化では個体、トライアル、候補解など。 |
| 評価基準 | 代替案を評価する観点。価格、性能、リスク、品質、目的関数など。 |
| 評価値 | 各代替案が各評価基準に対して持つ値。 |

これらに加えて、評価基準ごとの重要度を表す重みや、値が大きいほど良いのか小さいほど良いのかを示す評価方向を指定します。

## 単一基準評価との違い

単一基準評価では、代替案を一つの評価値だけで比較します。例えば、価格が最も安い製品を選ぶ、処理時間が最も短い手法を選ぶ、利益が最も大きい案を選ぶといった判断です。この場合、評価値を直接比較できるため、順位付けは比較的単純です。

一方で、MCDMでは複数の評価基準を同時に扱います。評価基準が複数になると、ある代替案がすべての基準で最良になるとは限りません。ある案は価格に優れ、別の案は品質に優れ、さらに別の案はリスクが小さいというように、評価基準間で優劣が分かれます。

単一基準評価とMCDMの違いは次のとおりです。

| 観点 | 単一基準評価 | MCDM |
| --- | --- | --- |
| 評価基準 | 1つ | 複数 |
| 比較方法 | 評価値を直接比較する | 複数基準を統合または比較する |
| 判断の難しさ | 比較的単純 | トレードオフの扱いが必要 |
| 重み付け | 通常は不要 | 基準の重要度を反映する場合が多い |
| 説明対象 | なぜその値が良いか | どの基準をどれだけ重視したか |

MCDMでは、評価基準間のトレードオフを扱うことが中心になります。例えば、コストを重視すれば安価な案が上位になり、性能を重視すれば高性能な案が上位になる可能性があります。そのため、MCDMの結果は計算手法だけでなく、評価基準の選び方や重みの設定にも大きく依存します。

## 代替案・評価基準・重みの関係

MCDMでは、代替案、評価基準、重みの関係を評価行列として整理します。評価行列は、行に代替案、列に評価基準を置き、各セルに評価値を入れた表です。

例えば、3つの代替案を4つの評価基準で評価する場合、評価行列は次のようになります。

| 代替案 | コスト | 性能 | リスク | 納期 |
| --- | ---: | ---: | ---: | ---: |
| A | 80 | 70 | 30 | 20 |
| B | 60 | 85 | 45 | 30 |
| C | 75 | 90 | 25 | 25 |

この表だけでは、どの代替案が最も望ましいかを一意に判断できない場合があります。コストやリスクは小さいほど望ましく、性能は大きいほど望ましいため、評価基準ごとに評価方向が異なります。また、納期をどの程度重視するかによっても結論が変わります。

そこで、評価基準ごとに重みを設定します。

| 評価基準 | 評価方向 | 重みの例 |
| --- | --- | ---: |
| コスト | 小さいほど良い | 0.30 |
| 性能 | 大きいほど良い | 0.40 |
| リスク | 小さいほど良い | 0.20 |
| 納期 | 小さいほど良い | 0.10 |

重みは、評価基準の相対的重要度を表します。上の例では、性能を最も重視し、次にコスト、リスク、納期の順に重視しています。多くのMCDM手法では、評価値を正規化したうえで重みを掛け、各代替案の総合スコアや順位を計算します。

この関係を整理すると、MCDMの基本構造は次のようになります。

```text
代替案 × 評価基準 = 評価行列
評価行列 + 評価方向 + 重み = 総合評価
総合評価 = スコアまたはランキング
```

重要なのは、重みは単なる計算パラメータではなく、意思決定者の価値判断を表すことです。同じ評価行列でも、重みが変わればランキングが変わる可能性があります。そのため、MCDMでは結果だけでなく、重みの根拠や感度分析も重要になります。

## MCDMが有効な場面

MCDMは、複数の評価基準が存在し、それらの間にトレードオフがある場面で有効です。特に、判断の根拠を説明したい場合や、関係者間で評価基準を共有したい場合に適しています。

代表的な適用場面は次のとおりです。

| 場面 | 例 |
| --- | --- |
| 製品・サービス選定 | 複数の製品を価格、性能、保守性、サポート品質で比較する。 |
| サプライヤー評価 | 価格、納期、品質、供給安定性、リスクを総合的に評価する。 |
| プロジェクト優先順位付け | 期待効果、実装コスト、リスク、緊急度をもとに着手順を決める。 |
| 投資判断 | 収益性、リスク、初期費用、回収期間を比較する。 |
| 多目的最適化結果の選定 | 複数の目的関数を持つトライアルから、総合的に望ましい解を選ぶ。 |

本書では、このうち多目的最適化結果の選定を主な対象にします。つまり、探索によって得られた個体集合を入力とし、目的関数値、制約状態、追加評価基準を使って採用候補を絞り込む場面を前提にします。

MCDMの利用が特に適しているのは、次の条件を満たす場合です。

- 評価対象となる代替案が複数ある
- 評価基準が複数あり、単一の基準だけでは判断できない
- 評価基準ごとの重要度を明示する必要がある
- 評価結果を関係者に説明する必要がある
- 重みや評価値を変えたときの結果の変化を確認したい

一方で、MCDMを使えば常に客観的な正解が得られるわけではありません。評価基準の選定、評価値の品質、重みの設定には主観や前提条件が含まれます。MCDMは意思決定を自動化するための道具というよりも、意思決定の前提を整理し、比較の根拠を明確にするための支援技術です。

したがって、MCDMを適用する際は、計算結果だけを採用するのではなく、評価基準の妥当性、重みの根拠、ランキングの安定性を確認することが重要です。
