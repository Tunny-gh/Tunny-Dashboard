# 第12章 最適化結果に対する適用例

## 実務適用の考え方

MCDMは、複数の評価基準を同時に考慮する必要がある場面で有効です。実務では、単にランキングを作るだけでなく、評価基準、重み、結果の理由を関係者に説明できることが重要になります。

多目的最適化結果にMCDMを適用する際は、次の流れで考えると整理しやすくなります。

```text
1. どの最適化結果から個体を選ぶのかを定義する
2. 実行不能個体や制約違反個体を除外する
3. パレートフロントまたは候補集合を整理する
4. 目的関数と追加評価基準を決める
5. 重みシナリオを設定する
6. MCDM手法でランキングする
7. 上位候補を可視化し、必要に応じて感度分析する
```

本章では、主に多目的最適化結果から個体を選ぶ適用例を取り上げます。後半では、一般的なMCDM適用例も参考として示します。

## パレートフロント上のバランス解選定

精度を最大化し、コストと処理時間を最小化する最適化結果を考えます。パレートフロント上には、高精度だが高コストの個体、低コストだが精度が低い個体、その中間にあるバランス型の個体が含まれます。

| 評価基準 | 評価方向 | 説明 |
| --- | --- | --- |
| 精度 | 大きいほど良い | モデルや設計の性能。 |
| コスト | 小さいほど良い | 実装・運用に必要な費用。 |
| 処理時間 | 小さいほど良い | 実行にかかる時間。 |
| 制約余裕 | 大きいほど良い | 採用後の安全側の余裕。 |

この場合、TOPSISやVIKORを使うと、理想解に近い個体や最大後悔が小さい個体を候補として見つけやすくなります。最終的には、1位だけでなく上位数個体を散布図や並行座標で比較し、採用しやすいバランス解を選びます。

## 性能重視・コスト重視・リスク重視の選定

同じパレートフロントでも、重みシナリオによって選ばれる個体は変わります。

| シナリオ | 重みの特徴 | 想定される上位候補 |
| --- | --- | --- |
| 性能重視 | 精度や品質の重みを大きくする | 高性能だが高コストの個体 |
| コスト重視 | コストや処理時間の重みを大きくする | 実装しやすい低コスト個体 |
| リスク重視 | 制約余裕や安定性の重みを大きくする | 採用リスクが低い個体 |
| バランス重視 | 各目的を比較的均等に扱う | 極端な弱点が少ない個体 |

複数シナリオで同じ個体が上位に残る場合、その個体は価値判断の変化に対して安定した候補です。一方、シナリオごとに上位個体が大きく変わる場合は、どの価値判断を採用するのかを関係者と確認します。

## 制約付き最適化結果からの採用候補選定

制約付き最適化では、目的関数値が良くても実行不能な個体が含まれることがあります。例えば、性能は高いが最大重量を超える個体や、コスト上限をわずかに超える個体です。

この場合、まずハード制約違反の個体を除外します。その後、制約を満たす個体について、目的関数値と制約余裕を評価基準に含めてMCDMを適用します。

| 評価基準 | 評価方向 | 説明 |
| --- | --- | --- |
| 目的性能 | 大きいほど良い | 最適化で最大化したい性能。 |
| コスト | 小さいほど良い | 上限以下であることが必須。 |
| 制約余裕 | 大きいほど良い | 上限・下限からの余裕。 |
| 安定性 | 大きいほど良い | 条件変動に対する頑健性。 |

制約余裕を評価基準に入れることで、制約ギリギリの個体よりも、採用後のリスクが小さい個体を選びやすくなります。

## 上位候補の可視化比較

MCDMランキングは表だけで確認するより、可視化と組み合わせると解釈しやすくなります。

| 可視化 | 確認できること |
| --- | --- |
| パレート散布図 | 上位個体がフロント上のどこにあるか。 |
| 並行座標 | 各目的・評価基準の強みと弱み。 |
| ランキングバー | MCDMスコア差と上位候補の近さ。 |
| 重み感度チャート | 重み変更による順位変化。 |

特に、上位個体がパレートフロントの端に偏っている場合は、極端解を選んでいる可能性があります。バランス解や膝点も合わせて確認すると、意思決定の説明がしやすくなります。

## 汎用的なMCDM適用例

### 製品選定

製品選定では、複数の製品候補を価格、性能、保守性、サポート品質、導入しやすさなどで比較します。

| 評価基準 | 評価方向 | 説明 |
| --- | --- | --- |
| 価格 | 小さいほど良い | 導入費用やライセンス費用。 |
| 性能 | 大きいほど良い | 処理能力、精度、応答速度など。 |
| 保守性 | 大きいほど良い | 運用・修正・拡張のしやすさ。 |
| サポート品質 | 大きいほど良い | ベンダー対応、ドキュメント、問い合わせ体制。 |
| 導入期間 | 小さいほど良い | 導入完了までの期間。 |

製品選定では、価格だけで最安を選ぶと、性能や保守性で問題が出ることがあります。一方で、性能だけで選ぶと、導入費用や運用負荷が大きくなる可能性があります。MCDMを使うことで、複数の観点を整理し、選定理由を説明しやすくなります。

### サプライヤー評価

サプライヤー評価では、価格、品質、納期、供給安定性、リスクなどを総合的に評価します。

| 評価基準 | 評価方向 | 説明 |
| --- | --- | --- |
| 価格 | 小さいほど良い | 調達コスト。 |
| 品質 | 大きいほど良い | 不良率、品質監査結果など。 |
| 納期遵守率 | 大きいほど良い | 納期どおりに納品された割合。 |
| 供給安定性 | 大きいほど良い | 継続供給能力、在庫体制、代替供給力。 |
| 取引リスク | 小さいほど良い | 財務リスク、地政学リスク、依存リスク。 |

サプライヤー評価では、短期的な価格だけでなく、品質や供給安定性を考慮する必要があります。MCDMにより、コスト削減と安定調達のバランスを比較できます。

### 投資判断

投資判断では、収益性、リスク、初期費用、回収期間、戦略適合性などを比較します。

| 評価基準 | 評価方向 | 説明 |
| --- | --- | --- |
| 期待収益 | 大きいほど良い | 将来的に見込まれる利益。 |
| 初期費用 | 小さいほど良い | 投資開始時に必要な費用。 |
| 回収期間 | 小さいほど良い | 投資回収までの期間。 |
| リスク | 小さいほど良い | 市場、技術、運用上の不確実性。 |
| 戦略適合性 | 大きいほど良い | 事業方針や長期戦略との一致度。 |

投資判断では、数値化しやすい収益性だけでなく、定性的な戦略適合性も重要です。定性基準を使う場合は、スコアリング基準を明確にし、評価者によるばらつきを抑えます。

### プロジェクト優先順位付け

複数のプロジェクト候補がある場合、期待効果、実装コスト、リスク、緊急度、実現可能性などを使って優先順位を決めます。

| 評価基準 | 評価方向 | 説明 |
| --- | --- | --- |
| 期待効果 | 大きいほど良い | 売上増加、効率化、品質改善などの効果。 |
| 実装コスト | 小さいほど良い | 人員、期間、予算。 |
| 実装リスク | 小さいほど良い | 技術的不確実性や依存関係。 |
| 緊急度 | 大きいほど良い | 早期対応の必要性。 |
| 実現可能性 | 大きいほど良い | 現在の体制や技術で実行可能か。 |

プロジェクト優先順位付けでは、スコア上位のプロジェクトをすぐに採用するのではなく、依存関係やリソース制約も確認します。MCDMは候補を整理するための材料として使い、最終判断では実行計画と合わせて検討します。

### リスク評価

リスク評価では、発生確率、影響度、検出しやすさ、対策コスト、緊急度などをもとに、対応すべきリスクの優先順位を決めます。

| 評価基準 | 評価方向 | 説明 |
| --- | --- | --- |
| 発生確率 | 大きいほど重要 | リスクが発生する可能性。 |
| 影響度 | 大きいほど重要 | 発生した場合の損害や影響。 |
| 検出困難度 | 大きいほど重要 | 発生前に検出しにくいほど優先度が高い。 |
| 対策コスト | 小さいほど良い | 対応に必要な費用や工数。 |
| 緊急度 | 大きいほど重要 | 早期対応の必要性。 |

リスク評価では、通常の「良い候補を選ぶ」問題とは異なり、危険度や対応優先度を高く評価することがあります。そのため、評価方向を明確にし、スコアが高いことの意味を関係者に説明する必要があります。

## 適用時の共通注意点

どの適用例でも、MCDMを使う際には次の点を確認します。

- 評価基準が意思決定の目的に合っているか
- 評価値をすべての代替案で取得できるか
- 定性評価のスコア基準が明確か
- 重みの根拠を説明できるか
- 上位候補が制約条件を満たしているか
- 感度分析で結果が安定しているか

MCDMは、実務判断を置き換えるものではありません。複数の判断材料を整理し、比較の根拠を明確にするための支援技術として使うことが重要です。
