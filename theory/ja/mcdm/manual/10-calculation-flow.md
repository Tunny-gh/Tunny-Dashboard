# 第10章 個体ランキング計算の流れ

## 評価計算の全体像

MCDMの評価計算は、評価行列を作成し、評価値を正規化し、重みを適用し、選択したMCDM手法に従ってスコアまたはランキングを求める流れで行います。

一般的な計算手順は次のとおりです。

```text
1. 最適化結果から候補集合を作成する
2. 採用不能な個体を除外する
3. 評価行列を作成する
4. 評価方向を定義する
5. 評価値を正規化する
6. 重みを適用する
7. MCDM手法に従ってスコアを算出する
8. スコアまたは選好関係に基づいてランキングを作成する
9. 上位N個体を比較し、結果を確認する
```

この章では、代表的な加重和型の計算を例に、評価行列からランキングを得るまでの流れを説明します。TOPSIS、VIKOR、PROMETHEEなどの手法ではスコア計算の部分が異なりますが、評価行列、評価方向、正規化、重み付けという前処理の考え方は共通しています。

## 評価行列の作成

評価行列は、行に個体、列に評価基準を配置した表です。各セルには、個体が評価基準に対して持つ評価値を入れます。

例えば、3つの代替案を、コスト、性能、リスクの3基準で評価する場合、評価行列は次のようになります。

| 個体 | コスト | 性能 | リスク |
| --- | ---: | ---: | ---: |
| A | 100 | 70 | 20 |
| B | 120 | 90 | 40 |
| C | 80 | 60 | 30 |

この段階では、値の大小だけで総合的な優劣を判断してはいけません。コストとリスクは小さいほど望ましく、性能は大きいほど望ましいため、評価方向が異なります。また、単位や値の範囲も異なるため、正規化が必要です。

評価行列を作成する際は、次の情報もあわせて定義します。

| 項目 | 例 |
| --- | --- |
| 評価基準名 | コスト、性能、リスク |
| 評価方向 | コスト型、ベネフィット型、コスト型 |
| 単位 | 万円、点、リスクスコア |
| 欠損値の扱い | 除外、補完、エラー |
| データ取得元 | 実測値、見積値、専門家評価など |

評価行列はMCDMの入力データそのものです。ここに誤りや不整合があると、後続の計算結果も不正確になります。

## 候補集合のフィルタリング

評価行列を作る前に、どの個体をMCDMの対象にするかを決めます。多目的最適化結果では、すべての個体をそのままランキングするより、制約状態やパレート支配関係を使って候補集合を整理する方が解釈しやすくなります。

代表的なフィルタリングは次のとおりです。

| 処理 | 目的 |
| --- | --- |
| 実行不能個体の除外 | 採用できない個体をランキング上位に出さない |
| 制約違反個体の除外 | ハード制約を満たす候補だけを比較する |
| 非劣解集合の抽出 | パレートフロント上の候補に絞る |
| 重複個体の整理 | 同じ目的関数値や同一条件の候補をまとめる |
| 外れ値確認 | 入力ミスや異常な探索結果を確認する |

候補集合を絞った場合は、どの条件で除外したかを記録します。ランキング結果だけを見ると、なぜ一部の個体が対象外なのか分からなくなるためです。

## 重み付き評価行列

評価行列をそのまま使うのではなく、まず評価値を比較可能な形に正規化し、その後に重みを適用します。

この例では、次の評価方向と重みを使います。

| 評価基準 | 評価方向 | 重み |
| --- | --- | ---: |
| コスト | 小さいほど良い | 0.30 |
| 性能 | 大きいほど良い | 0.50 |
| リスク | 小さいほど良い | 0.20 |

重みの合計は1です。

$$
0.30 + 0.50 + 0.20 = 1.00
$$

ここでは説明を単純にするため、Min-Max正規化を使います。正規化後は、すべての基準を「大きいほど良い」値として扱います。

### Step 1: 評価値の正規化

コストは小さいほど良いため、反転型Min-Max正規化を使います。

| 代替案 | コスト | 正規化後 |
| --- | ---: | ---: |
| A | 100 | 0.50 |
| B | 120 | 0.00 |
| C | 80 | 1.00 |

性能は大きいほど良いため、通常のMin-Max正規化を使います。

| 代替案 | 性能 | 正規化後 |
| --- | ---: | ---: |
| A | 70 | 0.33 |
| B | 90 | 1.00 |
| C | 60 | 0.00 |

リスクは小さいほど良いため、反転型Min-Max正規化を使います。

| 代替案 | リスク | 正規化後 |
| --- | ---: | ---: |
| A | 20 | 1.00 |
| B | 40 | 0.00 |
| C | 30 | 0.50 |

正規化後の評価行列は次のようになります。

| 代替案 | コスト | 性能 | リスク |
| --- | ---: | ---: | ---: |
| A | 0.50 | 0.33 | 1.00 |
| B | 0.00 | 1.00 | 0.00 |
| C | 1.00 | 0.00 | 0.50 |

### Step 2: 重みの適用

正規化後の評価値に、評価基準ごとの重みを掛けます。

$$
v_{ij} = w_j r_{ij}
$$

ここで、$r_{ij}$ は正規化後の評価値、$w_j$ は評価基準 $j$ の重み、$v_{ij}$ は重み付き評価値です。

| 代替案 | コスト 0.30 | 性能 0.50 | リスク 0.20 |
| --- | ---: | ---: | ---: |
| A | 0.15 | 0.17 | 0.20 |
| B | 0.00 | 0.50 | 0.00 |
| C | 0.30 | 0.00 | 0.10 |

この表が重み付き評価行列です。どの評価基準が各代替案の総合評価にどの程度寄与しているかを確認できます。

## スコア算出

加重和法では、各代替案の重み付き評価値を合計して総合スコアを求めます。

$$
S_i = \sum_{j=1}^{n} w_j r_{ij}
$$

上の例では、各代替案のスコアは次のようになります。

| 代替案 | 計算 | 総合スコア |
| --- | --- | ---: |
| A | 0.15 + 0.17 + 0.20 | 0.52 |
| B | 0.00 + 0.50 + 0.00 | 0.50 |
| C | 0.30 + 0.00 + 0.10 | 0.40 |

この結果では、Aが最も高い総合スコアを持ちます。Bは性能では最も優れていますが、コストとリスクで不利です。Cはコストでは最も優れていますが、性能が低いため総合スコアでは下位になります。

MCDM手法によって、スコアの計算方法は異なります。

| 手法 | スコア算出の考え方 |
| --- | --- |
| WSM | 正規化値に重みを掛けて合計する。 |
| TOPSIS | 正理想解と負理想解からの距離比を計算する。 |
| VIKOR | 全体効用と最大後悔から妥協指標を計算する。 |
| PROMETHEE | 代替案間の選好度からフローを計算する。 |
| AHP | 一対比較から得た重みを使い、正規化値を統合する。 |

したがって、同じ評価行列と同じ重みを使っても、選択するMCDM手法によってスコアの意味は異なります。スコアを比較する際は、どの手法で計算した値なのかを明示する必要があります。

## ランキング作成

スコアを算出した後、手法ごとのルールに従って代替案を並べます。

加重和法やTOPSISでは、スコアが高いほど望ましいため、スコア降順でランキングします。

| 順位 | 代替案 | 総合スコア |
| ---: | --- | ---: |
| 1 | A | 0.52 |
| 2 | B | 0.50 |
| 3 | C | 0.40 |

一方、VIKORではQ値が小さいほど望ましいため、Q値の昇順でランキングします。PROMETHEE IIではネットフローが高いほど望ましいため、ネットフローの降順でランキングします。

ランキング方向を整理すると次のようになります。

| 手法 | ランキング方向 |
| --- | --- |
| WSM | スコア降順 |
| TOPSIS | スコア降順 |
| VIKOR | Q値昇順 |
| PROMETHEE II | ネットフロー降順 |
| AHP | スコア降順 |

ランキングを作成する際は、同点や僅差の扱いも決めておく必要があります。スコア差が非常に小さい場合、順位だけを強調すると誤解を招くことがあります。その場合は、同率扱い、スコア差の表示、感度分析による確認が有効です。

## 上位N個体の比較

多目的最適化結果の個体選択では、1位の個体をそのまま採用するとは限りません。MCDMランキングは候補を絞るための材料であり、最終判断では上位N個体を比較する運用が現実的です。

上位候補の比較では、次の情報を並べます。

| 情報 | 確認内容 |
| --- | --- |
| MCDMスコア | 総合評価でどの程度差があるか。 |
| 目的関数値 | 元の最適化目的でどのようなトレードオフか。 |
| 制約状態 | 採用可能か、制約余裕は十分か。 |
| 寄与基準 | どの基準が順位を押し上げたか。 |
| 重みシナリオ別順位 | 価値判断を変えても上位に残るか。 |

1位と2位のスコア差が小さい場合は、順位ではなく同等候補として扱う方が適切です。特に、測定誤差やシミュレーション誤差がある場合は、僅差の順位を過度に解釈しないようにします。

## 計算例の解釈

上の計算例では、Aが1位、Bが2位、Cが3位になりました。ただし、この順位は次の前提に依存しています。

- 評価基準はコスト、性能、リスクの3つである
- コストとリスクは小さいほど良く、性能は大きいほど良い
- 重みはコスト0.30、性能0.50、リスク0.20である
- 正規化方式はMin-Max正規化である
- スコア計算は加重和法である

前提が変われば、ランキングも変わる可能性があります。例えば、性能の重みを下げてコストの重みを上げると、Cの順位が上がる可能性があります。リスクをより重視すれば、Aがさらに有利になる可能性があります。

このように、MCDMの計算結果は、評価行列、評価方向、正規化方式、重み、手法の組み合わせによって決まります。結果を提示する際は、順位だけでなく、これらの前提もあわせて示す必要があります。

## 実装上の確認ポイント

評価計算をシステムとして実装する場合は、計算手順だけでなく、入力検証と結果の再現性を確保する必要があります。

確認すべき点は次のとおりです。

| 確認項目 | 内容 |
| --- | --- |
| 入力サイズ | 代替案数、評価基準数、評価値配列の長さが一致しているか。 |
| 候補集合 | 実行不能個体や制約違反個体の扱いが明示されているか。 |
| 評価方向 | 各評価基準にベネフィット型またはコスト型が設定されているか。 |
| 重み | 重みが非負で、合計が0ではないか。必要に応じて正規化されているか。 |
| 欠損値 | 欠損値やNaNを補完するのか、除外するのか、エラーにするのか。 |
| ゼロ除算 | 最大値と最小値が等しい場合や列ノルムが0の場合に対応しているか。 |
| ランキング方向 | 手法ごとに昇順・降順を正しく扱っているか。 |
| メタデータ | 正規化方式、重み、手法、実行時刻などを記録しているか。 |

特に、計算結果を後から検証するには、入力データと計算条件を保存しておくことが重要です。ランキングだけを保存しても、なぜその順位になったのかを再現できません。

MCDMの評価計算では、数式の正しさだけでなく、前提条件を明示し、同じ入力から同じ結果を再現できることが重要です。
