# 第13章 MCDM導入時の注意点

## 導入時に確認すべき前提

MCDMを導入する際は、計算手法を選ぶ前に、評価対象、評価基準、データ、関係者、結果の使い方を確認する必要があります。これらが曖昧なまま計算を行うと、ランキングは作成できても、実務で使える判断材料にならない可能性があります。

導入前に確認すべき項目は次のとおりです。

| 項目 | 確認内容 |
| --- | --- |
| 目的 | どの最適化結果から何を選定・比較・順位付けしたいのか。 |
| 代替案 | 比較対象となる個体・トライアルは同じ探索結果または同じ条件の候補か。 |
| 候補集合 | 全個体、非劣解集合、上位候補など、どの範囲を対象にするのか。 |
| 評価基準 | 意思決定に必要な観点が含まれているか。 |
| データ | 評価値の取得元、単位、品質は明確か。 |
| 重み | 誰の価値判断を反映するのか。 |
| 利用方法 | 最終決定に使うのか、候補の絞り込みに使うのか。 |

## 評価基準の偏り

評価基準に偏りがあると、MCDMの結果も偏ります。例えば、性能に関する基準を複数入れ、コストやリスクに関する基準を少なくすると、性能が実質的に過大評価されます。

よくある偏りは次のとおりです。

| 偏り | 例 | 影響 |
| --- | --- | --- |
| 基準の重複 | 処理速度と処理時間を別基準にする | 同じ観点を二重に評価する |
| 基準の欠落 | リスクや保守性を評価しない | 実務上重要な要素が反映されない |
| 測定しやすさ偏重 | 数値化しやすい基準だけを使う | 定性的に重要な要素が抜ける |
| 特定部門の視点偏重 | コスト部門、技術部門など一部の視点に寄る | 関係者全体の合意が得にくい |

評価基準の偏りを防ぐには、基準設計時に関係者レビューを行い、目的に対して必要十分な基準になっているかを確認します。

## 主観的判断の扱い

MCDMでは、重みや定性評価に主観的判断が入ることがあります。主観が入ること自体は問題ではありません。重要なのは、どの判断が主観に基づいているかを明示し、その根拠を説明できるようにすることです。

主観的判断を扱う際の注意点は次のとおりです。

- 評価者を明確にする
- 評価尺度を定義する
- 複数評価者で確認する
- 判断理由を記録する
- 感度分析で主観判断の影響を確認する

例えば、保守性を5段階評価する場合、単に「保守性 = 4」と記録するだけでは不十分です。なぜ4なのか、どの状態を5とし、どの状態を3とするのかを定義する必要があります。

## データ品質の影響

MCDMの計算結果は入力データに依存します。評価値に誤り、欠損、外れ値、測定条件の違いがあると、ランキング結果も歪みます。

データ品質に関する確認項目は次のとおりです。

| 確認項目 | 内容 |
| --- | --- |
| 完全性 | すべての代替案に必要な評価値があるか。 |
| 正確性 | 入力ミスや計算ミスがないか。 |
| 一貫性 | 単位、測定条件、集計期間がそろっているか。 |
| 最新性 | 評価値が意思決定時点で有効か。 |
| 外れ値 | 極端な値が妥当な実測値か。 |
| 制約状態 | 実行不能個体や制約違反個体が混入していないか。 |
| 探索条件 | 比較する個体が同じ探索条件・評価条件で得られているか。 |

データ品質に問題がある場合は、補正、除外、再測定、評価基準の見直しを検討します。対応方針は、結果の説明時に示せるように記録しておきます。

## 説明可能性の確保

MCDMの導入では、ランキング結果を関係者に説明できることが重要です。単に「この手法で計算した結果、Aが1位です」と示すだけでは、納得感は得られません。

説明すべき内容は次のとおりです。

- なぜその評価基準を使ったのか
- 評価値はどこから取得したのか
- 重みはどのように決めたのか
- どのMCDM手法を使ったのか
- なぜその個体が上位になったのか
- パレートフロント上のどの位置にある個体なのか
- 制約条件を満たし、採用可能な個体なのか
- 重みや手法を変えても結論は安定しているのか

説明可能性を高めるには、スコアの内訳、評価基準ごとの寄与、感度分析結果をあわせて示します。総合スコアだけでなく、判断の前提と理由を見える形にすることが重要です。

## 利害関係者との合意形成

MCDMは、複数の関係者が関わる意思決定で特に有効です。ただし、関係者間で評価基準や重みの合意がない場合、ランキング結果に対する納得感は低くなります。

合意形成では、次の順序で確認すると進めやすくなります。

```text
1. 意思決定の目的に合意する
2. 代替案の範囲に合意する
3. パレートフロントや候補集合の作り方に合意する
4. 評価基準に合意する
5. 評価値の取得方法に合意する
6. 重みの考え方に合意する
7. 結果の使い方に合意する
```

特に重みは、関係者の価値判断を反映します。意見が分かれる場合は、単一の重みを無理に決めるのではなく、複数の重みシナリオで結果を比較する方法が有効です。

## 導入後の運用

MCDMは一度計算して終わりではありません。評価データ、候補、重み、事業環境が変われば、ランキングも変わります。

導入後は、次の点を運用ルールとして定めます。

- どのタイミングで再計算するか
- 評価基準を変更する条件は何か
- 重みを誰が更新できるか
- 過去結果をどのように保存するか
- 結果の承認プロセスをどうするか

MCDMを実務で継続的に使うには、計算ロジックだけでなく、評価条件の管理と変更履歴の記録が必要です。
