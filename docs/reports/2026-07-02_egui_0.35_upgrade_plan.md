# egui 0.30 → 0.35 アップグレード調査レポート

作成日: 2026-07-02 / 対象ブランチ: `chore/egui-0.35-upgrade`

## 1. 目的と背景

CI の Security Audit が quick-xml の脆弱性（RUSTSEC-2026-0194 / 0195、細工 XML による計算量 DoS、severity 7.5）で失敗した。原因は eframe 0.30 の Linux 専用推移的依存であり、現在は CI 側で 2 件を ignore して回避している。根本対応として egui ファミリーを最新へアップグレードする。

## 2. バージョン変更

| クレート | 現在 | 更新後 | 備考 |
|---|---|---|---|
| eframe | 0.30 | **0.35.0** (2026-06-25) | wgpu feature 維持 |
| egui | 0.30 | 0.35 | |
| egui_extras | 0.30 | 0.35 | image/file/svg feature 維持 |
| egui-wgpu | 0.30 | 0.35 | |
| egui_plot | 0.30 | **0.36.0** | egui 本体と別バージョン系列（0.35 対応版が 0.36） |
| wgpu | 24 | **29** | eframe 0.35 が wgpu 29.0.4 を要求。直接依存も揃える必要あり |

- **MSRV**: egui 0.34 以降は Rust 1.92。ローカルは 1.96 で問題なし。CI は `dtolnay/rust-toolchain@stable` なので問題なし。

## 3. Security Audit への効果（lockfile で実測済み）

- `quick-xml 0.30.0`（zbus_xml ← accesskit の AT-SPI 経路）は **完全に消滅**。accesskit_winit が 0.23 → 0.32 になり zbus 系が刷新されるため。
- `quick-xml 0.39.4`（wayland-scanner 0.31.10 ← winit）は **残存し、依然として脆弱**（修正版は >=0.41 のみ、wayland-scanner は最新版でも 0.39 系を固定）。
  - ただし wayland-scanner は **ビルド時 proc-macro・Linux ターゲット専用**で、信頼できるローカルの Wayland プロトコル定義 XML しか解析しない。本アプリは Windows/macOS のみ配布のため実リスクなし。
  - → **CI の ignore 2 件（0194/0195）は維持**し、コメントを「zbus 経路は解消済み、wayland-scanner のみ残存」に更新する。

## 4. コンパイルエラー実測（cargo check、lib ターゲットで 141 件）

ブランチ上でバージョンだけ上げて実測した結果。テスト・bin ターゲットは lib 修正後に追加で出る可能性あり。

### 4.1 egui_plot: コンストラクタに name 引数追加（約 90 件・最多）

`Line::new(series)` → `Line::new(name, series)`。`Points` / `Polygon` / `BarChart` / `BoxPlot` 等も同型。既存コードの `.name("…")` ビルダー呼び出しは第 1 引数へ移動する。

- 影響: surrogate_opt.rs (26), pareto_2d.rs (13), mcdm_scatter_chart.rs (12), pdp_chart.rs (10), optimization_history.rs (10), cluster_scatter.rs (8), convergence.rs (8), slice_chart.rs (4) ほかチャート全般
- エラー型: E0061「takes 2 arguments but 1 supplied」+ E0277「String: From<Vec<[f64;2]>>」（データを name 位置に渡していると解釈されるため）

### 4.2 メニュー/ポップアップ API 刷新（0.32、12 件）

- `ui.close_menu()` は削除 → `ui.close()`（コンパイラも同名候補として提示）
- 0.32 からメニューはクリックで自動クローズがデフォルト。**明示クローズが不要になった箇所は削除**し、挙動変更（開きっぱなし前提の UI）がないか目視確認
- `egui::show_tooltip_at_pointer(ctx, layer, id, …)` は削除 → `egui::Tooltip::always_open(ctx, layer, id, pos)` 等の新 Tooltip/Popup API（trial_detail_modal.rs:311）

### 4.3 Panel 統合（0.34 deprecated → 0.35 削除、layout.rs 15 件ほか）

- `egui::TopBottomPanel::top(…)` / `SidePanel::left(…)` → 統合された `egui::Panel::top(…)` / `Panel::left(…)`（layout.rs, right_panel.rs）

### 4.4 eframe App trait 分割（0.34、app.rs）

- `fn update(&mut self, ctx: &Context, frame: &mut Frame)` → 必須メソッド `fn ui(&mut self, ui: &mut Ui, frame: &mut Frame)`
- UI を描かない前処理（メッセージポンプ等）は provided の `fn logic(&mut self, ctx: &Context, frame: &mut Frame)` へ分離可能（logic 内での描画は禁止）
- `Ui` は `Context` へ Deref するため `ui.input(…)` 等がそのまま書ける。旧 `ctx` 参照は `ui.ctx()` で取得

### 4.5 Context メソッドの移動・改名（0.33-0.34、計 5 件）

- `ctx.screen_rect()` → `ctx.content_rect()`（3 件。意図的に safe area 外へ描くなら `viewport_rect()`）
- `ctx.available_rect()` → 削除（`content_rect()` ないし Ui 側 API へ）
- `is_using_pointer` 系の改名 1 件（コンパイラ提案に従う）

### 4.6 描画 API の型変更（0.31、E0308 12 件 + E0061 arity 13 件）

- `Rounding` → `CornerRadius`、`Frame::rounding()` → `corner_radius()`（1 件確認済み）
- `Margin` / `CornerRadius` / `Shadow` が f32 → i8/u8
- `Painter::rect*` 系は `StrokeKind` 引数が必須に（塗り矩形は `StrokeKind::Inside` が原則）

### 4.7 その他

- `ui.push_id(id_salt, …)`: `impl Hash` → `impl AsIdSalt`（= `Hash + Debug`）。ジェネリック境界に `+ std::fmt::Debug` を追加（grid_canvas.rs:631）
- toolbar.rs:328 `f.layout_no_wrap(…)`: Fonts API の可変性変更。`ctx.fonts_mut(…)` 等へ（コンパイラ指示に従う）
- **wgpu 24 → 29**: 3D キャンバス（egui-wgpu の Callback 経由）に直接 wgpu API があれば追加エラーが出る見込み。lib のエラーが多すぎて未到達の可能性があるため、上記修正後に再チェックして対応

## 5. コンパイルエラー以外の検証項目（挙動・見た目の変更）

| 変更 | 確認方法 |
|---|---|
| メニューがクリックで自動クローズ（0.32） | 各メニュー/コンテキストメニューの操作確認 |
| Frame が stroke 幅をパディングに含める（0.31） | 全体レイアウトの目視 |
| ScrollArea のエッジフェード（0.34） | テーブル・リスト表示の目視 |
| フォントレンダラが ab_glyph → skrifa（0.34） | テキスト描画の目視（ヒンティング差） |
| deprecated API | `clippy --all-targets -D warnings` が deprecated 使用で落ちるため、警告ゼロまで完全移行が必須 |

## 6. 作業手順

1. ✅ ブランチ `chore/egui-0.35-upgrade` 作成、Cargo.toml バンプ、lockfile 更新（実施済み）
2. wgpu を 29 へ変更 → Sonnet が §4 の分類順にコンパイルエラーを解消（機械的作業が大半）
3. Fable が API 移行の妥当性をレビュー（特に App trait 分割・メニュー挙動・Tooltip 置換）
4. `cargo test --workspace` / `clippy --all-targets --locked -D warnings` / fmt ×2
5. `.github/workflows/ci.yml` の audit ignore コメントを更新（zbus 経路解消を反映、ignore 自体は維持）
6. `cargo tree --target all -i quick-xml` で残存が wayland-scanner 経路のみであることを最終確認
7. アプリ起動して §5 の目視確認 → コミット

## 7. リスクと退避策

- 変更範囲は egui-app の UI 層に閉じる（rust_core は無関係）。失敗時はブランチ破棄で無傷
- 141 件の大半（約 110 件）は egui_plot の name 引数と Panel/close_menu の機械的置換で、判断を要するのは App trait 分割・Tooltip 置換・wgpu 29 対応のみ
