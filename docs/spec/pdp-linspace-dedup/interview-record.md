# pdp-linspace-dedup ヒアリング記録

**作成日**: 2026-05-01
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

`linspace` 関数の重複（`pdp::utils` と `core::lgbm` の2箇所）に関する配置先を確認するためのヒアリングを実施。

## 質問と回答

### Q1: linspace の共通配置先はどこがよいか

**質問日時**: 2026-05-01
**カテゴリ**: 既存設計確認
**背景**: `pdp::utils::linspace`（`pub(super)`）は `core::lgbm` からアクセス不可。`pdp` → `core` の依存方向があるため `core` → `pdp` の逆参照は循環依存になる。新規モジュール作成か既存モジュールへの追加か選択が必要。

**回答**: core::math に移動（推奨）

**信頼性への影響**:
- この回答により、配置先が確定し REQ-001 の信頼性レベルが 🟡 → 🔵 に向上
- `core::math` は既に `pub(crate)` 公開のディレクトリモジュールであり、新規ファイル追加で対応可能

---

## ヒアリング結果サマリー

### 確認できた事項
- 配置先: `core::math` モジュール（新規ファイル `grid.rs`）
- `pdp::utils` はインポート元を変更し、呼び出し元（ridge_core, kriging_core）は修正不要
- `core::lgbm::pdp_linspace` は削除し `core::math` 版に置換

### 残課題
- なし（軽量リファクタリングのため）
