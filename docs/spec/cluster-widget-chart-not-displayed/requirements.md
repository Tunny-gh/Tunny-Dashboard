# クラスタリング図表示不具合 要件定義書

## 概要

クラスタリング図ウィジェットを配置してもチャートが表示されない問題を解消し、ユーザーが手動実行で確実にクラスタリング結果を可視化できる状態を実現する。🔵 *ユーザー指示 + ヒアリング確定事項*

## 機能要件（EARS記法）

**【信頼性レベル凡例】**:
- 🔵 **青信号**: PRD・EARS要件定義書・設計文書・ユーザヒアリングを参考にした確実な要件
- 🟡 **黄信号**: PRD・EARS要件定義書・設計文書・ユーザヒアリングから妥当な推測による要件
- 🔴 **赤信号**: PRD・EARS要件定義書・設計文書・ユーザヒアリングにない推測による要件

### 通常要件

- REQ-001: システムはクラスタリング図ウィジェット内ヘッダーから手動実行操作を提供し、ユーザー操作時にクラスタリング計算を開始しなければならない。 🔵 *ヒアリング「手動実行で表示」「チャート内ヘッダー」より*
- REQ-002: システムはクラスタリング計算完了時に `ClusteringDone` 相当の完了メッセージを送信し、表示状態を更新しなければならない。 🔵 *実装調査で送信経路不足が主因と判明*
- REQ-003: システムはクラスタリング結果が存在する場合、クラスタリング図にクラスタ色分けされた散布図を表示しなければならない。 🔵 *既存Widget仕様 + ユーザー期待*
- REQ-004: システムはクラスタリング計算中に実行中状態を可視化し、重複実行を防止しなければならない。 🟡 *既存UIメモ（TASK-902）から妥当推測*

### 条件付き要件

- REQ-101: クラスタリング図が配置され、かつクラスタリング未実行の場合、システムは「クラスタリングを実行してください」等の案内メッセージを表示しなければならない。 🔵 *ヒアリング「案内メッセージ表示」より*
- REQ-102: trialデータが空の場合、システムはクラスタリング計算を実行せず、データ不足メッセージを表示しなければならない。 🔵 *既存空データガード + READMEデータ前提*
- REQ-103: 手動実行UIが押下された場合、システムは対象Studyの最新データのみを計算対象にしなければならない。 🟡 *stale防止の設計推測*

### 状態要件

- REQ-201: Study切替時、システムはクラスタリング結果状態と関連キャッシュをリセットしなければならない。 🔵 *ヒアリング「許容できる」より*
- REQ-202: Study切替後に再実行されるまでは、システムは未実行案内メッセージ状態を維持しなければならない。 🔵 *手動実行前提より*

### オプション要件

- REQ-301: システムはクラスタリング実行パラメータ（例: k値）をヘッダー内で変更できるようにしてもよい。 🟡 *TASK-902実装メモから妥当推測*

### 制約要件

- REQ-401: システムは既存のチャート配置/移動/削除挙動を破壊してはならない。 🔵 *chart-catalog要件より*
- REQ-402: システムはデータ未ロード時やWASM未初期化時にクラッシュしてはならない。 🔵 *既存Edge要件 + 実装調査より*
- REQ-403: システムは既存テスト基盤を維持し、回帰を生まない実装を行わなければならない。 🔵 *既存要求（ui-feature-gap/chart-wiring）より*

## 非機能要件

### パフォーマンス

- NFR-001: クラスタリング実行後、可視化更新は1秒以内にUI反映されなければならない。 🟡 *既存性能目標からの妥当推測*
- NFR-002: Study切替時の状態リセット処理は200ms以内に完了しなければならない。 🟡 *既存Study切替要件を準用*

### セキュリティ

- NFR-101: クラスタリング実行パラメータは異常値（k<2 等）をバリデーションし、不正計算を防止しなければならない。 🔵 *TASK-902テストメモより*

### ユーザビリティ

- NFR-201: 未実行・実行中・完了の3状態を視覚的に区別できるUIで提示しなければならない。 🔵 *ヒアリング結果 + UIメモより*

## Edgeケース

### エラー処理

- EDGE-001: 実行中にWASM初期化失敗が発生した場合、システムはクラッシュせずエラーメッセージを表示しなければならない。 🔵 *既存要件のエラー方針より*
- EDGE-002: `ClusteringDone` の件数とtrial件数が不整合な場合、システムは不整合データを破棄して再実行を促さなければならない。 🟡 *実装安全性の妥当推測*

### 境界値

- EDGE-101: trial件数が0件のとき、システムは散布図を描画せず案内メッセージを表示しなければならない。 🔵 *既存ガード挙動より*
- EDGE-102: k値がtrial件数を超える場合、システムは実行を拒否し入力補正を促さなければならない。 🟡 *クラスタリング一般制約 + UIメモより*
