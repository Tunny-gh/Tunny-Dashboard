# HTML Help Browser 要件定義書

## 概要

ヘルプドキュメントの表示方式を、egui内のカスタムMarkdownパーサーによるモーダル表示から、HTML出力＋ブラウザ表示に変更する。現在の md_renderer.rs は数式・テーブル・レイアウトの描画に制限があり、特に数式（`r_ij = v_ij / sqrt(Σ_i v_ij²)` 等）がプレーンテキストで読みづらい。HTML化により KaTeX での数式レンダリング、リッチなテーブル、レスポンシブなレイアウトを実現する。また日本語/英語の両コンテンツをサポートし、アプリ内で言語切替を可能にする。

## 機能要件（EARS記法）

**【信頼性レベル凡例】**:

- 🟡 **黄信号**: PRD・EARS要件定義書・設計文書・ユーザヒアリングから妥当な推測による要件
- 🔴 **赤信号**: PRD・EARS要件定義書・設計文書・ユーザヒアリングにない推測による要件

### ビルド時HTML生成

- REQ-001: システムは、ビルド時に theory/ 配下の全MarkdownファイルをHTMLに変換しなければならない 🔵 *ユーザヒアリング: ビルド時生成選択より*
- REQ-002: システムは、Markdown→HTML変換に pulldown-cmark または同等のRust Markdownパーサーを使用しなければならない 🟡 *Rustエコシステムの標準的選択から妥当な推測*
- REQ-003: システムは、ビルドスクリプト（build.rs）で theory/en/ と theory/ja/ の両方を変換しなければならない 🔵 *ユーザヒアリング: 日英両対応選択より*
- REQ-004: システムは、生成したHTMLを include_str! でバイナリに埋め込まなければならない 🔵 *ユーザヒアリング: ビルド時生成選択より*
- REQ-005: システムは、変換時にHTMLインジェクション対策（ユーザー入力のエスケープ）を実施しなければならない 🔵 *既存 html_report.rs のセキュリティパターンより*

### KaTeX数式レンダリング

- REQ-010: システムは、生成するHTMLに KaTeX のCSSとJSをインライン埋め込みしなければならない 🔵 *ユーザヒアリング: KaTeX埋め込み選択より*
- REQ-011: システムは、Markdown内の `$...$` をインライン数式として KaTeX でレンダリングしなければならない 🔵 *ユーザヒアリング: LaTeX記法書き換え選択より*
- REQ-012: システムは、Markdown内の `$$...$$` をブロック数式として KaTeX でレンダリングしなければならない 🔵 *ユーザヒアリング: LaTeX記法書き換え選択より*
- REQ-013: システムは、オフライン環境でも数式が正しく表示されるようにしなければならない 🔵 *ユーザヒアリング: KaTeX埋め込み選択（CDN不使用）より*

### ヘルプボタン動作変更

- REQ-020: ヘルプボタンをクリックした場合、システムは egui モーダルを開かず、ブラウザでHTMLを開かなければならない 🔵 *ユーザヒアリング: ブラウザのみ選択より*
- REQ-021: システムは、ブラウザ起動に open::that を使用しなければならない 🔵 *ユーザヒアリング: open::that選択より*
- REQ-022: システムは、ヘルプボタン押下時に埋め込みHTMLを一時ファイルに書き出し、そのファイルをブラウザで開かなければならない 🔵 *ユーザヒアリング: ビルド時生成＋ブラウザ表示より*
- REQ-023: システムは、一時ファイルの命名にウィジェット名と言語を含めなければならない 🟡 *デバッグ容易性から妥当な推測*

### 言語切替

- REQ-030: システムは、アプリ内でヘルプ表示言語を日本語/英語から選択可能にしなければならない 🔵 *ユーザヒアリング: アプリ内で切替選択より*
- REQ-031: システムは、言語設定をアプリの状態として保持しなければならない 🔵 *ユーザヒアリング: アプリ内で切替選択より*
- REQ-032: ヘルプボタン押下時、システムは現在選択されている言語のHTMLを開かなければならない 🔵 *ユーザヒアリング: 日英両対応選択より*

### MarkdownファイルのLaTeX記法移行

- REQ-040: theory/ 配下のMarkdownファイル内の数式をコードブロックから LaTeX記法（`$...$` / `$$...$$`）に書き換えなければならない 🔵 *ユーザヒアリング: LaTeX記法書き換え選択より*
- REQ-041: theory/en/ と theory/ja/ の両方の数式を移行しなければならない 🔵 *ユーザヒアリング: 日英両対応選択より*

### 旧ヘルプシステムの削除

- REQ-050: md_renderer.rs を削除しなければならない 🔵 *ユーザヒアリング: モーダル廃止承認より*
- REQ-051: help_modal.rs を削除しなければならない 🔵 *ユーザヒアリング: モーダル廃止承認より*
- REQ-052: help_types.rs の HelpContent / HelpTabDef を再設計しなければならない 🔵 *ユーザヒアリング: モーダル廃止承認より*
- REQ-053: help_content.rs を HTML埋め込みベースの構造に変更しなければならない 🔵 *ユーザヒアリング: モーダル廃止承認より*

### HTML品質

- REQ-060: 生成するHTMLはスタンドアロンで完結し、外部リソースを参照してはならない 🔵 *既存 html_report.rs のパターンより*
- REQ-061: HTMLには適切なCSSスタイリング（タイポグラフィ、テーブル、コードブロック）を含めなければならない 🔵 *リッチな表示要件より*
- REQ-062: HTMLはダークモード/ライトモードに対応すべきである 🟡 *eguiアプリのテーマ連動から妥当な推測*

## 非機能要件

### パフォーマンス

- NFR-001: ヘルプボタン押下からブラウザ起動まで 200ms 以内に完了しなければならない 🟡 *UX要件から妥当な推測（ファイル書き込み＋open::that）*
- NFR-002: ビルド時のHTML生成がビルド時間に顕著な影響（+5秒以上）を与えてはならない 🟡 *CI要件から妥当な推測*
- NFR-003: 一時ファイルの書き出しは非同期で実行すべきである 🟡 *UIスレッドブロック防止から妥当な推測*

### セキュリティ

- NFR-010: 一時ファイルはユーザーの一時ディレクトリに配置し、適切なパーミッションを設定しなければならない 🔵 *セキュリティ要件より*
- NFR-011: HTML内のユーザー提供データ（ファイル名等）はエスケープしなければならない 🔵 *既存 html_report.rs のパターンより*

### ユーザビリティ

- NFR-020: ブラウザで既に同じヘルプページが開いている場合、新規タブではなく既存タブを再利用すべきである 🟡 *UX向上から妥当な推測*
- NFR-021: ヘルプボタンがブラウザを開くことが視覚的に分かるようにすべきである 🟡 *UI設計から妥当な推測*

### 保守性

- NFR-030: 新しいウィジェットのヘルプ追加が theory/ へのmdファイル追加だけで完結するようにしなければならない 🔵 *既存 widget-help 要件 NFR-020 と同等*
- NFR-031: build.rs の変換ロジックはテスト可能でなければならない 🟡 *品質担保から妥当な推測*

## Edgeケース

### エラー処理

- EDGE-001: ブラウザ起動に失敗した場合、システムはエラーメッセージをユーザーに表示しなければならない 🟡 *既存 artifact_modal のパターンから妥当な推測*
- EDGE-002: 一時ディレクトリへの書き込みに失敗した場合、システムはエラーメッセージを表示しなければならない 🟡 *ファイルI/Oエラーハンドリングから妥当な推測*
- EDGE-003: ヘルプコンテンツが未定義のウィジェットの場合、デフォルトのプレースホルダHTMLを表示しなければならない 🟡 *既存 help_content.rs のパターンから妥当な推測*

### 境界値

- EDGE-010: 数式が非常に長い場合でも KaTeX が正しくレンダリングしなければならない 🔵 *KaTeXの機能仕様より*
- EDGE-011: 同時に複数のヘルプボタンを押した場合、それぞれ独立したブラウザタブが開かれるべきである 🟡 *UX要件から妥当な推測*
