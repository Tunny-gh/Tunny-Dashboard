## エピック 1: PROMETHEE II による完全ランキング

### ストーリー 1.1: PROMETHEE II で試行を完全順位付けしたい 🔵

**信頼性**: 🔵 *ユーザヒアリング・PROMETHEE アルゴリズム定義より*

**私は** Optuna 最適化結果の分析者 **として**
**PROMETHEE II（純フロー Φnet）で全試行を完全に順位付けしたい**
**そうすることで** TOPSIS / VIKOR と異なるランキング視点から最良試行を特定できる

**関連要件**: REQ-PR-001〜008, REQ-PR-010〜013, REQ-PR-023

**詳細シナリオ**:
1. ユーザーが MCDM Ranking ウィジェットを開く
2. メソッドコンボボックスで "PROMETHEE II" を選択する
3. 重みスライダーを調整する（デフォルト: 等重み）
4. "Run" ボタンを押す
5. バックグラウンドで `compute_promethee` が実行される（閾値 q=0, p=range×0.2 自動設定）
6. 完了後、Φnet バーチャートが表示され、試行が Φnet 降順でランキングされる

**前提条件**:
- Study が選択されており、目的関数が 1 つ以上存在する
- NaN 含有でない有効試行が 2 以上存在する

**制約事項**:
- 選好関数は Linear のみ（閾値自動設定、ユーザー変更不可）

**優先度**: Must Have

### ストーリー 1.2: PROMETHEE II の計算結果をテーブルで確認したい 🔵

**信頼性**: 🔵 *既存 McdmTable パターン・ユーザヒアリングより*

**私は** Optuna 最適化結果の分析者 **として**
**PROMETHEE II のランキング結果を上位 N 件のテーブルで確認したい**
**そうすることで** 各試行の Φnet スコアと目的関数値を数値で比較できる

**関連要件**: REQ-PR-012, REQ-PR-013

**詳細シナリオ**:
1. PROMETHEE II の計算が完了している
2. MCDM Table ウィジェットを開く
3. Top N セレクタ（5/10/20）で表示件数を選択する
4. ランク・Trial ID・Φnet スコア・各目的関数値がテーブルに表示される

**前提条件**:
- PROMETHEE II の計算が完了している（`app_state.mcdm_result` が存在する）

**優先度**: Must Have

## エピック 2: PROMETHEE I による部分ランキング

### ストーリー 2.1: PROMETHEE I で Φ+ と Φ- を可視化したい 🔵

**信頼性**: 🔵 *ユーザヒアリング（2 本バー表示）・PROMETHEE アルゴリズム定義より*

**私は** Optuna 最適化結果の分析者 **として**
**PROMETHEE I で各試行の正フロー（Φ+）と負フロー（Φ-）を並べて可視化したい**
**そうすることで** 試行が「他の試行より優れているか（Φ+）」と「他の試行より劣っているか（Φ-）」の両面から評価できる

**関連要件**: REQ-PR-007, REQ-PR-022

**詳細シナリオ**:
1. ユーザーがメソッドコンボボックスで "PROMETHEE I" を選択する
2. "Run" ボタンを押す
3. 完了後、各試行行に青（Φ+）と赤（Φ-）の 2 本バーが横並びで表示される
4. 試行は Φ+ 降順（タイブレーク: Φ- 昇順）でランキングされる

**前提条件**:
- Study が選択されており、有効試行が 2 以上存在する

**制約事項**:
- 不比較ペアの一覧は表示しない（Φ+/Φ- バーチャートのみ）

**優先度**: Must Have

---

### ストーリー 2.2: PROMETHEE I と II を切り替えて比較したい 🔵

**信頼性**: 🔵 *ユーザヒアリング（コンボボックス統合・キャッシュ機能）より*

**私は** Optuna 最適化結果の分析者 **として**
**PROMETHEE I と II のランキングをキャッシュを使って即座に切り替えたい**
**そうすることで** 再計算なしに部分順位付けと完全順位付けを比較できる

**関連要件**: REQ-PR-020, REQ-PR-021

**詳細シナリオ**:
1. PROMETHEE II を実行し結果を確認する
2. コンボボックスで "PROMETHEE I" に切り替える
3. キャッシュから即座に PROMETHEE I ビュー（Φ+/Φ- バー）に切り替わる
4. "Run" を押さずに表示が変わる

**前提条件**:
- PROMETHEE II を一度実行してキャッシュが存在する

**優先度**: Must Have

## エピック 3: 既存 MCDM との比較

### ストーリー 3.1: TOPSIS・VIKOR・PROMETHEE のランキングを比較したい 🔵

**信頼性**: 🔵 *既存 TOPSIS/VIKOR/PROMETHEE I/II のコンボボックス統合・ユーザヒアリングより*

**私は** Optuna 最適化結果の分析者 **として**
**同一 Study に対して TOPSIS・VIKOR・PROMETHEE I・PROMETHEE II の 4 メソッドを順番に実行し結果を比較したい**
**そうすることで** メソッド間のランキング差異を確認し、より信頼性の高い最良試行を選定できる

**関連要件**: REQ-PR-011-C

**詳細シナリオ**:
1. TOPSIS を実行してランキング確認
2. コンボボックスで VIKOR に切替 → 実行
3. コンボボックスで PROMETHEE I に切替 → 実行
4. コンボボックスで PROMETHEE II に切替 → 実行
5. 各メソッドのキャッシュにより、コンボボックス切替で過去結果を即時再表示

**前提条件**:
- Study が選択されており、有効試行が 2 以上存在する

**優先度**: Should Have
