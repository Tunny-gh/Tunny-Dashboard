## エピック1: 一対比較行列による重み設定

### ストーリー 1.1: 目的関数間の重要度を主観的に設定する 🔵

**信頼性**: 🔵 _ユーザヒアリング（フルAHP選択）より_

**私は** Tunny ダッシュボードのユーザー（最適化エンジニア）として
**目的関数間の相対的な重要度を一対比較行列で入力したい**
**そうすることで** AHP が自動的に優先度ベクトルを導出し、主観的な判断を定量的な重みに変換できる

**関連要件**: REQ-AHP-021, REQ-AHP-004, REQ-AHP-005

**詳細シナリオ**:

1. AHP Ranking チャートを開く
2. 目的関数名をヘッダーとした n×n の比較行列グリッドが表示される
3. 上三角セルの DragValue で各目的関数ペアの重要度比を入力する（Saaty 1-9）
4. 下三角セルに自動的に逆数が表示される
5. 優先度ベクトルが即座にプレビューされる 🟡 _実装容易性から推測（Run前にプレビュー）_

**前提条件**:

- Study が選択済みで、目的関数が 1 個以上定義されている
- AHP Ranking チャートがダッシュボードに配置されている

**制約事項**:

- Saaty スケール: 1〜9 の値のみ（小数点指定可）
- 目的関数数は最大 4（プロジェクト制約）

**優先度**: Must Have

### ストーリー 1.2: 整合性比率で入力の一貫性を確認する 🔵

**信頼性**: 🔵 _ユーザヒアリング（CR チェック実装選択）より_

**私は** Tunny ダッシュボードのユーザーとして
**一対比較行列を入力した後に整合性比率（CR）を確認したい**
**そうすることで** 判断の論理的一貫性を検証し、必要に応じて比較値を修正できる

**関連要件**: REQ-AHP-006, REQ-AHP-022

**詳細シナリオ**:

1. 一対比較行列を入力する
2. Run ボタンを押す
3. 計算完了後に CR 値が表示される（例: `"CR = 0.042"`）
4. CR ≤ 0.10 なら緑色で `"✓ Consistent"` が表示される
5. CR > 0.10 なら赤色で `"⚠ Inconsistent (CR > 0.10)"` が表示される
6. 不整合でもランキング結果は表示される（警告のみ）

**前提条件**:

- 一対比較行列が入力済み

**制約事項**:

- 目的関数が 1〜2 個の場合は CR = 0.0（常に一貫）

**優先度**: Must Have

## エピック2: AHP ランキングの確認

### ストーリー 2.1: AHP スコアでトライアルをランキングする 🔵

**信頼性**: 🔵 _ユーザヒアリング（加重和法・ランキングテーブル）より_

**私は** Tunny ダッシュボードのユーザーとして
**一対比較行列で導出した重みを使って全トライアルをランキングしたい**
**そうすることで** 主観的な重要度に基づいた最良トライアルを特定できる

**関連要件**: REQ-AHP-007, REQ-AHP-008, REQ-AHP-025

**詳細シナリオ**:

1. 一対比較行列を入力して Run を押す
2. 計算完了後に AHP ランキングテーブルが表示される
3. テーブルは「順位」「Trial ID」「AHP スコア」「各目的関数値」の列を持つ
4. Top5/Top10/Top20 のコンボボックスで表示件数を切り替える
5. 1位のトライアルが最も AHP スコアの高いトライアルである

**前提条件**:

- Study が選択済み
- 一対比較行列が入力済みで CR チェックを確認済み

**制約事項**:

- NaN 値を含むトライアルはランキング末尾に配置される

**優先度**: Must Have

---

### ストーリー 2.2: 優先度ベクトルで導出された重みを視覚確認する 🔵

**信頼性**: 🔵 _ユーザヒアリング（優先度ベクトルバーチャート選択）より_

**私は** Tunny ダッシュボードのユーザーとして
**AHP が一対比較行列から導出した優先度ベクトル（重み）をバーチャートで確認したい**
**そうすることで** 各目的関数に与えられた重みの比率を直感的に把握できる

**関連要件**: REQ-AHP-024

**詳細シナリオ**:

1. Run 後に計算結果が表示される
2. 優先度ベクトルバーチャートに目的関数ごとのバーが表示される
3. 最大の重みが最も長いバーとして表示される
4. 各バーに目的関数名と重み値（例: `"f1: 0.500"`）が表示される

**前提条件**:

- AHP 計算が完了している

**優先度**: Must Have

## エピック3: AHP チャートのライフサイクル管理

### ストーリー 3.1: Study を変更したときに AHP の状態がリセットされる 🔵

**信頼性**: 🔵 _既存 StudySelected ハンドラパターン・REQ-AHP-027 より_

**私は** Tunny ダッシュボードのユーザーとして
**別の Study に切り替えたときに AHP の入力値と結果がリセットされることを期待する**
**そうすることで** 前の Study の比較行列が誤って新しい Study に適用されるのを防げる

**関連要件**: REQ-AHP-027, REQ-AHP-013-B

**詳細シナリオ**:

1. Study A で一対比較行列を入力し Run を実行する
2. 別の Study B に切り替える
3. AHP チャートの一対比較行列入力がデフォルト（1.0）にリセットされる
4. ランキング結果表示がクリアされる
5. CR 表示もクリアされる

**前提条件**:

- 少なくとも 2 つの Study が存在する

**優先度**: Must Have

---

### ストーリー 3.2: AHP チャートをダッシュボードに配置する 🔵

**信頼性**: 🔵 _既存 ChartId/PanelItem パターン・REQ-AHP-014 より_

**私は** Tunny ダッシュボードのユーザーとして
**AHP Ranking チャートと AHP Table を自由レイアウトのダッシュボードに配置したい**
**そうすることで** 他のチャート（Pareto Scatter など）と並べて分析できる

**関連要件**: REQ-AHP-014

**詳細シナリオ**:

1. 右サイドパネルのチャートリストに `"AHP Ranking"` と `"AHP Table"` が表示される
2. ドラッグ＆ドロップでキャンバスに配置できる
3. 配置後に目的関数の一対比較行列入力グリッドが表示される

**前提条件**:

- Study が選択済み

**優先度**: Must Have
