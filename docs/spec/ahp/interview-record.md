# AHP ヒアリング記録

**作成日**: 2026-04-29
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

既存の MCDM 実装（TOPSIS/VIKOR/PROMETHEE）のパターンを確認し、AHP 固有の設計決定事項（重み決定方法・UI構成・スコア計算）を明確化するためのヒアリングを実施しました。

## 質問と回答

### Q1: AHP の重み決定方法

**質問日時**: 2026-04-29
**カテゴリ**: 未定義部分詳細化
**背景**: AHP は本来「一対比較行列」で重みを導出するが、既存の TOPSIS/VIKOR/PROMETHEE は直接重み入力スライダーを使用している。AHP をどのように統合するか確認が必要だった。

**選択肢**:

1. フルAHP（一対比較行列UI + 固有ベクトル法 + CR チェック）
2. シンプル統合（既存重み入力流用）
3. ハイブリッド

**回答**: フルAHP（一対比較行列UI + 固有ベクトル法 + CR チェック）

**信頼性への影響**:

- REQ-AHP-001〜008 の算法層の信頼性が 🔴 → 🔵 に向上
- 一対比較行列入力 UI の必要性が確定（🔵）

---

### Q2: CR（整合性比率）チェックの実装

**質問日時**: 2026-04-29
**カテゴリ**: 未定義部分詳細化
**背景**: AHP の特徴的な品質チェック機能。CR > 0.1 の場合に警告を出すかどうかの判断が必要だった。

**選択肢**:

1. 実装する（CR > 0.1 → 警告表示）
2. 実装しない

**回答**: 実装する（推奨）

**信頼性への影響**:

- REQ-AHP-006（整合性チェック）, REQ-AHP-022（CR UI表示）の信頼性が 🔴 → 🔵 に向上

### Q3: AHP チャートの UI 配置

**質問日時**: 2026-04-29
**カテゴリ**: 未定義部分詳細化
**背景**: 既存 McdmChart に統合するか（McdmMethod::Ahp 追加）、完全に新しいチャートにするか判断が必要だった。

**回答**: 「AHPように新しいチャートを作成してください」→ 完全別チャートとして解釈

**信頼性への影響**:

- REQ-AHP-014（ChartId追加）, REQ-AHP-020（AhpChart構造体）の信頼性が 🔴 → 🔵 に向上
- 既存 McdmMethod/McdmResult への変更不要が確定

## ヒアリング結果サマリー

### 確認できた事項

- AHP は完全な一対比較行列入力 UI を新規チャートとして実装する
- Saaty 1-9 スケールを使用する
- CR チェックを実装し、CR > 0.1 で警告表示する（ただし計算は続行可能）
- 加重和法 + Min-Max 正規化でスコアを計算する
- 優先度ベクトルバーチャート + ランキングテーブルを表示する
- 既存 McdmMethod/McdmResult enum は変更しない

### 追加/変更要件（既存設計文書にない新規事項）

- `ChartId::AhpRankChart` と `ChartId::AhpTable` を新規追加
- `AppMessage::AhpDone` を独立メッセージとして追加
- `ahp_chart.rs` ウィジェットを新規作成

### 残課題

- n ≥ 6 の RI 値（Saaty テーブルの拡張）の詳細確認（現状 1.24 で近似）
- AhpChart の UI レイアウト詳細（行列グリッドとバーチャートの縦横比）
