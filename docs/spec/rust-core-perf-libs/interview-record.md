# rust_core 外部ライブラリ高速化 ヒアリング記録

**作成日**: 2026-05-15
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

`rust_core` ディレクトリの自前実装コードを外部ライブラリで置き換えるため、
対象モジュールの優先順位、導入方針、移行戦略、既存 API への影響許容度を確認しました。

## 質問と回答

### Q1: 優先的に取り組むモジュール

**質問日時**: 2026-05-15
**カテゴリ**: 優先順位
**背景**: コードベース調査で 15 モジュール中 12 に自前実装を発見。リソース集中のため優先度の特定が必要。

**回答**: 全モジュールを選択（線形代数、最適化、乱数生成、クラスタリング）

**信頼性への影響**:
- 全モジュール対象であることが確定、スコープ絞り込みなし
- 各モジュールの要件を確実（🔵）として定義可能

---

### Q2: rand crate への PRNG 統一方針

**質問日時**: 2026-05-15
**カテゴリ**: 技術方針
**背景**: プロジェクト内に LCG、xorshift64、Fisher-Yates 用 LCG の 3 種の独自 PRNG が存在。品質と保守性の観点から統一の可否を確認。

**回答**: rand 導入（推奨）を選択。すべての独自 PRNG を rand + rand_chacha に置き換える。

**信頼性への影響**:
- REQ-301-01～03 を確実（🔵）として定義
- PRNG 品質の改善が確定（周期、一様性の向上）

---

### Q3: Random Forest デッドコードの方針

**質問日時**: 2026-05-15
**カテゴリ**: 技術方針
**背景**: `core/random_forest/` が `#[allow(dead_code)]` で実質未使用。LCG（rng.rs）のみ他モジュールで共有使用中。

**回答**: 削除（推奨）を選択。使用されていない RF 実装を削除し、LCG は他モジュールに移行後削除。

**信頼性への影響**:
- REQ-501-01～05 を確実（🔵）として定義
- 移行段階の LCG 一時配置を黄信号（🟡）として定義（REQ-501-04）

---

### Q4: argmin 導入範囲

**質問日時**: 2026-05-15
**カテゴリ**: 技術方針
**背景**: argmin には L-BFGS 以外に多数の最適化アルゴリズムが含まれる。将来の拡張を見据えた導入か、現状の必要最小限か。

**回答**: 最適化のみ（推奨）を選択。L-BFGS + line search のみを argmin に置き換え。

**信頼性への影響**:
- REQ-201-03 を確実（🔵）として定義
- スコープ明確化により実装負荷を限定

---

### Q5: データレイアウト移行方針

**質問日時**: 2026-05-15
**カテゴリ**: 技術方針
**背景**: `Vec<Vec<f64>>` はヒープ断片化とキャッシュミスの原因。faer::Mat（連続メモリ）への移行範囲が性能と作業量のトレードオフ。

**回答**: 全局的移行を選択。Vec<Vec<f64>> を faer::Mat に全面移行。

**信頼性への影響**:
- REQ-104-01～03 を確実（🔵）として定義
- 作業規模は大きいが、一括解決で将来の変換オーバーヘッドを排除

---

### Q6: K-means 方針

**質問日時**: 2026-05-15
**カテゴリ**: 技術方針
**背景**: `clustering/kmeans.rs` と `sparse_fitc.rs` に重複実装。統一または外部 crate 委譲の選択。

**回答**: linfa-clustering 導入を選択。2 つの K-means 実装を外部 crate に統合。

**信頼性への影響**:
- REQ-401-01～05 を確実（🔵）として定義
- 重複解消と保守性改善が確定

---

### Q7: 既存 API への影響許容度

**質問日時**: 2026-05-15
**カテゴリ**: 影響範囲
**背景**: データレイアウト移行に伴い、関数シグネチャ（公開 API）の変更が不可避。上位クレート（egui-app）への影響範囲の確認。

**回答**: API 含むリファクタを選択。関数シグネチャも含めて最適な形にリファクタリング。

**信頼性への影響**:
- REQ-104-02 を確実（🔵）として定義
- egui-app 側の呼び出しコードも更新が必要であることを確認

---

## ヒアリング結果サマリー

### 確認できた事項
- 全 4 モジュール（線形代数・最適化・乱数・クラスタリング）が対象
- rand crate による PRNG 統一
- linfa-clustering による K-means 外部委譲
- デッドコード（Random Forest）の削除
- API 含む全局的リファクタリングの実施

### 追加/変更要件
- argmin は L-BFGS のみの導入（将来拡張はスコープ外）
- Sobol 低差異列の導入はスコープ外（将来候補）

### 残課題
- なし（全主要方針が確定）
