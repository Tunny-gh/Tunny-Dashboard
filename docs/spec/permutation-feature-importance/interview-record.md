# Permutation Feature Importance ヒアリング記録

**作成日**: 2026-05-02
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

既存の感度分析実装（RF-Anova, MDI, SHAP など）との差分を明確化し、
Permutation Feature Importance に固有の仕様を確定するためのヒアリング。

## 質問と回答

### Q1: ベースモデルの選択

**質問日時**: 2026-05-02
**カテゴリ**: 未定義部分詳細化
**背景**: 既存 LightGBM ベースのメトリクス（RF-Anova, MDI, SHAP）との整合性を確認

**回答**: LightGBM（推奨）を選択

**信頼性への影響**:
- REQ-PFI-002-F の信頼性レベルが 🟡 → 🔵 に向上
- 新規依存クレート不要

---

### Q2: パーミュテーションの繰り返し回数

**質問日時**: 2026-05-02
**カテゴリ**: 未定義部分詳細化
**背景**: RF-Anova は n_repeats=1 のシンプルな実装。新規機能の差別化ポイントを確定

**回答**: 固定値（n_repeats=5）を選択

**信頼性への影響**:
- REQ-PFI-002-H の信頼性レベルが 🔴 → 🔵 に向上
- UI の複雑化を回避（スピナー不要）

---

### Q3: 重要度スコア形式

**質問日時**: 2026-05-02
**カテゴリ**: 未定義部分詳細化
**背景**: MSE増加量 vs R²減少量の2択。既存メトリクスとの一貫性

**回答**: 平均MSE増加量（推奨）を選択

**信頼性への影響**:
- REQ-PFI-002-H のスコア計算式が 🔴 → 🔵 に向上

---

### Q4: 既存コードベース分析の要否

**質問日時**: 2026-05-02
**カテゴリ**: 既存設計確認
**背景**: 設計文書のみ vs コード詳細分析で要件精度が変わる

**回答**: 必要（詳細分析を実施）

**信頼性への影響**:
- 全 REQ-PFI 要件の信頼性が向上（実装パターンを直接確認）

## ヒアリング結果サマリー

### 確認できた事項
- LightGBM RF を使用（既存インフラと同一）
- n_repeats=5 固定（UI パラメータ化は今回スコープ外）
- 平均MSE増加量を正規化して返す
- キャッシュ ID = 7（既存の 0〜6 の次番）
- RF-Anova とは明確に異なる（RF-Anova は n_repeats=1）

### 追加/変更要件
- n_repeats=5 の繰り返し実装（RF-Anova からの派生でなく独立実装）
- `PermutationResult` 型を rust_core と egui-app の両方に追加

### 残課題
- なし（すべての主要仕様がヒアリングで確定）

### 信頼性レベル分布

**ヒアリング前**:
- 🔵 青信号: 12件
- 🟡 黄信号: 4件
- 🔴 赤信号: 3件

**ヒアリング後**:
- 🔵 青信号: 18件 (+6)
