## エピック1: 基本的な散布図表示

### ストーリー 1.1: 複数目的関数の相関関係を散布図で確認したい 🔵

**信頼性**: 🔵 *既存設計（ParetoScatter2D）・ヒアリングより*

**私は** 最適化結果を分析するデータアナリスト **として**
**複数目的関数（例：目的1 vs 目的2）の相関関係を二次元の散布図で確認** **したい**
**そうすることで** パレート最適解における複数目的間のトレードオフを直感的に理解できる

**関連要件**: REQ-002, REQ-003, REQ-004

**詳細シナリオ**:
1. MCDM計算実施後、McdmRankChart タブで「散布図」タブを選択
2. 初期表示：第1目的関数（正規化済み）vs 第2目的関数（正規化済み）
3. ComboBox で X軸・Y軸を変更（例：目的2 vs 目的3 に変更）
4. 散布図が即座に更新され、異なるトレードオフが可視化

**前提条件**:
- MCDM計算が完了していること（app_state.mcdm_result が Some）
- 複数目的関数が存在すること（最低2個）

**制約事項**:
- 正規化処理により、スケール異なる目的関数を統一軸で表現

**優先度**: Must Have

### ストーリー 1.2: MCDM スコアと目的関数の関係を散布図で確認したい 🔵

**信頼性**: 🔵 *ユーザーヒアリング「X軸・Y軸の任意選択」より*

**私は** 最適化結果を分析するデータアナリスト **として**
**MCDM計算結果（スコア）と元の目的関数値の関係を散布図で確認** **したい**
**そうすることで** MCDM ランキング付けが正当性を持つか（目的関数値との乖離がないか）を検証できる

**関連要件**: REQ-003, REQ-006

**詳細シナリオ**:
1. 散布図タブで ComboBox を選択
2. X軸: VIKOR Q値（MCDM スコア）
3. Y軸: 第1目的関数値
4. プロット点分布から、Q値と目的関数値の相関を確認

**前提条件**:
- MCDM 計算（TOPSIS/VIKOR/PROMETHEE 等）が完了

**制約事項**:
- 異なるスケール（MCDM スコア: 0-1, 目的関数: 任意）の混在に対応

**優先度**: Must Have

## エピック2: ランキング可視化

### ストーリー 2.1: MCDM ランキング上位を色分けして強調したい 🔵

**信頼性**: 🔵 *ヒアリング「色分け戦略：ランキング位置別」・既存 ParetoScatter2D パターンより*

3. プロット点が色分け表示
4. ユーザーが「Top10」に変更 → 色分けが動的更新

**前提条件**:
- ランキング計算が完了（ranked_indices が存在）

**制約事項**:
- 色選択はプリセット（Top5/10/20）から選択

**優先度**: Must Have

## エピック3: MCDM 手法別対応

### ストーリー 3.1: VIKOR の複数指標（S/R/Q）を軸に選択したい 🟡

**信頼性**: 🟡 *既存 VIKOR 実装（S/R/Q三値）から妥当に推測*

**私は** 最適化結果を分析するデータアナリスト **として**
**VIKOR で計算された S値（総合効用）・R値（遺念）・Q値（妥協スコア）を軸に選択** **したい**
**そうすることで** 異なる VIKOR 観点でトレードオフを分析できる

**関連要件**: REQ-101

**詳細シナリオ**:
1. MCDM方法：VIKOR を選択
2. X軸 ComboBox：「S値（総合効用）」を選択
3. Y軸 ComboBox：「Q値（妥協スコア）」を選択
4. 散布図：S vs Q の関係を表示

**前提条件**:
- VIKOR 計算完了

**制約事項**:
- 軸選択肢は VIKOR 固有（S/R/Q）と目的関数群の組み合わせ

**優先度**: Should Have

**備考**: 実装ガイド完備（docs/design/vikor/architecture.md 参照）

**前提条件**:
- PROMETHEE 計算完了（既存実装済み）

**優先度**: Should Have

## エピック4: パフォーマンス・使いやすさ

### ストーリー 4.1: 大規模トライアル集合での性能を確保したい 🟡

**信頼性**: 🟡 *既存 ParetoScatter2D ダウンサンプリング実装から推測*

**私は** 最適化結果を分析するデータアナリスト **として**
**数千トライアルの散布図でもガク（visual clutter）なく、スムーズに操作** **したい**
**そうすることで** 大規模実験でも快適に分析できる

**関連要件**: REQ-008, NFR-001

**詳細シナリオ**:
1. 5000トライアル × 多目的最適化 の結果を散布図表示
2. ダウンサンプリング自動有効化（300点以下に削減）
3. 軸変更時も UI フリーズなく 60 FPS 維持

**前提条件**:
- 大規模トライアル集合（1000以上）が存在

**優先度**: Should Have

---

### ストーリー 4.2: ダウンサンプリングの詳細制御をしたい 🟡

**信頼性**: 🟡 *ParetoScatter2D 実装パターンより*

**私は** 最適化結果を分析するデータアナリスト **として**
**ダウンサンプリング（有効/無効）を UI チェックボックスで制御** **したい**
**そうすることで** 必要に応じて全データを表示・分析できる

3. 再度チェックをオン → 300点にダウンサンプリング

**前提条件**:
- 大規模トライアル集合が存在

**優先度**: Could Have
