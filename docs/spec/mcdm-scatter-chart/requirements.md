# MCDMで計算された結果を散布図で表示 要件定義書

**作成日**: 2026-05-06  
**対象バージョン**: Tunny Dashboard (egui版)  
**作業規模**: フル機能開発

---

## 概要

MCDMアルゴリズム（TOPSIS/VIKOR/PROMETHEE/AHP）で計算された多基準意思決定結果を、**散布図**で可視化できる機能を実装する。既存のバーチャート＋テーブル表示と並行して、データアナリストが複数目的間の関係性を二次元平面で直感的に理解できるようにする。

### 背景

- **既存状況**: McdmRankChart でランキング結果をバーチャート＋テーブルで表示
- **課題**: 複数目的関数間の相関関係や非優越性を二次元で確認できない
- **目標**: ParetoScatter2D パターンを参考に、MCDM結果を散布図で表現

### 1. 通常要件（基本動作）

#### REQ-001: 散布図タブの配置 🔵

**説明**: システムは McdmRankChart ウィジェット内に「散布図」タブを追加して、既存の「ランキング」タブと並行表示しなければならない。

**補足**:
- egui のタブ UI（`ui.selectable_label()` または `TabViewer`）で実装
- 「ランキング」タブ: 既存バーチャート＋テーブル表示
- 「散布図」タブ: 新規 McdmScatterChart ウィジェット表示

**出典**: ヒアリング「UI配置：新規タブで公開」, 既存実装パターン

#### REQ-002: 散布図ウィジェットの作成 🔵

**説明**: システムは新規 `McdmScatterChart` ウィジェット（`egui-app/src/ui/widgets/mcdm_scatter_chart.rs`）を実装し、MCDM結果を二次元プロット上に表現しなければならない。

**補足**:
- `egui_plot::Plot` で実装（ParetoScatter2D パターン踏襲）
- 計算を再度実施することなく、既存 `app_state.mcdm_result` のデータを再利用
- 目的関数値と MCDM スコアを軸として利用可能

**出典**: ParetoScatter2D 実装パターン, 既存チャート配置

#### REQ-003: X軸・Y軸のコンボボックス選択 🔵

**説明**: ユーザーが ComboBox を使って任意の2軸をX軸・Y軸として選択でき、散布図の表示内容が動的に変わらなければならない。

**補足**:
- **X軸候補**: 目的関数値群、MCDM スコア（Q値 for VIKOR、Score for TOPSIS等）
- **Y軸候補**: 別の目的関数値、別の MCDM スコア指標（S値・R値など VIKOR特有）
- 軸の初期値：第1目的関数 vs 第2目的関数（ユーザ希望）
- 選択変更時は `display_rows_cache` を無効化

**出典**: ヒアリング「軸選択機能：任意軸選択」, ParetoScatter2D 軸選択パターン

#### REQ-004: 単位・無次元化の処理 🟡

**説明**: システムは複数目的関数（スケール異なる）と MCDM スコア（正規化済み）が混在する場合、それぞれを正規化して軸上に表示しなければならない。

**補足**:
- **正規化アルゴリズム**: Min-Max正規化 `(v - min) / (max - min)`
- 目的関数値には MCDM の正規化ロジックを流用（エッジケース: 全値同一 → スコア = 0）
- 軸ラベルに「(正規化)」と明記
- 元値は ホバー時のツールチップに表示

**出典**: 既存MCDM実装の正規化処理, 設計仕様

#### REQ-005: 色分けルール - ランキング順位別 🔵

**説明**: システムは MCDM 計算結果のランキング順位に基づいて、各プロット点の色を分類しなければならない。

**補足**:
- **色分けグループ**:
  - Top5: 🔴 赤 (`Color32::from_rgb(255, 0, 0)`)
  - Top6-10: 🟠 オレンジ (`Color32::from_rgb(255, 165, 0)`)
  - Top11-20: 🟡 黄 (`Color32::from_rgb(255, 255, 0)`)
  - その他: ⚪ 灰色 (`Color32::from_rgb(200, 200, 200)`)
- Top N はユーザーが ComboBox で切り替え可能（「Top5」「Top10」「Top20」）
- ranked_indices から順位 → 色マッピング

**出典**: ヒアリング「色分け戦略：ランキング位置別」, 既存 Pareto 実装

#### REQ-006: 複数 MCDM 手法への対応 🔵

**説明**: システムは TOPSIS/VIKOR/PROMETHEE/AHP の4つの MCDM 手法すべてをサポートし、手法ごとに異なるスコア指標を軸として表現しなければならない。

**補足**:
- **TOPSIS**: `TopsisResult.scores` → Y軸に使用可能
- **VIKOR**: `VikorResult.s_values`, `r_values`, `q_values` → 複数軸オプション
- **PROMETHEE**: `PrometheeResult.phi_plus`, `phi_minus`, `phi_net` → 複数軸オプション
- **AHP**: `AhpResult.scores` → Y軸に使用可能
- `app_state.mcdm_result` の `match` 分岐で手法別の軸リスト生成

**出典**: ヒアリング「MCDM手法：全て」, 既存実装の enum パターン

#### REQ-007: トライアル ID のホバー表示 🔵

**説明**: ユーザーがプロット点にカーソルを合わせたとき、対応するトライアル ID と両軸の元値（正規化前）をツールチップで表示しなければならない。

**補足**:
- 表示内容:
  ```
  Trial ID: 42
  X軸（第1目的）: 3.14 (正規化: 0.62)
  Y軸（第2目的）: 0.89 (正規化: 0.45)
  VIKOR Q値: 0.33
  Rank: 7
  ```
- egui_plot の `hover_callback` で実装

**出典**: 既存 ParetoScatter2D 実装パターン

#### REQ-008: ダウンサンプリング対応 🟡

**説明**: 大規模トライアル集合（1000以上）の場合、ガク（visual clutter）を避けるため、ParetoScatter2D と同一のダウンサンプリング戦略を適用してもよい。

**補足**:
- `use_downsample: bool` フラグで制御
- ダウンサンプリング算法: 既存 `scatter_matrix.rs` 参照
- デフォルトは `use_downsample = true`（大規模向け自動有効化）
- ユーザが UI で切り替え可能

**出典**: ParetoScatter2D ダウンサンプリング実装, 既存パターン

### 2. 条件付き要件（手法別の軸設定）

#### REQ-101: VIKOR 固有の軸オプション 🔵

**説明**: MCDM手法が VIKOR の場合、ユーザーが S値・R値・Q値の複合表示を軸に選択できなければならない。

**補足**:
- 軸選択肢:
  - X軸: 目的関数群 + S値, R値, Q値
  - Y軸: 別目的関数 + S値, R値, Q値（X軸と異なる組み合わせ）
- 推奨例: 「S値 vs Q値」（S: 総合効用, Q: 妥協スコア）
- 実装: `McdmMethod::Vikor` の match 分岐で軸リスト拡張

**出典**: 既存 VIKOR 設計（S/R/Qの3スコア）

#### REQ-102: PROMETHEE 固有の軸オプション 🔵

**説明**: MCDM手法が PROMETHEE の場合、φ+（正流束）・φ-（負流束）・φ（正味流束）の複合表示を軸に選択できなければならない。

**補足**:
- 軸選択肢:
  - X軸: 目的関数群 + φ+, φ-, φ
  - Y軸: 別目的関数 + φ+, φ-, φ
- 推奨例: 「φ+ vs φ-」（支配度の直感的比較）
- 実装: `McdmMethod::PrometheeI | McdmMethod::PrometheeII` の match 分岐

**出典**: 既存 PROMETHEE 実装

#### REQ-103: AHP 固有の制限 🟡

**説明**: MCDM手法が AHP の場合、散布図は AHP スコア vs 単一目的関数の軸選択のみを許可しなければならない。

**補足**:
- AHP は複合基準の統合スコアため、複数 AHP スコア軸の同時表示は不要
- 軸選択肢:
  - X軸: 目的関数群 (複数選択可)
  - Y軸: AHP スコア（固定）
  - あるいは逆 (AHP スコア X軸)
- 実装: `McdmMethod::Ahp` の match 分岐で軸リスト制限

**出典**: AHP の統計的性質から妥当な推測

### 3. 状態要件（UI状態管理）

#### REQ-201: タブ状態の管理 🟡

**説明**: 「ランキング」タブと「散布図」タブの選択状態は、`McdmRankChart` ウィジェットのローカル状態として管理され、セッション間で永続化しなくてもよい。

**補足**:
- `active_tab: TabState` を `McdmRankChart` フィールドに追加
- TabState: `enum { Ranking, ScatterPlot }`
- UI 更新時に選択タブを描画

**出典**: 既存タブ UI 実装パターン

#### REQ-202: 軸選択状態の管理 🟡

**説明**: X軸・Y軸・色分けグループ（Top N）の選択状態は、`McdmScatterChart` ウィジェットのローカル状態として管理され、MCDM 再計算時にリセットしてもよい。

**補足**:
- `x_axis: String`, `y_axis: String`, `top_n: usize` を フィールドに追加
- 初期値：X軸＝第1目的, Y軸＝第2目的, Top N＝5

**出典**: ParetoScatter2D の軸状態管理パターン

### 4. 非機能要件

#### NFR-001: パフォーマンス - 描画速度 🟡

**説明**: 最大1000トライアル × 複数目的関数の散布図描画時、UI フリーズなく 60 FPS で動作しなければならない。

**補足**:
- ダウンサンプリング有効化（デフォルト）で300点以下に削減
- キャッシュ戦略: `display_rows_cache` で軸変更時の再計算を最小化
- egui_plot の最適化手法を適用

**出典**: 既存パフォーマンス要件, ParetoScatter2D 実装

#### NFR-002: パフォーマンス - メモリ使用量 🟡

**説明**: 散布図ウィジェットのメモリ使用量は 50 MB 以下でなければならない。

**補足**:
- 原因: Points配列キャッシュ
- 対策: ダウンサンプリング時の点数削減, キャッシュサイズ制限

**出典**: 既存メモリ制約

#### NFR-003: ユーザビリティ - 直感性 🔵

**説明**: ユーザーが ComboBox で軸を変更した直後、散布図が即座に（<100ms）更新されなければならない。

**補足**:
- リアクティビティ: Rust の所有権機構で即座な再描画

**出典**: egui-plot の動作特性

#### NFR-004: アクセシビリティ - 色覚補助 🟡

**説明**: 色分け以外にもマーカー形状（●/◆/■）で区別可能にしてもよい。

**補足**:
- Red + Circle: Top 5
- Orange + Diamond: Top 6-10
- Yellow + Square: Top 11-20
- Gray + Cross: Others
- オプション実装

**出典**: アクセシビリティ考慮

## Edge ケース

### EDGE-001: 全トライアル同一スコアの場合 🟡

**説明**: X軸・Y軸が全て同一値の場合（min = max）、システムは正規化を0に設定し、1点に全てのプロット点を集約してもよい。

**補足**:
- UI: 「データが単一値のため表示できません」メッセージ
- ユーザーに軸変更を促す

**出典**: 既存エラー処理パターン

### EDGE-002: MCDM 結果未計算状態 🔵

**説明**: MCDM 計算を未実施か計算中の場合、散布図タブは「計算中...」プレースホルダーを表示しなければならない。

**補足**:
- `app_state.mcdm_result.is_none()` → プレースホルダー表示
- 計算完了 → 散布図描画

**出典**: 既存ローディング状態パターン

### EDGE-003: トライアル ID と軸値のマッピングミス 🟡

**説明**: ダウンサンプリング後でも、ホバー表示では元の trial_id/value を正確に表示しなければならない。

**補足**:
- ダウンサンプリング時の `sampled_indices` を保持
- ホバー時に逆引き

**出典**: 既存マッピング処理, ParetoScatter2D 実装

## 制約事項

### REQ-401: 既存 MCDM ロジックの変更禁止 🔵

**説明**: 散布図実装による既存 TOPSIS/VIKOR/PROMETHEE/ENTROPY/AHP アルゴリズムの変更は行ってはならない。

**補足**:
- 計算の再利用: 既存 `app_state.mcdm_result` のデータをそのまま使用
- 新規計算・パラメータ追加なし

**出典**: アーキテクチャ保全

### REQ-402: 既存 McdmRankChart の動作維持 🔵

**説明**: 既存のバーチャート＋テーブル表示（ランキングタブ）の動作は一切変更してはならない。

**補足**:
- 新規 McdmScatterChart は McdmRankChart の内部ウィジェット（子コンポーネント）
- タブ選択ロジックで両者を排他的に表示

**出典**: 後方互換性

### REQ-403: メッセージパッシングアーキテクチャの維持 🔵

**説明**: 散布図表示において、新規アルゴリズム計算を spawn_task で実行してはならない。

**補足**:
- 既存 `app_state.mcdm_result` のデータを再利用のみ
- 新規計算が必要な場合は将来タスク

**出典**: 既存アーキテクチャ設計
