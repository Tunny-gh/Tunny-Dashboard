## REQ-001: 散布図タブの配置 🔵

**信頼性**: 🔵 *既存設計（McdmRankChart）・ヒアリングより*

### Given（前提条件）
- MCDM 計算が完了している
- McdmRankChart ウィジェットが表示されている
- 既存「ランキング」タブが表示されている

### When（実行条件）
- UI を確認する

### Then（期待結果）
- McdmRankChart 内に「ランキング」タブと「散布図」タブが並行表示される
- 初期状態は「ランキング」タブがアクティブ
- ユーザーが「散布図」タブをクリックできる

### テストケース

#### 正常系

- [ ] **TC-001-01**: タブ UI が存在する 🔵
  - **入力**: UI 初期化完了
  - **期待結果**: `data-testid="mcdm-scatter-tab"` が DOM に存在
  - **信頼性**: 🔵 *UI 標準パターンより*

- [ ] **TC-001-02**: 「ランキング」タブが最初アクティブ 🔵
  - **入力**: UI 初期化
  - **期待結果**: 「ランキング」タブが selected=true
  - **信頼性**: 🔵 *既存実装より*

- [ ] **TC-001-03**: 「散布図」タブをクリックでアクティブ切り替え 🔵
  - **入力**: UI 初期化後、「散布図」タブをクリック
  - **期待結果**: active_tab = TabState::ScatterPlot に変更
  - **信頼性**: 🔵 *egui タブ UI 標準動作*

## REQ-003: X軸・Y軸のコンボボックス選択 🔵

**信頼性**: 🔵 *ヒアリング・既存 ParetoScatter2D より*

### Given（前提条件）
- 散布図ウィジェットが表示されている
- 複数目的関数が存在（≧2個）
- MCDM スコアが計算済み

### When（実行条件）
- ComboBox で軸を選択

### Then（期待結果）
- X軸・Y軸が即座に（<100ms）変更
- 散布図がリアルタイム更新

### テストケース

#### 正常系

- [ ] **TC-003-01**: 初期軸は第1目的 vs 第2目的 🔵
  - **入力**: UI 初期化
  - **期待結果**: 
    - x_axis = "Objective 1" (または第1目的名)
    - y_axis = "Objective 2" (または第2目的名)
  - **信頼性**: 🔵 *ヒアリング確認*

- [ ] **TC-003-02**: X軸 ComboBox で第2目的を選択 🔵
  - **入力**: X軸 ComboBox から "Objective 2" を選択
  - **期待結果**: 
    - x_axis = "Objective 2" に変更
    - 散布図が第2 vs 第2目的で再描画（不健全だが許容）
  - **信頼性**: 🔵 *UI 操作確認*

- [ ] **TC-003-03**: Y軸を MCDM スコアに変更 🔵
  - **入力**: Y軸 ComboBox から "VIKOR Q値" を選択
  - **期待結果**: 
    - y_axis = "VIKOR Q値" に変更
    - 散布図が第1目的 vs VIKOR Q値で再描画
  - **信頼性**: 🔵 *軸混在パターン*

- [ ] **TC-003-04**: 軸変更時にキャッシュが無効化 🟡
  - **入力**: X軸変更
  - **期待結果**: display_rows_cache = None に設定
  - **信頼性**: 🟡 *ParetoScatter2D 実装パターン*

#### 異常系

- [ ] **TC-003-E01**: X軸と Y軸が同じ場合も許容 🟡
  - **入力**: X軸 = Y軸 = "Objective 1"
  - **期待結果**: 散布図が同一軸で描画（diagonal line 形成）
  - **信頼性**: 🟡 *設計上の判断*

## REQ-004: 単位・無次元化の処理 🟡

**信頼性**: 🟡 *既存 MCDM 正規化処理から推測*

### Given（前提条件）
- X軸・Y軸に異なるスケール軸が選択された
- 例：X軸 = 第1目的（スケール 0-100）, Y軸 = VIKOR Q値（スケール 0-1）

### When（実行条件）
- 散布図を描画

### Then（期待結果）
- 両軸が 0-1 の正規化スケール統一で表示
- 軸ラベルに「(正規化)」表記
- ホバーツールチップで元値表示

### テストケース

#### 正常系

- [ ] **TC-004-01**: Min-Max正規化が適用 🟡
  - **入力**: 目的関数値 [10, 20, 30, 40]
  - **期待結果**: 正規化値 [0.0, 0.33, 0.67, 1.0]（近似値）
  - **信頼性**: 🟡 *数学的確認*

- [ ] **TC-004-02**: 軸ラベルに「(正規化)」表記 🟡
  - **入力**: 軸選択後、UI 描画
  - **期待結果**: X軸ラベル = "Objective 1 (正規化)"
  - **信頼性**: 🟡 *UI 仕様から推測*

- [ ] **TC-004-03**: ホバーで元値表示 🔵
  - **入力**: プロット点にマウスオーバー
  - **期待結果**: ツールチップに元値表示
    ```
    X: 3.14 (正規化: 0.62)
    Y: 0.89 (正規化: 0.45)
    ```
  - **信頼性**: 🔵 *既存 ParetoScatter2D パターン*

#### 異常系

- [ ] **TC-004-E01**: 全値同一の場合（min = max）🟡
  - **入力**: 軸データがすべて 5.0
  - **期待結果**: 
    - 正規化値 = 0.0（またはスキップ）
    - メッセージ: 「データが単一値のため表示できません」
  - **信頼性**: 🟡 *エッジケース処理*

#### 境界値

- [ ] **TC-004-B01**: min = max - epsilon の場合 🟡
  - **入力**: データ [5.0, 5.0000001]
  - **期待結果**: 数値安定性を保持（NaN 回避）
  - **信頼性**: 🟡 *浮動小数点安全性*

## REQ-005: 色分けルール - ランキング順位別 🔵

**信頼性**: 🔵 *ヒアリング・既存実装より*

### Given（前提条件）
- ランキング情報（ranked_indices）が計算済み
- Top N が指定されている（デフォルト Top5）

- 散布図を描画

### Then（期待結果）
- プロット点が Top N のランキングに基づいて色分け
- Top5: 🔴, Top6-10: 🟠, Top11-20: 🟡, Others: ⚪

### テストケース

#### 正常系

- [ ] **TC-005-01**: Top5 が 🔴 赤で表示 🔵
  - **入力**: ランキング上位5件 + 他のトライアル
  - **期待結果**: ranked_indices[0:4] のプロット点が赤色
  - **信頼性**: 🔵 *色選択確認*

- [ ] **TC-005-02**: Top6-10 が 🟠 オレンジで表示 🔵
  - **入力**: ランキング 6-10 位のトライアル
  - **期待結果**: ranked_indices[5:9] のプロット点がオレンジ色
  - **信頼性**: 🔵 *色選択確認*

- [ ] **TC-005-03**: Top N セレクタで動的変更 🟡
  - **入力**: Top N ComboBox から「Top10」を選択
  - **期待結果**: 
    - 色分けグループ境界が変更
    - Top6-10 が 🟠 から 🔴 に変更（新 Top10 に昇格）
    - Top11-20 が 🟡 から 🟠 に変更
  - **信頼性**: 🟡 *UI 動的更新確認*

- [ ] **TC-005-04**: 全トライアル数 < Top N の場合 🟡
  - **入力**: トライアル総数 8, Top N = 10
  - **期待結果**: 全8件を Top グループで色分け（グレー圏なし）
  - **信頼性**: 🟡 *エッジケース*

## REQ-008: ダウンサンプリング対応 🟡

**信頼性**: 🟡 *ParetoScatter2D ダウンサンプリング実装より*

### Given（前提条件）
- トライアル数が多い（1000以上）
- ダウンサンプリング有効化（デフォルト）

### When（実行条件）
- 散布図を描画

### Then（期待結果）
- プロット点数が 300 以下に削減
- UI が 60 FPS で動作
- ユーザーが「ダウンサンプリング有効/無効」を切り替え可能

### テストケース

#### 正常系

- [ ] **TC-008-01**: デフォルトでダウンサンプリング有効 🟡
  - **入力**: 5000トライアル, UI 初期化
  - **期待結果**: 
    - プロット点数 ≤ 300
    - use_downsample = true
  - **信頼性**: 🟡 *パフォーマンス設定*

- [ ] **TC-008-02**: ダウンサンプリング無効化 🟡
  - **入力**: UI チェックボックス「ダウンサンプリング有効」をオフ
  - **期待結果**: 
    - 全5000点がプロット表示
    - use_downsample = false
  - **信頼性**: 🟡 *UI 制御確認*

- [ ] **TC-008-03**: ダウンサンプリング時の精度 🟡
  - **入力**: 5000トライアル, ダウンサンプリング有効
  - **期待結果**: 削減後の分布が元の分布を代表する（視覚的検証）
  - **信頼性**: 🟡 *統計的確認必要*

#### 異常系

- [ ] **TC-008-E01**: ダウンサンプリング無効時の遅延許容 🟡
  - **入力**: 10000トライアル, ダウンサンプリング無効
  - **期待結果**: UI レスポンス遅延あっても動作は正確
  - **信頼性**: 🟡 *ユーザー許容度*

## 非機能要件テスト

### NFR-001: パフォーマンス - 描画速度 🟡

**信頼性**: 🟡 *既存パフォーマンス要件より*

- [ ] **TC-NFR-001-01**: 最大1000トライアル描画時に 60 FPS 維持
  - **測定項目**: フレームレート (fps)
  - **目標値**: ≥ 55 fps
  - **測定条件**: X/Y 軸変更, ホバー操作時
  - **信頼性**: 🟡 *性能目標推測*

- [ ] **TC-NFR-001-02**: 軸変更時の再描画 <100ms
  - **測定項目**: 軸変更から新描画までの時間 (ms)
  - **目標値**: ≤ 100 ms
  - **信頼性**: 🟡 *ユーザー体験目安*

### NFR-002: パフォーマンス - メモリ使用量 🟡

**信頼性**: 🟡 *既存制約より*

- [ ] **TC-NFR-002-01**: メモリ使用量 50 MB 以下
  - **測定項目**: 散布図ウィジェット専有メモリ
  - **目標値**: ≤ 50 MB
  - **測定条件**: 5000トライアル × 5目的
  - **信頼性**: 🟡 *ダウンサンプリング効果推測*
