## エピック1: トレードオフ探索

### ストーリー 1.1: 重み付きParetoナビゲーター 🔵

**信頼性**: 🔵 *ユーザヒアリング Q3・Q4・first_spec.md 差別化ポイントより*

**私は** 多目的最適化の分析担当者 **として**  
**各目的関数の重みスライダーを動かして最適解をリアルタイムにハイライトしたい**  
**そうすることで** 「速度を最優先するなら X、コストを重視するなら Y」というトレードオフを直感的に探索できる

**関連要件**: REQ-001-A〜G

**詳細シナリオ**:
1. 4目的の Study を選択すると、Left Panel 下部に「Trade-off Navigator」セクションが現れる
2. 各目的（obj1〜obj4）に対応する重みスライダー（0〜1）が並んでいる
3. "obj1: 速度" のスライダーを 0.8 に引き上げると、他スライダーが自動正規化される
4. 全グラフ上で最高スコアの試行が金色（★）でハイライトされる
5. スライダーを調整するたびにリアルタイムでハイライトが切り替わる

**前提条件**:
- 多目的 Study が選択されている（目的数 ≥ 2）
- `rust_core/src/multi_objective/pareto/tradeoff.rs` の `score_tradeoff_navigator()` が実装済み

**制約事項**:
- 単目的 Study 選択時は非表示
- 最大目的数は 4（first_spec.md の設計制約）

**優先度**: Must Have

## エピック2: 分析状態の永続化・共有

### ストーリー 2.1: フィルタ条件を保存して後日再現する 🔵

**信頼性**: 🔵 *ユーザヒアリング Q3・first_spec.md UI機能・filter.rs より*

**私は** 複数日にわたって最適化結果を分析するエンジニア **として**  
**今日設定したフィルタ条件（パラメータ範囲・選択インデックス）を JSON ファイルに保存したい**  
**そうすることで** 翌日同じ Journal を開いた際に続きから分析を再開できる

**関連要件**: REQ-002-A〜E

**詳細シナリオ**:
1. Parallel Coordinates でブラシを設定し、500件を選択した状態
2. ToolBar の「フィルタを保存」ボタンをクリック
3. OS のファイル保存ダイアログが開き、`filter_2026-04-26.json` として保存
4. 翌日、同じ Journal を開き「フィルタを読み込み」をクリック
5. 昨日と同じ 500 件が選択された状態が復元される

**優先度**: Must Have

4. 上司が Tunny Dashboard を開き、同じ Journal ファイルを選択
5. .tdash ファイルをドラッグ&ドロップして読み込む
6. 完全に同じ分析状態が再現される

## エピック4: マルチスタディ比較

### ストーリー 4.1: アルゴリズム間の性能差を並列比較する 🔵

**信頼性**: 🔵 *ユーザヒアリング Q7・first_spec.md Study比較設計より*

**私は** 複数のサンプラーを比較したい最適化研究者 **として**  
**同一 Journal 内の 3 種類の Study（NSGA-II / TPE / MOTPE）を同時に比較したい**  
**そうすることで** サンプラーごとの収束速度・Pareto 品質・変数探索傾向を客観的に評価できる

**関連要件**: REQ-006-A〜D

**詳細シナリオ**:
1. Study 選択で「比較モード」を有効化し、3 Study を選択
2. 統計サマリーテーブルに各 Study の試行数・Pareto 数・Best 値が並列表示される
3. HV 履歴グラフに 3 本の折れ線が重畳し、NSGA-II の収束が最速と確認
4. Pareto 重畳散布図で TPE が Pareto 前線に近い解を多く持つと判明
5. 変数分布 KDE 重畳で探索傾向の違いを視覚化する

**優先度**: Must Have

## エピック5: アーティファクト連携

### ストーリー 5.1: シミュレーション結果画像をトライアルに紐付けて確認する 🔵

**信頼性**: 🔵 *ユーザヒアリング Q3・Q6・first_spec.md アーティファクト設計より*

**私は** FEM シミュレーション結果を Optuna と連携させている設計エンジニア **として**  
**Trial Table から各試行のシミュレーション結果画像をワンクリックで確認したい**  
**そうすることで** 応力分布や形状の良否を目視確認しながら最適解を選定できる

**関連要件**: REQ-007-A〜H

**詳細シナリオ**:
1. Journal ファイルを読み込むと、隣接の `artifacts/` フォルダが自動検出される
2. Trial Table の「Artifacts」列に 📷 アイコンが表示されている試行がある
3. 試行 ID 1024 の 📷 アイコンをクリック
4. モーダルが開き、`artifacts/1024/result.png` の応力分布画像が表示される
5. 画像を確認しながら他の Pareto 解と比較して最終設計案を選定

**優先度**: Must Have

## エピック6: 単目的最適化対応

### ストーリー 6.1: 収束状況をリアルタイムで診断する 🔵

**信頼性**: 🔵 *ユーザヒアリング Q8・first_spec.md 単目的設計より*

**私は** 長時間の単目的最適化を監視しているエンジニア **として**  
**Left Panel で現在の Best 値・改善率・収束状況を一目で確認したい**  
**そうすることで** 「もう十分収束した」と判断して最適化を手動停止するタイミングを掴める

**関連要件**: REQ-008-A〜F

**詳細シナリオ**:
1. 単目的 Study（minimize: objective_value）を選択
2. Left Panel に「収束診断カード」が自動で表示される
3. カードには「Best: 0.0234（Trial #4821）」「直近100試行の改善率: 0.3%」と表示
4. Optimization History チャートに Best 値追跡ラインが重畳表示される
5. 半対数スケール切り替えで収束の鈍化を確認
6. Bottom Panel の「Best 解遷移」タブで Best 値更新の履歴を確認

**優先度**: Must Have

## エピック7: Parallel Coordinates 拡張

### ストーリー 7.1: 不要な軸を隠して重要な変数に絞り込む 🔵

**信頼性**: 🔵 *ユーザヒアリング Q9・parallel_coords.rs より*

**私は** 30 変数の最適化結果を分析しているエンジニア **として**  
**Parallel Coordinates から重要でない変数を非表示にして重要な 5 軸に絞りたい**  
**そうすることで** 密集した 30 軸 PCP から重要な変数関係のみを鮮明に確認できる

**関連要件**: REQ-009-A〜C

**詳細シナリオ**:
1. 30 軸の Parallel Coordinates が表示されている
2. Importance Chart で重要度が低い x15〜x30 の 👁 アイコンをクリックして非表示
3. 10 軸に絞られた PCP で変数間の相関が明確になる
4. 目的関数軸を「掴みハンドル」でドラッグして左端に移動
5. 変数→目的の流れが左から右へ自然に見えるようになる

**優先度**: Should Have
