# sensitivity-refactoring ヒアリング記録

**作成日**: 2026-05-04
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

コード分析（Explore agent による全16ファイルの網羅的調査）から特定した重複・問題箇所について、リファクタリング方針をユーザーと確認するためのヒアリングを実施。

## 質問と回答

### Q1: 標準化処理の共通化先

**質問日時**: 2026-05-04
**カテゴリ**: 既存設計確認
**背景**: `column_mean_std` 相当の処理が `sensitivity/ridge.rs`、`sensitivity/analysis/common.rs`、`sensitivity/sobol.rs`、`pdp/utils.rs` の4箇所に重複実装されていた。共通化先として3択を提示。

**回答**: `core::math に昇格`

**信頼性への影響**:
- REQ-001〜REQ-002 の信頼性レベルが 🟡 → 🔵 に向上
- pdp モジュールも対象に含まれることが明確化（REQ-002-4 追加）

---

### Q2: 型安全性（Newtype vs 型エイリアス）

**質問日時**: 2026-05-04
**カテゴリ**: 既存設計確認
**背景**: `RfAnovaResult`・`MdiResult`・`ShapResult`・`PermutationResult` が全て `TreeImportanceResult` の型エイリアスで、コンパイル時に区別できない状態だった。

**回答**: `Newtypeパターンに変更（推奨）`

**信頼性への影響**:
- REQ-003 の信頼性レベルが 🟡 → 🔵 に向上
- 型エイリアスを使用していた呼び出し側の対応（REQ-003-3）を要件に追加

---

### Q3: ツリーメトリクスの構造化

**質問日時**: 2026-05-04
**カテゴリ**: 既存設計確認
**背景**: MDI/SHAP/RF-ANOVA/PFI の4メトリクスが同一フロー（フィルタリング → ダウンサンプリング → 分割 → 訓練 → 重要度計算 → 正規化）を独立して実装していた。

**回答**: `Trait で抽象化（推奨）`

**信頼性への影響**:
- REQ-004 全体の信頼性レベルが 🟡 → 🔵 に向上（具体的な実装方針が確定）
- `TreeMetric` トレイトのメソッドシグネチャは実装時に調整可能

---

### Q4: MAX_ROWS 定数の扱い

**質問日時**: 2026-05-04
**カテゴリ**: 既存設計確認
**背景**: 各メトリクスの `MAX_ROWS` が個別ファイルに散在（MDI/SHAP: 1000、RF-ANOVA/PFI: 2000）し、値が異なる理由もドキュメント化されていなかった。

**回答**: `定数を集約（推奨）`（値の変更はしない）

**信頼性への影響**:
- REQ-005 の信頼性レベルが 🔴 → 🔵 に向上
- 値の変更は行わないことが確定（NFR-002 の基準が明確化）

---

### Q5: pdp モジュールの包含

**質問日時**: 2026-05-04
**カテゴリ**: 影響範囲確認
**背景**: `pdp/utils.rs::col_mean_std` と `sensitivity` の標準化処理が同一アルゴリズム。`pdp/ridge_core.rs` は `sensitivity::compute_ridge` を直接呼び出しており、関連度が高い。

**回答**: `pdpも包含`

**信頼性への影響**:
- REQ-002-4 追加（pdp/utils.rs の col_mean_std を core::math に統合）
- REQ-007-2 追加（pdp パブリックAPIの維持要件）

---

## ヒアリング結果サマリー

### 確認できた事項

- 標準化処理は `core::math::stats` への集約が確定
- Newtypeパターン採用が確定（既存のNewtype使用箇所の修正が必要）
- Trait 抽象化の採用が確定
- MAX_ROWS の値は変更しない（集約のみ）
- pdp モジュールもリファクタリング対象に含む

### 追加/変更要件

- REQ-002-4: pdp/utils.rs も統一対象に追加
- REQ-007-2: pdp パブリックAPI維持要件を追加
- NFR-005: 定数へのコメント記載要件を追加

### 残課題

- `TreeMetric` トレイトの具体的なメソッドシグネチャ（`&self` vs 関連関数、エラー型など）は設計フェーズで確定する
- Newtypeラッパー導入による呼び出し側の変更量は設計フェーズで見積もりを取る
- `analysis/full.rs` での Trait 利用方法（トレイトオブジェクト vs ジェネリクス）は設計フェーズで決定する
