## エピック1: リアルタイムデータ監視

### ストーリー 1.1: ワンクリックでライブ更新を開始する 🔵

**信頼性**: 🔵 *既存トグルUI + ヒアリング「トグルのみで開始」より*

**私は** 最適化実験実行者 **として**
**ツールバーの「Live: On/Off」ボタンを1クリックでファイルの自動更新を開始したい**
**そうすることで** 手動でファイルを再読み込みすることなく、最適化の進行状況をリアルタイムに確認できる

**関連要件**: REQ-LU-003, REQ-LU-004, REQ-LU-005

**詳細シナリオ**:
1. ユーザーがJournalファイルを開き、Studyを選択済み
2. ツールバーの「Live: Off」ボタンをクリック
3. ボタンが「Live: On」に切り替わり、バックグラウンドでポーリング開始
4. 2秒後に最初のポーリングが実行される

**前提条件**:
- Journalファイルが開かれていること
- Studyが選択されていること

**制約事項**:
- ファイル未開封時はトグルを無効化
- ポーリングはバックグラウンドスレッドで実行

**優先度**: Must Have

---

### ストーリー 1.2: ポーリング間隔を調整する 🔵

**信頼性**: 🔵 *ヒアリング「間隔調整UI」より*

**私は** 最適化実験実行者 **として**
**ポーリング間隔を1秒〜30秒の範囲で調整したい**
**そうすることで** 最適化の速度に合わせた更新頻度を設定できる

**関連要件**: REQ-LU-002, REQ-LU-301

**詳細シナリオ**:
1. ユーザーがツールバーまたは設定UIで間隔調整コントロールを操作
2. スライダーまたは入力で1秒〜30秒の範囲で値を設定
3. 変更は次回ポーリングから即座に反映される

**前提条件**:
- ライブ更新が有効または無効のどちらでも調整可能

**優先度**: Must Have

## エピック2: データ反映と可視化

### ストーリー 2.1: 新規トライアルを自動的にグラフに反映する 🔵

**信頼性**: 🔵 *既存 LiveUpdateDone メッセージ + ヒアリング「全Study更新」より*

**私は** 解析担当者 **として**
**最適化中に新規トライアルが追加されたら、グラフやテーブルを自動更新したい**
**そうすることで** 常に最新の最適化状況を視覚的に把握できる

**関連要件**: REQ-LU-001, REQ-LU-007, REQ-LU-008

**詳細シナリオ**:
1. ポーリングがファイルサイズの増加を検出
2. 増加分のバイトのみを読み込み
3. `append_journal_diff` で差分パースを実行
4. 新規完了トライアルが存在する場合、`LiveUpdateDone` メッセージを送信
5. メインスレッドがメッセージを受信し、グラフ・テーブル・カウンタを更新
6. 新規完了トライアルが0件の場合はUI更新をスキップ

**前提条件**:
- ライブ更新が有効であること
- Journalファイルが他プロセスから書き込み中であること

**制約事項**:
- 差分パースは100ms以内（1,000行）
- 全件再パースは禁止

**優先度**: Must Have

---

### ストーリー 2.2: 複数Studyのトライアル数を同時更新する 🔵

**信頼性**: 🔵 *ヒアリング「全Study更新」より*

**私は** 最適化研究者 **として**
**複数Studyが存在する場合、すべてのStudyのデータを自動更新したい**
**そうすることで** Study選択ドロップダウンを切り替えた際に即座に最新データを確認できる

**関連要件**: REQ-LU-008, REQ-LU-103

**詳細シナリオ**:
1. Journalファイルに3つのStudy（A, B, C）が含まれている
2. ポーリングで新規トライアルが検出される
3. 全Study（A, B, C）のメタデータ（完了トライアル数）が更新される
4. Study選択ドロップダウンの件数表示が更新される
5. 現在表示中のStudyのグラフが再描画される

**優先度**: Must Have

---

### ストーリー 2.3: 現在の試行数をツールバーで確認する 🔵

**信頼性**: 🔵 *ヒアリング「試行数カウンタ」より*

**私は** 解析担当者 **として**
**ツールバーに現在の完了トライアル数を常に確認したい**
**そうすることで** グラフを見なくても最適化の進捗を把握できる

**関連要件**: REQ-LU-009

**詳細シナリオ**:
1. ツールバーに「Trials: 1,234」のような形式でカウンタを表示
2. ライブ更新で新規トライアルが追加されるたびにカウンタが更新される
3. Study切り替え時もカウンタが該当Studyの件数に更新される

**優先度**: Must Have

## エピック3: ユーザー体験の保護

### ストーリー 3.1: ライブ更新中も分析操作を継続する 🔵

**信頼性**: 🔵 *既存要件 REQ-134 + ヒアリング「全保持」より*

**私は** 解析担当者 **として**
**ライブ更新中にブラシ選択やフィルタ調整を行っても、それらの状態が維持されたい**
**そうすることで** データ更新のたびに分析作業をやり直す必要がない

**関連要件**: REQ-LU-006

**詳細シナリオ**:
1. ユーザーがParetoフロントの一部をブラシ選択中
2. ポーリングで新規トライアルが追加される
3. グラフは新しいデータポイントを含めて再描画される
4. ブラシ選択範囲は維持され、新しいデータポイントが範囲内であれば選択状態に含まれる
5. フィルタ設定、ズーム視点も同様に維持される

**前提条件**:
- ブラシ選択・フィルタ・ズームが設定されていること

**優先度**: Must Have

---

### ストーリー 3.2: エラー発生時に安全に停止する 🔵

**信頼性**: 🔵 *既存 TASK-1201設計 + ヒアリング「自動停止あり」より*

**私は** 最適化実験実行者 **として**
**ファイルアクセスエラーが連続した場合、ライブ更新が自動的に停止しエラー内容を知らせてほしい**
**そうすることで** エラーに気づかず無駄なポーリングが継続されるのを防げる

**関連要件**: REQ-LU-010

**詳細シナリオ**:
1. ファイルがアクセス不能になる（削除・権限変更等）
2. 1回目のエラー: ポーリングを継続
3. 2回目のエラー: ポーリングを継続
4. 3回目のエラー: 自動停止、トグルが「Live: Off」に切り替わり
5. エラーメッセージがツールバーに表示される

**優先度**: Must Have

---

### ストーリー 3.3: 最適化完了の可能性を通知する 🔵

**信頼性**: 🔵 *ヒアリング「通知のみ」より*

**私は** 最適化実験実行者 **として**
**ファイルへの追記が一定時間止まった場合、最適化が完了した可能性を通知してほしい**
**そうすることで** 長時間の最適化で完了タイミングを見逃さない

**関連要件**: REQ-LU-101

**詳細シナリオ**:
1. ポーリングを継続中
2. 60秒間ファイルサイズに変化がない
3. ステータスバーに「最適化が完了した可能性があります」を一時表示
4. ポーリングは継続（再開に備える）

**優先度**: Should Have

## エピック4: ライフサイクル管理

### ストーリー 4.1: 別ファイルを開いたときに監視を切り替える 🟡

**信頼性**: 🟡 *既存コードフローから妥当な推測*

**私は** 解析担当者 **として**
**ライブ更新中に別のJournalファイルを開いた場合、自動的に新しいファイルの監視に切り替わってほしい**
**そうすることで** 手動でライブ更新を停止→再開する手間が省ける

**関連要件**: REQ-LU-201

**詳細シナリオ**:
1. ファイルAをライブ更新中
2. ユーザーが「Open」ボタンでファイルBを開く
3. ファイルAのポーリングが停止
4. ファイルBが読み込まれ、`last_byte_offset` がリセット
5. ライブ更新が有効なままファイルBのポーリングが開始

**優先度**: Should Have

---

### ストーリー 4.2: アプリ終了時にポーリングを確実に停止する 🟡

**信頼性**: 🟡 *ネイティブアプリの基本要件から推測*

**私は** ユーザー **として**
**アプリを閉じたときにバックグラウンドのファイル監視が確実に停止してほしい**
**そうすることで** リソースリークやプロセス残留を防げる

**関連要件**: REQ-LU-203

**詳細シナリオ**:
1. ライブ更新が有効な状態でアプリを閉じる
2. ポーリングスレッドに停止シグナルが送信される
3. スレッドが現在の処理を完了後、クリーンに終了
4. アプリプロセスが正常に終了

**優先度**: Must Have
