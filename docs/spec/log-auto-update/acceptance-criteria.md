## REQ-LU-001: ポーリング方式のファイルサイズ検出と差分パース 🔵

**信頼性**: 🔵 *既存実装 live_update.rs + ヒアリングより*

### Given（前提条件）
- Journalファイルが開かれている
- ライブ更新が有効である
- ファイルが外部プロセスから追記されている

### When（実行条件）
- ポーリング間隔（デフォルト2秒）が経過した

### Then（期待結果）
- ファイルサイズが前回の `last_byte_offset` より大きい場合、増加分のバイトのみを読み込む
- `append_journal_diff` が呼び出される
- 消費バイト数が `last_byte_offset` に加算される

### テストケース

#### 正常系

- [ ] **TC-001-01**: ファイルに新規トライアル3件が追記された場合、差分パースで3件の完了トライアルを検出する 🔵
  - **入力**: 3件のCOMPLETEトライアル（CREATE + SET_PARAM + SET_STATE_VALUES）が追記されたファイル
  - **期待結果**: `new_completed = 3`, `consumed_bytes = 追記バイト数`
  - **信頼性**: 🔵 *既存テスト tc_1201_01 と同パターン*

- [ ] **TC-001-02**: ファイルサイズが変化していない場合、ファイル読み込みをスキップする 🔵
  - **入力**: ファイルサイズ = `last_byte_offset`
  - **期待結果**: ファイル読み込みなし、`LiveUpdateDone` メッセージ送信なし
  - **信頼性**: 🔵 *ポーリングの基本動作*

#### 異常系

- [ ] **TC-001-E01**: ファイルが削除されている場合、エラーカウントが+1される 🔵
  - **入力**: 監視対象ファイルが存在しない
  - **期待結果**: エラーカウント +1、ポーリング継続
  - **信頼性**: 🔵 *EDGE-LU-001 より*

#### 境界値

- [ ] **TC-001-B01**: 1行のみの追記（最小差分）を正しく処理する 🔵
  - **入力**: 1行のJSONL（完全な\n終端あり）
  - **期待結果**: 正常パース
  - **信頼性**: 🔵 *find_consumed_bytes() の設計より*

## REQ-LU-003: トグルによるライブ更新制御 🔵

- バックグラウンドスレッドでポーリングループが開始される
- `file_path` と `last_byte_offset` が現在のファイル情報で初期化される

### テストケース

#### 正常系

- [ ] **TC-003-01**: トグルONでポーリングが開始される 🔵
  - **入力**: ToggleLiveUpdate アクション
  - **期待結果**: `live_update.enabled = true`、ポーリングスレッド起動
  - **信頼性**: 🔵 *既存コードフロー*

- [ ] **TC-003-02**: トグルOFFでポーリングが停止される 🔵
  - **入力**: ライブ更新ON状態で ToggleLiveUpdate アクション
  - **期待結果**: `live_update.enabled = false`、ポーリングスレッド停止
  - **信頼性**: 🔵 *既存コードフロー*

#### 異常系

- [ ] **TC-003-E01**: ファイル未開封時はトグルが無効化される 🔵
  - **入力**: ファイル未開封状態
  - **期待結果**: 「Live: On/Off」ボタンがクリック不可
  - **信頼性**: 🔵 *REQ-LU-004 より*
