# Tree-based 感度分析の重複解消 ヒアリング記録

**作成日**: 2026-05-02
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

コード分析で判明した、タスクファイル記載外の重複箇所・実装方針の選択肢について確認するためのヒアリングを実施しました。

## 質問と回答

### Q1: 追加重複のスコープについて

**質問日時**: 2026-05-02
**カテゴリ**: スコープ確認
**背景**: コード分析で NaN/Inf フィルタリング・80/20 holdout split の追加重複を発見したため、タスクファイルの範囲に含めるか確認が必要

**質問**: タスクファイルに記載されていない追加の重複（NaN/Inf フィルタリング、80/20 holdout split）も今回のスコープに含めますか？

**回答**: 含めない（推奨）

**信頼性への影響**:
- これにより REQ-401〜REQ-406 は `permute_single_column` / `normalize` のみに限定され、信頼性レベルが 🔵 に確定
- 追加重複は「スコープ外」として明記

---

### Q2: R² 計算の統一について

**質問日時**: 2026-05-02
**カテゴリ**: 既存設計確認
**背景**: `rf_anova.rs` が独自の R² 計算（行107-113）を持つのに対し、`permutation.rs` は `mse_to_r_squared()` を使用している。内部実装統一の機会として確認

**質問**: rf_anova.rs の独自 R² 計算を permutation.rs と同じ mse_to_r_squared() に統一しますか？

**回答**: 統一する（推奨）

**信頼性への影響**:
- 新規要件 REQ-501, REQ-502 を追加（信頼性レベル: 🔵, 🟡）
- R² 計算結果は機能的に同一であるため、動作への影響なし

---

### Q3: ファイル配置について

**質問日時**: 2026-05-02
**カテゴリ**: 未定義部分詳細化
**背景**: タスクファイルは `tree_common.rs` を指定しているが、既存の `sensitivity/data.rs` に追加する選択肢もあるため確認

**質問**: 新規ファイル tree_common.rs を作成する方針でよいですか？

**回答**: tree_common.rs（推奨）

**信頼性への影響**:
- REQ-401 のファイルパスが確定し、信頼性レベルが 🔵 に確定

**回答**: for ループ（推奨）

## ヒアリング結果サマリー

### 確認できた事項
- スコープはタスクファイル記載の4箇所の重複のみ
- 新規ファイル `tree_common.rs` を作成
- R² 計算を `mse_to_r_squared()` に統一
- egui-app 側の results.rs も対象に含める
- normalize は for ループスタイルで統一

### 追加/変更要件
- REQ-501: rf_anova.rs の R² 計算を mse_to_r_squared() に統一（タスクファイルに記載なし、ヒアリングで追加）
- REQ-502: rf_anova.rs に mse_to_r_squared の import を追加（タスクファイルに記載なし）

### 残課題
- なし（全ての不明点が解消済み）
