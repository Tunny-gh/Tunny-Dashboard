# Entropy Weight Method（エントロピー法）要件定義書

## 概要

MCDM（TOPSIS/VIKOR）における目的関数の重みを、試行データの情報エントロピーに基づいて客観的に自動算出する機能。Shannon エントロピーを用いて各目的のデータ分散を評価し、分散が大きい（情報量が多い）目的ほど大きな重みを付与する。

## 機能要件（EARS記法）

**【信頼性レベル凡例】**:
- 🔵 **青信号**: 既存実装パターン・ユーザヒアリングを参考にした確実な要件
- 🟡 **黄信号**: 既存実装パターンから妥当な推測による要件
- 🔴 **赤信号**: 既存実装パターンにない推測による要件

### 通常要件

- REQ-001: システムは、試行データの目的関数値から各目的の情報エントロピーを計算し、エントロピー重みベクトルを返さなければならない 🔵 *既存MCDMアーキテクチャ・エントロピー法の標準定義より*
- REQ-002: システムは、エントロピー重みの計算に比例正規化（p_ij = x_ij / sum_i(x_ij)）を使用しなければならない 🔵 *ユーザヒアリング「比例正規化」より*
- REQ-003: システムは、計算されたエントロピー重みを Weights セクションのスライダーに自動反映しなければならない 🔵 *ユーザヒアリング「重みスライダーに自動反映」より*
- REQ-004: システムは、各目的のエントロピー値・分散・重みをテーブル形式で表示しなければならない 🔵 *ユーザヒアリング「エントロピー値のテーブル表示」より*
- REQ-005: エントロピー重みは、TOPSIS/VIKOR すべての MCDM 手法で共通利用しなければならない 🔵 *ユーザヒアリング「全手法共通」より*
- REQ-006: システムは、Weights セクションに「Manual / Entropy」切替コントロールを提供しなければならない 🔵 *既存UIパターン（McdmMethodセレクタ）より*

### 条件付き要件

- REQ-101: 目的の値がすべて同じ（分散ゼロ）の場合、システムはその目的のエントロピー値を 1.0 とし、重みを均等分配しなければならない 🔵 *エントロピー法の標準的ゼロ除説処理より*
- REQ-102: 試行データに NaN が含まれる場合、システムは NaN を含む試行を除外してエントロピー計算を行わなければならない 🔵 *既存MCDMのNaN除外パターン（filter_valid_indices）より*
- REQ-103: 有効試行数が 0（全試行NaN）の場合、システムはエラーを返さなければならない 🔵 *既存MCDMの入力検証パターンより*
- REQ-104: 目的の値がすべて非負でない（負の値を含む）場合、システムは比例正規化の前に非負変換（min-max正規化）を適用しなければならない 🟡 *比例正規化の制約から妥当な推測*

### 状態要件

- REQ-201: Weight Mode が Entropy の場合、システムはスライダーを読み取り専用とし、エントロピー計算結果の重みを表示しなければならない 🔵 *ユーザヒアリング「自動反映」より*
- REQ-202: Weight Mode が Manual の場合、システムはスライダーを手動編集可能とし、エントロピー値テーブルを非表示にしなければならない 🔵 *既存UIパターンより*
- REQ-203: 試行データが変更された（ファイル再読込等）場合、Weight Mode が Entropy であればシステムは自動的にエントロピー重みを再計算しなければならない 🟡 *既存UIパターンから妥当な推測*

### オプション要件

- REQ-301: システムは、エントロピー重みをスライダーに反映した後、ユーザが Manual モードに切り替えて微調整できるようにしてもよい 🔵 *ユーザヒアリング「重みスライダーに自動反映」より*

### 制約要件

- REQ-401: エントロピー計算関数は `rust_core`（tunny-core）クレートに実装し、`egui-app` からは `tunny_core::entropy::compute_entropy_weights()` として呼び出さなければならない 🔵 *既存MCDMアーキテクチャ（topsis.rs, vikor.rs パターン）より*
- REQ-402: エントロピー計算の入力は、既存MCDMと同じフラット `values: &[f64]`（行優先）形式で受け取らなければならない 🔵 *既存compute_topsis/compute_vikorの入力パターンより*
- REQ-403: エントロピー重みの合計は 1.0 でなければならない 🔵 *重みの数学的定義より*
- REQ-404: 各重みは 0.0 以上 1.0 以下でなければならない 🔵 *重みの数学的定義より*

- NFR-001: 50,000試行 × 4目的のエントロピー重み計算は 100ms 以内に完了しなければならない 🔵 *既存MCDMパフォーマンス要件（TOPSIS/VIKORと同等）より*
- NFR-002: エントロピー重み計算は、UIスレッドをブロックしないようバックグラウンドタスクで実行しなければならない 🔵 *既存MCDMのspawn_taskパターンより*

### ユーザビリティ

- NFR-201: Weight Mode の切替は即座に反映され、再計算ボタンの押下を必要としない 🟡 *既存UIパターンから妥当な推測*
- NFR-202: エントロピー重みが計算済みの場合、手法（TOPSIS/VIKOR）を切り替えても重みは維持される 🔵 *ユーザヒアリング「全手法共通」より*

### ロバスト性

- NFR-301: 目的数が 1 の場合でもエラーなく動作しなければならない 🔵 *既存MCDMの単一目的テストケースより*
- NFR-302: 試行数が 1 の場合でもエラーなく動作しなければならない 🔵 *既存MCDMの単一試行テストケースより*

## Edgeケース

### エラー処理

- EDGE-001: 全目的のエントロピー値が 1.0（全データ同一）の場合、重みは均等（1/n）とする 🔵 *エントロピー法の標準的処理*
- EDGE-002: 目的の値に負数が含まれる場合、min-max正規化で非負変換後に比例正規化を適用する 🟡 *比例正規化の制約から妥当な推測*
- EDGE-003: 目的の値にゼロが含まれる場合、p_ij * ln(p_ij) = 0 * (-∞) を 0 として扱う 🔵 *Shannon エントロピーの標準的定義（lim x→0+ x·ln(x) = 0）より*
- EDGE-004: 目的の値に NaN が含まれる試行は計算から除外する 🔵 *既存MCDMのNaN除外パターンより*
- EDGE-005: 目的の値に inf/-inf が含まれる場合、NaNと同様に除外する 🟡 *既存実装から妥当な推測*

### 境界値

- EDGE-101: n_objectives = 1 の場合、重み = [1.0] となる 🔵 *数学的定義より*
- EDGE-102: n_trials = 1 の場合、エントロピーは計算不能のため均等重みを返す 🟡 *単一試行では分散ゼロのため妥当な推測*

## アルゴリズム概要

### Step 1: データ正規化

各目的 $j$ の値を比例正規化:

$$p_{ij} = \frac{x_{ij}}{\sum_{k=1}^{m} x_{kj}}$$

※ 負の値を含む場合は先に min-max 正規化で [0, 1] に変換してから適用。

### Step 2: 情報エントロピーの計算

各目的 $j$ のエントロピー:

$$e_j = -\frac{1}{\ln(m)} \sum_{i=1}^{m} p_{ij} \ln(p_{ij})$$

※ $p_{ij} = 0$ の項は $0 \cdot \ln(0) = 0$ として扱う。

### Step 3: 分散度の計算

$$d_j = 1 - e_j$$

### Step 4: 重みの計算

$$w_j = \frac{d_j}{\sum_{k=1}^{n} d_k}$$

※ 全目的の $d_j = 0$（全データ同一）の場合、$w_j = 1/n$（均等重み）。

### 入出力仕様

**入力**:
- `values: &[f64]` — フラット行優先の目的関数値（既存MCDMと同じ形式）
- `n_trials: usize` — 試行数
- `n_objectives: usize` — 目的数

**出力**:
```rust
pub struct EntropyResult {
    pub weights: Vec<f64>,        // 正規化済みエントロピー重み（sum = 1.0）
    pub entropies: Vec<f64>,      // 各目的の情報エントロピー値 e_j
    pub diversities: Vec<f64>,    // 各目的の分散度 d_j = 1 - e_j
    pub normalized_matrix: Vec<f64>, // 正規化行列 p_ij（デバッグ・表示用）
    pub duration_ms: f64,         // 計算時間
}
```
