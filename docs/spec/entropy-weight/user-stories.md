## エピック1: エントロピー重みの計算

### ストーリー 1.1: エントロピー重みを自動計算する 🔵

**信頼性**: 🔵 *ユーザヒアリング「全手法共通」・既存MCDMアーキテクチャより*

**私は** Optuna ダッシュボードユーザー **として**
**試行データからエントロピー法により客観的な重みを自動計算したい**
**そうすることで** 主観的な重み設定に頼らず、データ駆動で目的関数の重要度を評価できる

**関連要件**: REQ-001, REQ-002

**詳細シナリオ**:
1. ユーザーが試行データを読み込む
2. Weights セクションで Weight Mode を「Entropy」に切り替える
3. システムがバックグラウンドでエントロピー計算を実行する
4. 計算完了後、重みスライダーに結果が自動反映される

**前提条件**:
- 試行データが読み込み済みであること
- 目的関数が2つ以上定義されていること

**制約事項**:
- 計算は UI スレッドをブロックしないこと（NFR-002）

**優先度**: Must Have

### ストーリー 1.2: エントロピー値の詳細を確認する 🔵

**信頼性**: 🔵 *ユーザヒアリング「エントロピー値のテーブル表示」より*

**私は** Optuna ダッシュボードユーザー **として**
**各目的のエントロピー値・分散度・重みをテーブルで確認したい**
**そうすることで** どの目的がデータにおいて情報量（分散）が大きいかを客観的に理解できる

**関連要件**: REQ-004

**詳細シナリオ**:
1. Weight Mode が Entropy の場合、Weights セクション内にテーブルが表示される
2. テーブルには各目的の以下の値が表示される:
   - 目的名
   - 情報エントロピー値 (e_j)
   - 分散度 (d_j = 1 - e_j)
   - エントロピー重み (w_j)

**前提条件**:
- エントロピー計算が完了していること

**優先度**: Must Have

## エピック2: 重みモードの切替

### ストーリー 2.1: Manual/Entropy モードを切り替える 🔵

**信頼性**: 🔵 *ユーザヒアリング「重みスライダーに自動反映」・既存UIパターンより*

**私は** Optuna ダッシュボードユーザー **として**
**重みの設定方法を Manual と Entropy の間で切り替えたい**
**そうすることで** 目的に応じて主観的な重み調整と客観的な重み計算を使い分けられる

**関連要件**: REQ-006, REQ-201, REQ-202

**詳細シナリオ**:
1. Weights セクションの上部に Weight Mode セレクタが表示される
2. "Manual" 選択時: 重みスライダーが手動編集可能、エントロピーテーブル非表示
3. "Entropy" 選択時: エントロピー計算が実行され、スライダーが読み取り専用、エントロピーテーブル表示

**前提条件**:
- 試行データが読み込み済みであること

**優先度**: Must Have

### ストーリー 2.2: エントロピー重みを微調整する 🔵

**信頼性**: 🔵 *ユーザヒアリング「重みスライダーに自動反映」より*

**私は** Optuna ダッシュボードユーザー **として**
**エントロピー重みをベースに手動で微調整したい**
**そうすることで** 客観的な重みを起点としつつ、ドメイン知識を反映した最終調整ができる

**関連要件**: REQ-301, REQ-201

**詳細シナリオ**:
1. Entropy モードでエントロピー重みがスライダーに反映される
2. Manual モードに切り替える
3. スライダーの値はエントロピー重みのまま手動編集可能になる
4. ユーザーがスライダーを微調整して Run ボタンを押す

**前提条件**:
- エントロピー計算が完了していること

**優先度**: Could Have

## エピック3: 堅牢なエッジケース処理

### ストーリー 3.1: 全データ同一の目的を処理する 🔵

**信頼性**: 🔵 *エントロピー法の標準的定義より*

**私は** Optuna ダッシュボードユーザー **として**
**全試行で同一値の目的があってもエラーなくエントロピー計算をしてほしい**
**そうすることで** 特殊なデータセットでも安心して利用できる

**関連要件**: REQ-101, EDGE-001

**詳細シナリオ**:
1. 目的1の値が全試行で同一（例: 全て 5.0）
2. エントロピー計算を実行
3. 目的1のエントロピー e_1 = 1.0、分散度 d_1 = 0.0 となる
4. d_1 = 0 の目的は重み計算から除外、残りの目的で重みを再配分
5. 全目的が d_j = 0 の場合、均等重み（1/n）を返す

**優先度**: Must Have

---

### ストーリー 3.2: NaN や負の値を含むデータを処理する 🔵

**信頼性**: 🔵 *既存MCDMのNaN除外パターン・エントロピー法の制約より*

**私は** Optuna ダッシュボードユーザー **として**
**NaN や負の値を含むデータでもエントロピー計算が動作してほしい**
**そうすることで** データの前処理を気にせず利用できる

**関連要件**: REQ-102, REQ-103, REQ-104, EDGE-004, EDGE-005

**詳細シナリオ**:
1. 一部試行に NaN が含まれる → NaN 試行を除外して計算
2. 目的値に負数が含まれる → min-max 正規化で非負変換後に計算
3. 全試行が NaN → エラーメッセージを表示

**優先度**: Must Have
