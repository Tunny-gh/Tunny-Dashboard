## エピック 1: 感度分析の高速化

### ストーリー 1.1: 複数目的変数での感度分析を素早く完了させたい 🔵

**信頼性**: 🔵 *ユーザヒアリング（適用範囲: Sensitivity 目的変数ループ）・コードベース調査より*

**私は** Tunny Dashboard のユーザー **として**  
**複数の目的変数（N ≥ 2）に対して感度分析（RfAnova/MDI/SHAP/Permutation）を実行したい**  
**そうすることで** 分析結果を N 倍近くの速度で得られ、インタラクティブな探索ができる

**関連要件**: REQ-001, REQ-101, NFR-001

**詳細シナリオ**:
1. ユーザーが Sensitivity ウィジェットのメトリクスを選択し、計算をトリガーする
2. `run_tree_metric_for_all_objectives` が `objective_columns` を `par_iter()` で並列処理する
3. 各目的変数の LightGBM モデルが独立したスレッドで並列訓練・推論される
4. 全目的変数の計算完了後、結果が UI に反映される

**前提条件**:
- 目的変数が 2 個以上存在する
- `rayon = "1"` が Cargo.toml に存在する（既存）

**制約事項**:
- 各目的変数のモデルインスタンスは独立（共有なし）
- 既存テストが全て通過すること

**優先度**: Must Have

### ストーリー 1.2: Sobol 感度分析のサロゲート訓練を高速化したい 🔵

**信頼性**: 🔵 *ユーザヒアリング（適用範囲: Sobol サロゲート per-objective）・コードベース調査より*

**私は** Tunny Dashboard のユーザー **として**  
**Sobol 感度分析の計算時間を短縮したい**  
**そうすることで** 多目的最適化の感度を迅速に確認できる

**関連要件**: REQ-002, NFR-001

**詳細シナリオ**:
1. Sobol 感度分析がトリガーされる
2. `build_sobol_surrogate` の `y_matrix` ループが `par_iter()` で並列化される
3. 各目的変数の Ridge 回帰サロゲートが並列で訓練される
4. Monte Carlo サンプリングで Sobol 指数が計算される

**前提条件**:
- 目的変数が 2 個以上存在する

**優先度**: Must Have

## エピック 2: RandomForest 訓練の高速化

### ストーリー 2.1: RandomForest の木構築を並列化したい 🔵

**信頼性**: 🔵 *ユーザヒアリング（適用範囲: RandomForest 木構築ループ）・コードベース調査より*

**私は** 開発者 **として**  
**`RandomForest::train` の木構築ループを rayon で並列化したい**  
**そうすることで** Spearman/Ridge 以外のツリー系メトリクスで使われる場合の訓練が高速化する**

**関連要件**: REQ-003, REQ-102, NFR-002

**詳細シナリオ**:
1. `RandomForest::train` が呼ばれる
2. `0..n_trees` のループを `rayon::into_par_iter()` に置き換える
3. 各木のシードは `seed.wrapping_add(tree_index as u64)` など決定論的に計算する
4. 生成した `DecisionTree` を収集して `RandomForest` を構成する

**前提条件**:
- `Lcg::new(seed)` がスレッドごとに独立して呼べる

**制約事項**:
- シードは `seed + tree_index` 形式で決定論的

**優先度**: Must Have

## エピック 3: Permutation Feature Importance の高速化

### ストーリー 3.1: 特徴量ループを並列化したい 🔵

**信頼性**: 🔵 *ユーザヒアリング（適用範囲: Permutation 特徴量ループ）・コードベース調査より*

**私は** Tunny Dashboard のユーザー **として**  
**Permutation Feature Importance の計算を高速化したい**  
**そうすることで** 多数の特徴量（パラメータ）がある最適化問題でも素早く重要度が得られる

**関連要件**: REQ-004, REQ-103, NFR-001

**詳細シナリオ**:
1. Permutation Feature Importance がトリガーされる
2. 現行の in-place 変更パターンを、特徴量ごとに `x_eval` のコピーを独立して保持する設計に変更する
3. `(0..p).into_par_iter()` で特徴量ループを並列化する
4. 各スレッドが独立した `x_eval_work` コピーを操作し、結果を収集する

**前提条件**:
- LightGBM booster の prediction はスレッドセーフ

**制約事項**:
- 評価行列のコピーコストが許容範囲内であること（EDGE-002）

**優先度**: Must Have

## エピック 4: ベンチマーク整備

### ストーリー 4.1: 並列化の効果をベンチマークで定量化したい 🔵

**信頼性**: 🔵 *ユーザヒアリング（ベンチマーク：含める）より*

**私は** 開発者 **として**  
**各並列化対象モジュールに `criterion` ベンチマークを追加したい**  
**そうすることで** 並列化前後の性能差を数値で示すことができる

**関連要件**: NFR-002

**詳細シナリオ**:
1. `rust_core/benches/` に感度分析・Sobol・RF・Permutation のベンチマークを追加する
2. 直列版と並列版を同一入力で実行して時間を比較する
3. `cargo bench` でレポートを生成する

**優先度**: Should Have
