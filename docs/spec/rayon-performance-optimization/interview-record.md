# rayon 導入による並列化高速化 ヒアリング記録

**作成日**: 2026-05-04  
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

既存コードベース（`rust_core`）の調査結果を踏まえ、rayon 導入の対象範囲・
LightGBM スレッドセーフ方針・egui との競合管理・ベンチマーク要件を明確化するため
ヒアリングを実施した。

---

## 質問と回答

### Q1: rayon を新たに適用する範囲

**質問日時**: 2026-05-04  
**カテゴリ**: 未定義部分詳細化  
**背景**: `rayon = "1"` は Cargo.toml に既に存在するが、利用は `pdp/kriging_core.rs` のみ。
感度分析・Sobol・RandomForest・Permutation のループが直列であることをコード調査で確認し、
4 つの候補を提示した。

**回答**: 「Sensitivity 目的変数ループ」「Sobol サロゲート (per-objective)」「RandomForest 木構築ループ」「Permutation 特徴量ループ」の **全 4 件を適用対象とする**。

**信頼性への影響**:
- REQ-001〜004 の信頼性レベルが 🔴（推測）→ 🔵（ヒアリング確定）に向上

---

### Q2: LightGBM スレッドセーフ方針

**質問日時**: 2026-05-04  
**カテゴリ**: 既存設計確認  
**背景**: LightGBM C API は「訓練はスレッドアンセーフ、予測はスレッドセーフ」という仕様がある。
目的変数ごとのモデルインスタンスは独立しているため並列化できるが、
ユーザーの意図を確認する必要があった。

**回答**: 「**並列訓練を許可**」— 各目的変数の LightGBM モデルは独立したインスタンスであるため、
並列に訓練することを認める。

**信頼性への影響**:
- REQ-101 の信頼性レベルが 🟡（推測）→ 🔵（ヒアリング確定）に向上

---

### Q3: egui スレッド競合管理

**質問日時**: 2026-05-04  
**カテゴリ**: 既存設計確認  
**背景**: rayon のグローバルスレッドプールが egui UI スレッドのレスポンスに影響する
可能性があるため、スレッド数制限が必要か確認した。

**回答**: 「**変更不要**」— 既存の非同期呼び出し構造のまま維持する。
rayon のデフォルトスレッド数制限は行わない。

**信頼性への影響**:
- REQ-401 の信頼性レベルが 🟡（推測）→ 🔵（ヒアリング確定）に向上

---

### Q4: ベンチマーク要件

**質問日時**: 2026-05-04  
**カテゴリ**: 追加要件  
**背景**: 並列化の効果を定量的に示すため、`criterion` ベンチマークのカバレッジ追加が
有効かどうかを確認した。

**回答**: 「**含める**」— `criterion` ベンチマークに対象モジュールのカバレッジを追加する。

**信頼性への影響**:
- NFR-002 が新規追加（信頼性レベル: 🔵）

---

### Q5: 並列化後の安全検証方法

**質問日時**: 2026-05-04  
**カテゴリ**: 既存設計確認  
**背景**: 並列化により計算順序が変わる可能性があり、結果の正確性をどう担保するか確認した。

**回答**: 「**既存テストの通過で十分**」— 専用の再現性テストは不要。
`cargo test` の通過を以て安全性の証明とする。

**信頼性への影響**:
- REQ-201・NFR-101 の信頼性レベルが 🟡→🔵 に向上

## ヒアリング結果サマリー

### 確認できた事項
- rayon は既に依存関係として存在し、`pdp/kriging_core.rs` で実績がある
- LightGBM の目的変数ごと並列訓練は許可される
- egui スレッド競合の懸念はなく、スレッド数制限は不要
- 既存テストの通過のみで安全性は十分

### 追加/変更要件
- **追加**: NFR-002（criterion ベンチマークカバレッジ）
- **全 4 パス**（Sensitivity・Sobol・RF・Permutation）が正式に適用対象となった

### 残課題
- Permutation の in-place 変更パターンの具体的な再設計方針（REQ-103）は設計フェーズで検討
- RandomForest 並列化後の決定論的シード設計（REQ-102）は実装時に要確認
- rayon のスレッドプールデフォルト数が CPU コア数であることによる影響を実測で確認
