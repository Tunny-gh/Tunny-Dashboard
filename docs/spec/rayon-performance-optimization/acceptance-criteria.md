## REQ-001: Sensitivity 目的変数ループ並列化 🔵

**信頼性**: 🔵 *ユーザヒアリング・コードベース調査より*

### Given（前提条件）
- `rust_core/Cargo.toml` に `rayon = "1"` が存在する
- 目的変数が 2 個以上の `DataFrame` がアクティブ

### When（実行条件）
- `run_tree_metric_for_all_objectives` が呼ばれる

### Then（期待結果）
- `objective_columns.par_iter()` による並列処理が行われる
- 各目的変数の結果が収集されて `TreeImportanceResult` として返される
- シングルスレッドの結果と統計的に同等な重要度値が得られる

### テストケース

#### 正常系

- [ ] **TC-001-01**: 2 目的変数での並列実行 🔵
  - **入力**: n=100 行, p=3 パラメータ, n_objectives=2
  - **期待結果**: 重要度ベクトルの長さが p=3、2 目的変数分の結果が返る
  - **信頼性**: 🔵 *既存テスト構造より*

- [ ] **TC-001-02**: 4 目的変数での並列実行 🔵
  - **入力**: n=100 行, p=4 パラメータ, n_objectives=4
  - **期待結果**: 4 目的変数分の結果が正しく返る
  - **信頼性**: 🔵 *ユーザヒアリングより*

#### 異常系

- [ ] **TC-001-E01**: 目的変数 1 個のシングルオブジェクティブ 🔵
  - **入力**: n_objectives=1
  - **期待結果**: rayon は起動するが実質直列処理。結果は従来と同一
  - **信頼性**: 🔵 *rayon の par_iter(1要素) 動作より*

- [ ] **TC-001-E02**: データ行数 n < 2 🔵
  - **入力**: n=1
  - **期待結果**: 早期リターン（全ゼロベクトル）。パニックなし
  - **信頼性**: 🔵 *既存ガード処理より*

## REQ-003: RandomForest 木構築ループ並列化 🔵

**信頼性**: 🔵 *ユーザヒアリング・コードベース調査より*

### Given（前提条件）
- `n_trees > 1`
- 各木のシードが `seed.wrapping_add(tree_index as u64)` で計算される

### When（実行条件）
- `RandomForest::train` が呼ばれる

### Then（期待結果）
- `n_trees` 本の `DecisionTree` が並列で構築されて収集される
- 同一シードで実行した場合、従来の直列版と同一の `DecisionTree` が構築される（決定論的）

### テストケース

#### 正常系

- [ ] **TC-003-01**: n_trees=10 での並列訓練 🔵
  - **入力**: n=50, p=2, n_trees=10, seed=42
  - **期待結果**: `RandomForest.trees.len() == 10`
  - **信頼性**: 🔵 *既存 RF テストより*

- [ ] **TC-003-02**: 決定論的シード検証 🟡
  - **入力**: 同一 (x, y, seed)
  - **期待結果**: 2 回実行で同一の予測値が得られる
  - **信頼性**: 🟡 *シード設計から妥当な推測（浮動小数点加算順の微差を許容）*
  - **備考**: R² の差異が `1e-9` 以内であれば合格

#### 境界値

- [ ] **TC-003-B01**: n_trees=1 🔵
  - **入力**: n_trees=1
  - **期待結果**: 正常に 1 本の木が返る。パニックなし
  - **信頼性**: 🔵 *既存テストより*

## REQ-004: Permutation 特徴量ループ並列化 🔵

**信頼性**: 🔵 *ユーザヒアリング・コードベース調査より*

### Given（前提条件）
- `x_eval` の各行コピーが各スレッドに渡される
- `lgbm_mse` の prediction がスレッドセーフ

### When（実行条件）
- `compute_from_prepared` の特徴量ループが呼ばれる

### Then（期待結果）
- `(0..p).into_par_iter()` で特徴量ループが並列実行される
- 各スレッドが独立した `x_eval` コピーを操作する
- 並列化後も `importances.sum() ≈ 1.0`

### テストケース

#### 正常系

- [ ] **TC-004-01**: p=3 での並列特徴量評価 🔵
  - **入力**: n=60, p=3, dominant_feat=0
  - **期待結果**: `importances[0]` が最大値を持つ
  - **信頼性**: 🔵 *既存 permutation テストより*

- [ ] **TC-004-02**: 重要度の合計チェック 🔵
  - **入力**: 任意の (x, y) with n≥20, p≥2
  - **期待結果**: `importances.iter().sum::<f64>() ≈ 1.0` (誤差 `1e-9` 以内)
  - **信頼性**: 🔵 *既存テストケースより*

#### 異常系

- [ ] **TC-004-E01**: p=1 の単一特徴量 🔵
  - **入力**: p=1
  - **期待結果**: `importances.len() == 1`, 合計 1.0
  - **信頼性**: 🔵 *境界値テストより*
