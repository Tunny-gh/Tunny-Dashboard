## エピック1: 統計的有意性のある重要度の可視化

### ストーリー 1.1: 有意なパラメータの特定 🔵

**信頼性**: 🔵 *ユーザヒアリング2026-04-25より*

**私は** 最適化結果を分析するエンジニア **として**
**感度分析チャートでパラメータごとのp値と有意性マークを確認したい**
**そうすることで** 統計的に意味のある重要パラメータと偶然重要に見えるパラメータを区別できる

**関連要件**: REQ-STAT-001, REQ-STAT-004, REQ-STAT-005

**詳細シナリオ**:
1. ユーザーが感度分析タブを開く
2. Spearman / Ridge / RF-ANOVA 等のメトリクスを選択する
3. 重要度バーの右側に「0.032 *」形式でp値と有意性マークが表示される
4. 「*」は p_adjusted < 0.05、「**」は < 0.01、「***」は < 0.001 を意味する
5. Bonferroni 補正済みのp値であることが UI に示される

**前提条件**:
- 感度分析のデータが少なくとも4トライアル以上存在する

**制約事項**:
- p値は Bonferroni 補正済みを表示する
- サンプル数不足（n < 4）の場合は「統計情報なし」と表示する

**優先度**: Must Have

### ストーリー 1.2: 95%信頼区間によるパラメータ重要度の精度把握 🔵

**信頼性**: 🔵 *ユーザヒアリング2026-04-25より*

**私は** 最適化結果を分析するエンジニア **として**
**各パラメータの重要度の95%信頼区間を確認したい**
**そうすることで** 重要度推定値の不確かさを理解し、判断の信頼性を評価できる

**関連要件**: REQ-STAT-002, REQ-STAT-023, REQ-STAT-033, REQ-STAT-042

**詳細シナリオ**:
1. ユーザーが感度分析チャートを表示する
2. 各重要度バーにエラーバー（信頼区間の下限・上限）が表示される
3. 信頼区間が広い場合（サンプル少）はグレーアウトまたは注意表示がある
4. Sobol の場合、R² < 0.5 の目的関数については警告が表示される

**前提条件**:
- 感度分析が完了している状態

**優先度**: Must Have

### ストーリー 1.3: Ridge回帰の係数の統計的有意性確認 🔵

**信頼性**: 🔵 *ユーザヒアリング・Ridge理論より*

**私は** 最適化モデルを評価するエンジニア **として**
**Ridge 回帰の各パラメータ係数が統計的に有意かどうかを確認したい**
**そうすることで** 線形モデル上で目的関数に実際に寄与しているパラメータを特定できる

**関連要件**: REQ-STAT-020〜025, REQ-STAT-061〜062

**詳細シナリオ**:
1. ユーザーが「Ridge」メトリクスを選択する
2. 各パラメータの β 係数バーに「p=0.012 *」形式で表示される
3. Ridge の正則化バイアスにより p値が近似であることを示す「～」マークが表示される
4. R² が高く（≥0.8）かつ p値が低い（**以上）パラメータが最も信頼性が高い

**前提条件**:
- トライアル数 n > p + 2（パラメータ数より2以上多い）

**優先度**: Must Have

## エピック2: 各メトリクス固有の統計的根拠

### ストーリー 2.1: RF-ANOVAのランダム性を考慮した有意性確認 🔵

**信頼性**: 🔵 *ユーザヒアリング（ツリー間分散選択）より*

**私は** 感度分析を利用するエンジニア **として**
**RF-ANOVA の重要度が100本の木にまたがって安定して高いことを確認したい**
**そうすることで** ランダムフォレストのランダム性による偶発的な重要度を除外できる

**関連要件**: REQ-STAT-030〜034

**詳細シナリオ**:
1. ユーザーが「RF-ANOVA」メトリクスを選択する
2. 各パラメータの重要度について、100本の木での平均と信頼区間が表示される
3. 信頼区間が 0 をまたがないパラメータには有意性マークが表示される
4. 不安定なパラメータ（信頼区間が広い）は視覚的に識別可能

**優先度**: Must Have

---

### ストーリー 2.2: Sobol指標の一次効果と交互作用の統計的信頼性確認 🔵

**信頼性**: 🔵 *ユーザヒアリング（Jansen分散選択）より*

**私は** グローバル感度分析を行うエンジニア **として**
**Sobol 一次指標 S_i および全効果指標 ST_i の統計的信頼区間を確認したい**
**そうすることで** サロゲートモデルと有限サンプルによる不確かさを定量的に把握できる

**関連要件**: REQ-STAT-040〜044

**詳細シナリオ**:
1. ユーザーが「Sobol First」または「Sobol Total」を選択する
2. Jansen 推定量から計算された95%信頼区間がバーに表示される
3. サロゲートモデルの R² に基づく品質警告が表示される（R² < 0.5 で赤警告）
4. ST_i - S_i の差（交互作用量）についても信頼区間が計算・表示される

**優先度**: Must Have

## エピック3: 統計計算基盤の整備

### ストーリー 3.1: pure Rustによる統計分布計算 🟡

**信頼性**: 🟡 *外部クレート不可の制約から妥当な推測*

**私は** コア機能を開発する開発者 **として**
**t分布と正規分布のCDFをpure Rustで実装したい**
**そうすることで** 外部クレートなしでp値を計算でき、バイナリサイズを増やさない

**関連要件**: NFR-STAT-020

**詳細シナリオ**:
1. `rust_core/src/core/math/` に `statistics.rs` を追加する
2. t分布 CDF: 正規分布の近似または不完全ベータ関数の実装
3. 標準正規分布 CDF: Abramowitz & Stegun 近似（誤差 < 1.5×10⁻⁷）
4. 単体テストで scipy の結果と照合して精度を確認する

**前提条件**:
- `rust_core/src/core/math/` ディレクトリが存在する

**優先度**: Must Have

**備考**: 既存の `rust_core/src/core/math/linear_algebra.rs` と同モジュールに配置する

---

### ストーリー 3.2: 既存分析関数への統計計算の統合 🔵

**信頼性**: 🔵 *ユーザヒアリング・既存実装から確実な変更点*

**私は** 開発者 **として**
**既存の感度分析計算関数（rf_anova.rs, ridge.rs, spearman.rs 等）を拡張して統計情報を返すよう変更したい**
**そうすることで** 既存の呼び出し側コードへの影響を最小限に抑えながら統計情報を追加できる

**関連要件**: REQ-STAT-060〜063

**詳細シナリオ**:
1. `types.rs` の各構造体に `Option<Vec<...>>` フィールドを追加する
2. 各計算関数（`compute_rf_anova_importances` 等）が統計情報を計算して返すように拡張する
3. 既存のテストはすべて引き続きパスする
4. 統計情報フィールドが `None` でも既存の UI 表示は正常に動作する

**優先度**: Must Have
