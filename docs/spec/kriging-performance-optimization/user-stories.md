## エピック 1: UI ブロック解消

### ストーリー 1.1: Kriging 計算中も UI を操作できる 🔵

**信頼性**: 🔵 *ユーザヒアリング（確実に実装したい）・既存 UI フリーズ問題より*

**私は** Tunny Dashboard ユーザー **として**
**Kriging モデルを選択して計算中でも他の操作（ドロップダウン変更・タブ切り替え）を続けたい**
**そうすることで** 長い計算待ち中に他の分析を並行して進められる

**関連要件**: REQ-001, NFR-003

**詳細シナリオ**:
1. SurfacePlot3D で "Kriging" モデルを選択する
2. 計算が開始され、スピナーとモデル名・推定時間が表示される
3. スピナー表示中でも X軸/Y軸/目的関数のドロップダウンが操作可能
4. 他のタブへの切り替えが可能
5. 計算完了後、スピナーが消えてサーフェスプロットが表示される

**前提条件**:
- ブラウザが Web Worker API をサポートしている
- 試行データが既にロード済み

**制約事項**:
- viteSingleFile 制約下で動作すること

**優先度**: Must Have

## エピック 2: 計算アルゴリズム最適化

### ストーリー 2.1: LML/勾配の二重計算を排除する 🔵

**信頼性**: 🔵 *kriging.rs ボトルネック分析・既存コード構造より*

**私は** Rust コア開発者 **として**
**L-BFGS 各イテレーションの LML と勾配計算を1回の Cholesky 分解で済ませたい**
**そうすることで** 1イテレーションあたり ~2× の計算削減が得られる

**関連要件**: REQ-002

**詳細シナリオ**:
1. `log_ml_with_gradient(x, y, params)` 関数を実装する
2. 1回の build_kernel_matrix + cholesky + compute_alpha + K^{-1} 計算で LML 値と全勾配を返す
3. `optimize_hyperparams` の main loop で `log_ml_with_gradient` を使用する
4. Armijo 線探索では LML のみ（Cholesky + alpha だけ）を再計算する

**優先度**: Must Have

---

### ストーリー 2.2: L-BFGS 収束を早期停止で高速化する 🔵

**信頼性**: 🔵 *ユーザヒアリング（max_iter 削減許容）より*

**私は** Rust コア開発者 **として**
**L-BFGS が LML 変化量が小さい場合に早期に停止するようにしたい**
**そうすることで** 不要なイテレーションを避け実用的な収束を達成できる

**関連要件**: REQ-003

**詳細シナリオ**:
1. `max_iter` を 100 → 50 に変更する
2. 直近の LML 値を記録し、5 イテレーション連続で変化が 1e-3 以下なら早期停止
3. 既存の `‖∇L‖ < 1e-5` 収束条件は維持する

**優先度**: Must Have

---

### ストーリー 2.3: サブサンプル数を 500 に削減する 🔵

**信頼性**: 🔵 *ユーザヒアリング（許容）より*

**私は** Rust コア開発者 **として**
**N > 500 のとき 500 点にサブサンプリングするよう変更したい**
**そうすることで** N=5000 の Study でも Cholesky 分解が 8× 高速化される**

**関連要件**: REQ-004

**詳細シナリオ**:
1. `train_gp` の `subsample_n` デフォルト引数を 1000 → 500 に変更する
2. `compute_pdp_2d_kriging` の `train_gp(…, 500, seed)` 呼び出しを更新する
3. N ≤ 500 の場合はサブサンプリングせず全点を使用する

**優先度**: Must Have

## エピック 3: Sparse Kriging モデル追加

### ストーリー 3.1: Sparse Kriging を選択できる 🔵

**信頼性**: 🔵 *ユーザヒアリング（モデル選択ドロップダウンに追加）より*

**私は** Tunny Dashboard ユーザー **として**
**"Sparse Kriging" を Model ドロップダウンから選択したい**
**そうすることで** N=5000 の大規模 Study でも 5 秒以内にサーフェスプロットを確認できる**

**関連要件**: REQ-005-01, REQ-005-05, REQ-005-06

**詳細シナリオ**:
1. Model ドロップダウンに "Sparse Kriging" オプションが追加されている
2. 選択すると "Expected: < 5s" のスピナーが表示される
3. 計算完了後、サーフェスプロットと R² 値が表示される

**前提条件**: N ≥ M（M=50 誘導点数）の Study がロード済み

**優先度**: Should Have

---

### ストーリー 3.2: N < M の Study でも Sparse Kriging が使える 🔵

**信頼性**: 🔵 *EDGE-003 境界値要件より*

**私は** Tunny Dashboard ユーザー **として**
**試行数が少ない Study（N < 50）でも Sparse Kriging を選択したい**
**そうすることで** モデル選択時にエラーが発生しない**

**関連要件**: EDGE-003

**詳細シナリオ**:
1. N < 50（誘導点数 M=50 より少ない）Study で "Sparse Kriging" を選択する
2. 自動的に標準 Kriging にフォールバックする
3. 計算結果は標準 Kriging と同じ品質で返される

**優先度**: Must Have（安全性のため）
