# Kriging 高速化 ヒアリング記録

**作成日**: 2026-04-05
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

現行 Kriging 実装のボトルネックを分析し、高速化要件を明確化するためのヒアリングを実施。
既存実装 (`rust_core/src/kriging.rs`) の計算量分析結果をユーザーに提示し、
最適化方針の優先順位を決定する。

---

## 質問と回答

### Q1: ユースケース（試行数 N の規模）

**カテゴリ**: 既存設計確認
**背景**: Kriging の計算量 O(N³) はサブサンプル後も N=1000 で 10⁹ ops。
想定 N の規模によって最適化戦略が変わる。

**質問**: Krig の主なユースケース（試行数 N の規模）を教えてください
**回答**: 大規模（N ≤ 5000）

**信頼性への影響**:
- REQ-004（サブサンプル削減）が有効な要件として確定 → 🟡 → 🔵
- NFR-001（10秒以内）の根拠が明確に → 🔵

---

### Q2: 速度と精度のトレードオフ

**カテゴリ**: 既存設計確認
**背景**: サブサンプル削減・L-BFGS削減はいずれも精度と速度のトレードオフがある。
RF との差別化という観点から精度への要求を確認。

**質問**: 速度と精度のトレードオフをどう考えますか？
**回答**: 精度をある程度維持したバランスを期待するが、RFもあるのでそことの差別化は行いたい

**信頼性への影響**:
- Sparse Kriging を「品質モデル」として位置づける設計方針が確定
- max_iter を 50（100からの削減）とする根拠が明確に → REQ-003 🔵
- 差別化のために `R² > 0.8` 品質指標を要件に含めることを検討

---

### Q3: 実装難度の高い最適化を含めるか

**カテゴリ**: 優先順位確認
**背景**: Web Worker・Sparse GP はいずれも実装コストが高い。
ユーザーの時間・リソース制約を確認する。

**質問**: 実装難度の高い最適化を含めますか？
**回答**: 高難度も含む

**信頼性への影響**:
- REQ-001（Web Worker）・REQ-005（Sparse Kriging）が確定 → 🔴 → 🔵

---

### Q4: Web Worker オフロードの優先度

**カテゴリ**: 追加要件
**背景**: Web Worker は UIブロック解消に最も効果的だが、
viteSingleFile 制約下での WASM 転送に工夫が必要。

**質問**: Web Worker オフロードについて
**回答**: 確実に実装したい

**信頼性への影響**:
- REQ-001 全体（6要件）が 🔵 に確定
- viteSingleFile + Worker の技術課題が要件に明示的に含まれた

---

### Q5: Sparse GP の実装方針

**カテゴリ**: 追加要件
**背景**: Sparse GP は O(N×M²) による大幅高速化が可能だが、
標準 Kriging と異なる実装が必要。オプションか自動切替かを確認。

**質問**: Sparse GP（誘導点近似）について
**回答**: オプションで切り替えられるようにできますか？

**信頼性への影響**:
- REQ-005-05（ドロップダウン追加）の根拠が明確に → 🔵
- 自動切替ではなく明示的モデル選択として設計確定

---

### Q6: Sparse GP の UI 切り替え方法

**カテゴリ**: 追加要件詳細化
**背景**: オプション切り替えの UI 実装方法（ドロップダウン追加 vs 自動切替 vs 将来機能）を確認。

**質問**: Sparse GP の UI 切り替え方法を教えてください
**回答**: モデル選択ドロップダウンに追加（推奨）

**信頼性への影響**:
- SurfacePlot3D.tsx の MODEL_OPTIONS に "Sparse Kriging" 追加が確定 → 🔵

---

### Q7: サブサンプル数削減の許容

**カテゴリ**: 既存設計確認
**背景**: subsample_n を 1000→500 にすると N=5000 で 8× 高速化。
多少の精度低下を許容するか確認。

**質問**: サブサンプル数の削減（1000→500）について
**回答**: 許容（推奨）

**信頼性への影響**:
- REQ-004-01（subsample_n=500）が 🔵 に確定

## ヒアリング結果サマリー

### 確認できた事項

- ターゲット試行数: N ≤ 5000
- 速度目標: 10 秒以内（UIブロックなし）
- Kriging の差別化軸: RF より高品質な滑らかな曲面
- Sparse Kriging: 4番目のモデルとしてドロップダウンに追加
- サブサンプル: 1000→500 への削減を許容
- L-BFGS: 100→50 イテレーション削減を許容
- Web Worker: 確実に実装する方針

### 追加要件

- REQ-001: Web Worker オフロード（新規）
- REQ-005: Sparse Kriging モデル（新規）

### 変更要件

- REQ-003: max_iter 100→50（既存 kriging.rs の変更）
- REQ-004: subsample_n 1000→500（既存 kriging.rs の変更）

### 残課題

- viteSingleFile 制約下での Worker + WASM の具体的な実装方法（blob URL? importScripts?）
- Sparse Kriging の誘導点最適化（固定グリッド vs K-means vs 最適化）
- Worker 初期化エラー時のフォールバック詳細仕様
