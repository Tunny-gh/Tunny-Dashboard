## エピック1: VIKORアルゴリズム計算

### ストーリー 1.1: VIKORランキング計算の実行 🔵

**信頼性**: 🔵 *ユーザヒアリング・既存TOPSIS実装パターンより*

**私は** Tunny Dashboardで多目的最適化結果を分析する設計者として  
**MCDMランキングチャートでVIKORを選択してRunを押したい**  
**そうすることで** 妥協解の観点から最良の試行がどれかを定量的に判断できる

**関連要件**: REQ-001, REQ-002, REQ-004, REQ-005

**詳細シナリオ**:
1. MCDMランキングチャートを開く
2. 手法コンボボックスから "VIKOR" を選択
3. 重みスライダーで各目的の重みを調整
4. v パラメータスライダーで妥協度（0〜1）を調整（デフォルト 0.5）
5. "Run" ボタンをクリック
6. スピナーが表示される（計算中）
7. 計算完了後、バーチャートに上位N件のスコアが表示される

**前提条件**:
- スタディが読み込まれており、2つ以上の目的関数が存在する
- is_minimize 情報が app_state から取得できる

**優先度**: Must Have

### ストーリー 1.2: v パラメータによるランキング変化の確認 🔵

**信頼性**: 🔵 *ユーザヒアリング（vスライダー調整可能）より*

**私は** 設計者として  
**v=0.0（最小遺憾重視）とv=1.0（最大多数合意重視）を切り替えてランキングを比較したい**  
**そうすることで** 戦略の違いが意思決定にどう影響するかを把握できる

**関連要件**: REQ-007, REQ-201, EDGE-103, EDGE-104

**詳細シナリオ**:
1. VIKOR選択中、v スライダーを 0.0 に設定
2. Run → バーチャートでR重視のランキングを確認
3. v スライダーを 1.0 に変更
4. Run → バーチャートでS重視のランキングを確認
5. 2つのランキングを比較

**優先度**: Must Have

## エピック2: VikorResult型・アーキテクチャ統合

### ストーリー 2.1: S/R/Q全スコアの格納 🔵

**信頼性**: 🔵 *ユーザヒアリング（S/R/Q全出力）より*

**私は** 将来の機能拡張を視野に入れた開発者として  
**VikorResultにS値・R値・Q値を全て格納したい**  
**そうすることで** テーブル表示や追加分析でrawデータを活用できる

**関連要件**: REQ-301

**詳細シナリオ**:
1. `compute_vikor()` が `VikorResult { s_values, r_values, q_values, ranked_indices, ... }` を返す
2. `McdmResult::Vikor(VikorResult)` で app_state に格納される
3. `primary_scores()` は `1.0 - q_values` を返す（既存UIとの互換）

**優先度**: Must Have

## エピック3: 堅牢性・エラー耐性

### ストーリー 3.1: NaN値を含む試行の安全な処理 🔵

**信頼性**: 🔵 *ユーザヒアリング（TOPSIS同方針）より*

**私は** 設計者として  
**NaNを含む試行がある場合でもVIKOR計算がクラッシュせずに動作してほしい**  
**そうすることで** 不完全なデータでも安全に分析できる

**関連要件**: REQ-101

**詳細シナリオ**:
1. NaN値を含む試行があるスタディでVIKOR計算を実行
2. NaN試行は Q=1.0（最悪値）として扱われる
3. NaN試行はランキング末尾に配置される
4. 残りの有効試行は正常にランキングされる

**優先度**: Must Have

---

### ストーリー 3.2: 入力検証エラーの安全な通知 🔵

**信頼性**: 🔵 *TOPSIS実装パターンより*

**私は** 開発者として  
**不正な入力に対して明確なエラーメッセージを受け取りたい**  
**そうすることで** デバッグを迅速に行える

**関連要件**: REQ-402, EDGE-001〜005

**詳細シナリオ**:
1. n_trials=0 や values長不一致などの不正入力で `compute_vikor` を呼び出す
2. `Err("n_trials must be >= 1")` 等の明確なエラーが返る
3. UIはエラーを EmptyState / Error メッセージとして表示する

**優先度**: Must Have
