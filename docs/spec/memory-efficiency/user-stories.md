## エピック1: 大規模 study の定常メモリ削減

### ストーリー 1.1: 単一 study のメモリ削減 🔵

**信頼性**: 🔵 *PRD MEM-001・コード調査（`types.rs:61`, `io/study.rs:46-94`）より*

**私は** 大規模な Optuna study（数万〜10万試行）を分析する **エンドユーザー** として
**study を開いたときのアプリのメモリ消費を抑えたい**
**そうすることで** メモリ不足や強制終了を起こさず大規模データを快適に分析できる

**関連要件**: REQ-001, REQ-002, REQ-101, NFR-001

**詳細シナリオ**:
1. 10万試行・約22列の Journal ログを読み込む。
2. 完了試行最多の study が自動選択される。
3. アプリは行指向 `Vec<TrialRow>` の永続コピーを作らず、共有列指向ストアを参照する。
4. 定常メモリが現行比で 50% 以上削減されている。

**前提条件**:
- 代表ベンチマークデータセット（100k × 22）が用意されている（[prep.md](prep.md)）。

**制約事項**:
- チャート出力・分析結果は現行と等価（REQ-401）。
- `cargo test --workspace` がグリーン（REQ-404）。

**優先度**: Must Have

### ストーリー 1.2: スレッド間で安全に共有される列ストア 🔵

**信頼性**: 🔵 *ユーザヒアリング2026-05-29・`dataframe/state.rs:12-21` より*

**私は** 状態・データフローを保守する **開発者** として
**列指向 DataFrame を UI スレッドとワーカースレッドの双方から安全に読めるようにしたい**
**そうすることで** 行指向データの複製をワーカー→UI へ送る現行の重複を根本から排除できる

**関連要件**: REQ-002, REQ-003, REQ-403

**詳細シナリオ**:
1. thread_local の `GLOBAL_STATE` を廃止し、DataFrame を `Arc` 等の共有ストアへ移す。
2. `extract_trial_rows()` による行再構築・送信を撤廃、または最小化する。
3. 所有権と無効化ルールが明確に定義される。

**前提条件**:
- ライブ更新時の書き込み同期方式は設計フェーズで詳細化。

**優先度**: Must Have

**備考**: 本ストーリーは MEM-001 の実装基盤であり、後続エピックの前提となる。

## エピック2: ウィジェットキャッシュの重複排除

### ストーリー 2.1: Pareto ウィジェットの行クローン撤廃 🔵

**信頼性**: 🔵 *PRD MEM-002・`pareto_2d.rs:38`, `pareto_3d.rs:99` より*

**私は** Pareto 2D / 3D を多用する **エンドユーザー** として
**これらのウィジェットがデータを二重に抱え込まないでほしい**
**そうすることで** チャートを開くたびにメモリが膨らむのを避けられる

**関連要件**: REQ-004, REQ-005

**詳細シナリオ**:
1. Pareto 2D / 3D の `display_rows_cache: Option<Vec<TrialRow>>` を削除。
2. 描画に必要な最小データ（インデックス・座標・ランク）のみキャッシュ。
3. ダウンサンプル時・非ダウンサンプル時とも描画結果が不変。

**優先度**: Must Have

---

### ストーリー 2.2: 派生列キャッシュの共有・一元化 🔵

**信頼性**: 🔵 *PRD MEM-003・`parallel_coords.rs:71`, `scatter_matrix.rs:31` より*

**私は** 複数の可視化を同時に開く **エンドユーザー** として
**Parallel Coordinates と Scatter Matrix が同じ列データを別々に持たないでほしい**
**そうすることで** 可視化を増やしてもメモリが線形に増えない

**関連要件**: REQ-006, REQ-007, NFR-201

**詳細シナリオ**:
1. 両ウィジェットの `col_data_cache: Option<Vec<Vec<f64>>>` を共有 or 一元化、または都度計算＋即解放。
2. ウィジェット間を切り替えてもメモリが可視化数に比例しない。

**優先度**: Must Have

## エピック3: 比較モードと分析・ロードのピーク削減

### ストーリー 3.1: 軽量な比較 study 🔵

**信頼性**: 🔵 *PRD MEM-005・`app_state.rs:43,128` より*

**私は** 複数 study を比較する **エンドユーザー** として
**比較対象を追加してもメモリがフル study 複製ぶん増えないでほしい**
**そうすることで** 4 件まで比較してもメモリに余裕がある

**関連要件**: REQ-010, REQ-011, REQ-103, REQ-201, EDGE-101

**詳細シナリオ**:
1. `comparison_studies: Vec<StudyContext>` をフル保持から、軽量メタ＋遅延描画データ／共有列ストアへ変更。
2. 比較追加時のメモリ増加がフル複製比例にならない。
3. 比較削除時に関連メモリが速やかに解放される。

**優先度**: Must Have

---

### ストーリー 3.2: 分析実行のピークメモリ削減 🔵

**信頼性**: 🔵 *PRD MEM-004・`poll_chart.rs:16-22` より*

**私は** PDP / Surface Plot / Sensitivity を繰り返し実行する **エンドユーザー** として
**実行のたびに大きな一時行列が作り直されないでほしい**
**そうすることで** 分析実行中のピークメモリとプチフリーズを抑えられる

**関連要件**: REQ-008, REQ-009, REQ-102, NFR-002

**詳細シナリオ**:
1. `r.params` HashMap 参照からの `Vec<Vec<f64>>` 再構築を、借用スライス／共有行列に置換。
2. 入力不変なら再実行で同等の一時行列を再生成しない。

**優先度**: Should Have

---

### ストーリー 3.3: ジャーナルロードのピーク削減 🔵

**信頼性**: 🔵 *PRD MEM-006・`finalize.rs:20,104` より*

**私は** 大きな Journal ログを開く **エンドユーザー** として
**ロード中のピークメモリを抑えたい**
**そうすることで** ロード時の一時的なメモリスパイクで失敗しない

**関連要件**: REQ-012, NFR-003

**詳細シナリオ**:
1. `per_study_rows: Vec<Vec<TrialRow>>` と確定 `DataFrame` の同時保持を最小化（ストリーム化／コンパクション）。
2. 同一ログでロード時ピークが現行より低い。
3. study・目的・user attr・制約のパース結果に回帰なし。

**優先度**: Should Have

---

### ストーリー 3.4: 未使用 GPU ホストバッファの撤廃 🔵

**信頼性**: 🔵 *PRD MEM-007・`types.rs:62`, `message_handler.rs:254`（描画読み出しなし）より*

**私は** 状態を保守する **開発者** として
**UI から読まれていない `gpu_data` を定常状態に持ちたくない**
**そうすることで** 100k 試行あたり約 4MB の無駄を削れる

**関連要件**: REQ-013, REQ-104, EDGE-102

**詳細シナリオ**:
1. 描画側で `gpu_data` が実際に読まれていないことを最終確認。
2. 未使用なら `StudyContext` から削除、または遅延構築＋不要時解放へ変更。
3. ライブ更新が引き続き正しく動作する。

**優先度**: Could Have
