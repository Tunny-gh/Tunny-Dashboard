# memory-efficiency 要件定義書

## 概要

Tunny Dashboard は現在、同一の study データを `rust_core`（列指向 `DataFrame`）と `egui-app`（行指向 `Vec<TrialRow>` ＋ per-row `HashMap`）、および各ウィジェットキャッシュで多重に保持しており、定常時メモリとロード・分析時のピークメモリを押し上げている。本要件は、現行の UI 挙動と分析結果を維持したまま、これらの回避可能な重複を排除しメモリ消費を削減することを定義する。

## 機能要件（EARS記法）

**【信頼性レベル凡例】**:
- 🔵 **青信号**: PRD・設計文書・コード調査・ユーザヒアリングを参考にした確実な要件
- 🟡 **黄信号**: それらから妥当に推測した要件
- 🔴 **赤信号**: 根拠資料にない推測による要件

### 通常要件

- REQ-001: システムは、`rust_core` に同等の列指向データが存在する場合、選択中 study に対して永続的な `Vec<TrialRow>` を materialize・保持してはならない 🔵 *PRD MEM-001 / `egui-app/src/state/types.rs:61`・`io/study.rs:46-94`*
- REQ-002: システムは、アプリ状態における study データ表現として、共有の列指向表現（`DataFrame` の共有ビュー）を用いなければならない 🔵 *PRD MEM-001・ユーザヒアリング2026-05-29（共有ストア化方針）*
- REQ-003: システムは、列指向 `DataFrame` を UI スレッドとワーカースレッドの双方から安全に読めるよう、`Arc` 等の共有ストアで保持し、現行の thread_local 専有保持を廃止しなければならない 🔵 *ユーザヒアリング2026-05-29・`rust_core/src/data/dataframe/state.rs:12-21`*
- REQ-004: システムは、Pareto 2D / Pareto 3D ウィジェットにおいて `Vec<TrialRow>` のクローンキャッシュを保持してはならない 🔵 *PRD MEM-002 / `pareto_2d.rs:38`・`pareto_3d.rs:99`*
- REQ-005: システムは、Pareto 2D / 3D の描画に必要な最小限のデータ（フィルタ済みインデックス、点座標、ランクスライス等）のみをキャッシュしなければならない 🔵 *PRD MEM-002*
- REQ-006: システムは、Parallel Coordinates と Scatter Matrix が同一 study データに対して個別のフルカラムキャッシュをそれぞれ所有しないようにしなければならない 🔵 *PRD MEM-003 / `parallel_coords.rs:71`・`scatter_matrix.rs:31`*
- REQ-007: システムは、可視化に必要な派生数値列を一度だけ構築して共有するか、オンデマンドで計算し速やかに解放しなければならない 🔵 *PRD MEM-003*
- REQ-008: システムは、PDP / Surface Plot / Sensitivity の各実行において、再利用可能な列指向入力が存在する場合に行データから大きな `Vec<Vec<f64>>` 行列を毎回再構築してはならない 🔵 *PRD MEM-004 / `egui-app/src/ui/poll_chart.rs:16-22`*
- REQ-009: 分析パイプラインは、ネストした `Vec<Vec<f64>>` の再構築よりも、借用スライス・フラットバッファ・共有済み行列を優先しなければならない 🔵 *PRD MEM-004*
- REQ-010: システムは、比較モードにおいて、比較対象 study ごとにフルの `StudyContext` を保持してはならない（明示的に必要な場合を除く）🔵 *PRD MEM-005 / `app_state.rs:43`*
- REQ-011: 比較対象 study は、軽量メタデータと遅延構築される描画データ、または共有列指向ストアを用いなければならない 🔵 *PRD MEM-005*
- REQ-012: ジャーナルパースは、中間状態（`TrialBuilder` / per-study 行ベクタ）と確定 `DataFrame` の同時保持を最小化しなければならない 🔵 *PRD MEM-006 / `finalize.rs:20,104`・`state.rs:11`*
- REQ-013: システムは、UI から実際に読まれていないホスト側 `gpu_data` バッファを `StudyContext` の定常状態に保持してはならない 🔵 *PRD MEM-007 / `types.rs:62`・`message_handler.rs:254`（描画側読み出しなし）*

### 条件付き要件

- REQ-101: study を選択した場合、システムは通常運用において永続的な `Vec<TrialRow>` コピーを生成してはならない 🔵 *PRD MEM-001 受け入れ基準*
- REQ-102: 同一 study に対し同一分析を再実行する場合、入力が変化していなければ、システムは同等の大きな一時行列を再生成してはならない 🔵 *PRD MEM-004 受け入れ基準*
- REQ-103: 比較対象 study を追加する場合、システムはフル study 複製にほぼ比例したメモリ増加を発生させてはならない 🔵 *PRD MEM-005 受け入れ基準*
- REQ-104: GPU 関連配列が特定ワークフローでのみ必要な場合、システムはそれを遅延構築し、不要になった時点で解放しなければならない 🔵 *PRD MEM-007*

### 状態要件

- REQ-201: 比較対象 study が削除された状態に遷移する場合、システムは関連メモリを速やかに解放しなければならない 🔵 *PRD MEM-005 / 非機能要件・`app_state.rs:128`*
- REQ-202: study が切り替えられた状態、またはキャッシュが陳腐化した状態にある場合、システムはメモリ解放を明示的に行わなければならない 🔵 *PRD 非機能要件*

### オプション要件

- REQ-301: システムは、共有列指向ストアのメモリ使用状況を debug ビルドで計測・ログ出力してもよい 🟡 *既存 `study.rs` の `[timing]` ログ慣習から妥当な推測*

### 制約要件

- REQ-401: システムは、既存のチャート出力および分析結果を機能的に等価に保たなければならない 🔵 *PRD 非機能要件*
- REQ-402: メモリ最適化は、サイレントなデータ損失を発生させてはならない 🔵 *PRD 非機能要件*
- REQ-403: 新規の共有キャッシュは、所有権と無効化ルールを明確に持たなければならない 🔵 *PRD 非機能要件*
- REQ-404: 等価性は `cargo test --workspace` のグリーン維持で担保しなければならない 🔵 *ユーザヒアリング2026-05-29*
- REQ-405: 本作業は WASM 互換や後方互換シムを必要としない（ネイティブ専用・破壊的変更可）🔵 *CLAUDE.md / プロジェクト方針*

## 非機能要件

### パフォーマンス

- NFR-001: 単一 study の大規模ジャーナルにおける定常メモリを、現行実装ベースラインに対して **少なくとも 50% 削減** しなければならない 🔵 *PRD MEM-001 受け入れ基準*
- NFR-002: 分析実行時のピークメモリは、現行ベースラインより計測可能なほど低くなければならない 🔵 *PRD MEM-004 / 成功基準*
- NFR-003: ジャーナルロード時のピークメモリは、同一ログファイルに対して現行実装より低くなければならない 🔵 *PRD MEM-006 受け入れ基準*
- NFR-004: メモリ削減効果は **100k trials × 約22列の代表データセット** で、改修前後の定常・ピークメモリを定量計測して検証しなければならない 🔵 *ユーザヒアリング2026-05-29・PRD MEM-003*
- NFR-005: メモリ最適化は、study 選択・分析実行・チャート描画の応答性を現行から悪化させてはならない 🟡 *PRD「現行 UI 挙動を維持」から妥当な推測*

### セキュリティ

- （該当なし）本要件はローカル処理のメモリ最適化であり、セキュリティ要件への直接の影響はない 🔵 *PRD スコープ・README（サーバなしローカル処理）*

### ユーザビリティ

- NFR-201: ウィジェット切り替えは、重複 study キャッシュによってメモリ使用量を線形に増加させてはならない 🔵 *PRD MEM-003 受け入れ基準 / 成功基準*

## Edgeケース

### エラー処理

- EDGE-001: 空 study（0 試行）選択時、共有列指向ストアは空表現を返し、`Vec<TrialRow>` 廃止後もパニックせず現行挙動を維持しなければならない 🟡 *`DataFrame::empty()`（`model.rs:27`）から妥当な推測*
- EDGE-002: 数値化できない列（カテゴリ／文字列パラメータ）を含む study でも、列指向アクセスは現行の数値変換挙動を保たなければならない 🟡 *`model.rs:76-99`（string_cols 分岐）から妥当な推測*

### 境界値

- EDGE-101: 比較対象 study の上限（最大4件）でメモリ増加が現行より十分小さく、上限超過時の挙動が現行と等価でなければならない 🔵 *`app_state.rs:43` コメント「最大4件」*
- EDGE-102: ライブ更新中に study データが増加するケースでも、共有ストア／`gpu_data` 遅延化後に正しく更新が反映されなければならない 🔵 *PRD MEM-007 受け入れ基準「Live update continues to behave correctly」*
