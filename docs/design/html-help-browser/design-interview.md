# HTML Help Browser 設計ヒアリング記録

**作成日**: 2026-05-14
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

要件定義で決定した機能要件をもとに、技術設計の詳細判断を明確化するためのヒアリングを実施した。

## 質問と回答

### Q1: 言語切替UIの配置場所

**質問日時**: 2026-05-14
**カテゴリ**: アーキテクチャ
**背景**: 言語切替UIの配置場所により、状態管理のスコープが変わる。ツールバーだとAppState、コンテキストメニューだとローカル状態の可能性がある。

**回答**: メニュー内を選択。「⋯」メニュー内に言語切替を配置。

**信頼性への影響**:
- 言語設定は AppState に保持（ツールバーと同様）
- UIコンポーネントは既存のメニューパターンに統合
- REQ-030 の信頼性レベルが 🔵 に確定

---

### Q2: 日本語ウィジェットヘルプの不存在対応

**質問日時**: 2026-05-14
**カテゴリ**: データモデル
**背景**: theory/ja/ に widgets/ サブディレクトリが存在せず、ParetoScatter2D等の日本語ヘルプがない。フォールバック vs 新規作成の判断が必要。

**回答**: 日本語ウィジェットも作成するを選択。

**信頼性への影響**:
- theory/ja/widgets/ の新規作成がスコープに追加
- フォールバックロジックが不要になり設計がシンプルに
- REQ-041 のスコープが theory/ja/ 全体に確定

---

### Q3: HTMLカラーテーマ

**質問日時**: 2026-05-14
**カテゴリ**: 技術選択
**背景**: eguiアプリはダーク/ライトテーマを切り替え可能。HTMLもテーマ追従するか、固定にするかで実装複雑度が大きく変わる。

**回答**: ライト固定を選択。eguiのテーマには追従しない。

**信頼性への影響**:
- CSS が単一テーマで済み、設計が大幅にシンプルに
- テーマ検出ロジックが不要（AppState からの egui Visuals 参照なし）
- HTMLは常に `color: #333; background: #fff;` のライトテーマ

---

## ヒアリング結果サマリー

### 確認できた事項
- 言語切替UIは「⋯」メニュー内に配置
- theory/ja/widgets/ も新規作成する
- HTMLはライトテーマ固定（eguiテーマ追従なし）

### 設計方針の決定事項
- HelpLanguage は AppState に保持、clear() でリセットしない
- フォールバックロジック不要（全言語の全コンテンツが存在）
- CSSは単一ライトテーマの定数定義のみ
