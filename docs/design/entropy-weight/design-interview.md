# Entropy Weight Method 設計ヒアリング記録

**作成日**: 2026-04-24
**ヒアリング実施**: step4 既存情報ベースの差分ヒアリング

## ヒアリング目的

既存の要件定義・VIKOR設計文書・実装パターンを確認し、Entropy Weight Methodの設計上の選択が必要な部分（UI配置・計算トリガー・スライダー挙動）を明確化するためのヒアリングを実施しました。

## 質問と回答

### Q1: WeightModeセレクタの配置場所

**質問日時**: 2026-04-24
**カテゴリ**: UI設計
**背景**: WeightMode（Manual/Entropy）のセレクタをどこに配置するかで、UIのレイアウトとユーザビリティが変わるため

**回答**: 手法セレクタの横

**信頼性への影響**:
- この回答により、WeightModeセレクタの配置が 🔴 → 🔵 に確定
- 手法（TOPSIS/VIKOR）と重みモード（Manual/Entropy）が横並びで独立操作可能に
- REQ-006のUI設計が確定

---

### Q2: エントロピー計算のトリガー

**質問日時**: 2026-04-24
**カテゴリ**: インタラクション設計
**背景**: エントロピー計算をいつ実行するかで、ユーザー体験とバックグラウンド処理の設計が変わるため

**回答**: Weight Mode切替時（推奨）

**信頼性への影響**:
- この回答により、計算トリガーの設計が 🔴 → 🔵 に確定
- Run ボタンはMCDM計算（TOPSIS/VIKOR）のみに専念
- WeightMode切替時に自動でエントロピー計算 → 結果をスライダーに反映
- NFR-201（即座に反映）の実現方法が確定

---

### Q3: Entropyモード時のスライダー挙動

**質問日時**: 2026-04-24
**カテゴリ**: UI設計
**背景**: Entropyモード時にスライダーを読み取り専用にするか、編集可能にするかで、ステート管理の複雑さが変わるため

**回答**: 読み取り専用（推奨）

**信頼性への影響**:
- この回答により、スライダーの挙動が 🔴 → 🔵 に確定
- REQ-201（Entropy時は読み取り専用）の実現方法が確定
- Manualに切り替えた時はエントロピー重みを引き継いで編集可能（REQ-301）
- エントロピー重みの「上書き防止」と「微調整」の両立が確認できた

---

## ヒアリング結果サマリー

### 確認できた事項
- WeightModeセレクタは手法セレクタの横に配置
- Entropy計算はWeightMode切替時に自動実行
- Entropyモード時はスライダー読み取り専用、Manual切替で編集可能に

### 設計方針の決定事項
- Entropy法はMcdmMethod enumには追加しない（重み決定手法として独立管理）
- AppMessageに `EntropyDone(EntropyResult)` を追加
- McdmRankChartに `weight_mode: WeightMode` と `entropy_result: Option<EntropyResult>` を追加

### 残課題
- なし（全主要項目が確認済み）
