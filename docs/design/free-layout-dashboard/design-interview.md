# Free Layout Dashboard 設計ヒアリング記録

**作成日**: 2026-04-12

## ヒアリング目的

既存の egui-app 実装を踏まえ、「UIの自由度向上」要件の不明点を明確化した。

---

## Q1: 右パネル追加後の左パネルの扱い

**カテゴリ**: アーキテクチャ  
**背景**: 左パネルにはチャート選択チェックボックスがあるが、右パネルがそれを代替する場合の競合を避ける必要があった。

**質問**: 右パネル（ハンバーガーメニュー）を追加した場合、左パネルのチャート選択チェックボックスはどうしますか？

**回答**: **左パネルは残す（フィルター専用）**

**信頼性への影響**:
- 左パネル: チャート選択を削除し、Filters・Color Mode のみ残す（🔴 → 🔵）
- 右パネル: チャート選択 + TrialTable を一覧化（🔴 → 🔵）

---

## Q2: セル結合の操作方法

**カテゴリ**: データモデル / UI  
**背景**: グリッドの「上段を横長で使う」ためのセル結合操作の UX を決める必要があった。

**質問**: グリッドのセル結合はどのように操作しますか？

**回答**: **セル右クリックでメニューからサイズ変更**

**信頼性への影響**:
- コンテキストメニュー実装が確定（🔴 → 🔵）
- egui の `ui.context_menu(|ui|{...})` を利用

---

## Q3: グリッドの最大行列数

**カテゴリ**: アーキテクチャ  
**背景**: デフォルト 2×2 を超えた場合の上限設計が必要だった。

**質問**: キャンバスのグリッド構成は最大何行×何列まで対応しますか？

**回答**: **自由に行列を追加（上限なし）**

**信頼性への影響**:
- `GridLayout` は `Vec<Vec<GridCell>>` の動的サイズで実装（🔴 → 🔵）
- 行追加/削除ボタンを UI に追加

---

## ヒアリング結果サマリー

### 確認できた事項
- 左パネルはフィルター専用として残す
- セル結合は右クリックコンテキストメニューで操作
- グリッドは行列を自由に追加できる（制限なし）

### 設計方針の決定事項
- `visible_charts: HashSet<ChartId>` を廃止し `GridLayout` に置き換え
- `BottomPanel` を廃止し `PanelItem::TrialTable` として右パネルからD&Dで配置
- `right_panel.rs` を新規作成（SidePanel::right + 折りたたみ）
- `grid_canvas.rs` を新規作成（自由グリッドレンダラー）

### 残課題
- セル結合と D&D の競合（結合セルへのドロップ防止の実装詳細）
- 行列が増えた際のセル高さ/幅の計算式（egui の `available_size` で対応予定）
- セッション保存（`io/session.rs`）への `GridLayout` シリアライズ追加

### 信頼性レベル分布

**ヒアリング後**:
