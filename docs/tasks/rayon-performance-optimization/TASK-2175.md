## タスク概要

`rust_core/src/sensitivity/analysis/common.rs` の `run_tree_metric_for_all_objectives` において、
目的変数ごとのループを `rayon::par_iter()` で並列化する。
`TreeMetric` 実装体はいずれも `&self` 参照のみ使用し状態を持たないため、
`where M: TreeMetric + Send + Sync` 境界を追加することで安全に並列化できる。

```rust
// 変更前

pub(super) fn run_tree_metric_for_all_objectives<M: TreeMetric>(
    metric: &M,

    // ...

// 変更後
use rayon::prelude::*;
// ...

pub(super) fn run_tree_metric_for_all_objectives<M: TreeMetric + Send + Sync>(
    metric: &M,
    x_matrix: &[Vec<f64>],
    objective_columns: &[Vec<f64>],
    param_count: usize,
    objective_count: usize,
) -> TreeImportanceResult {
    let results: Vec<(Vec<f64>, f64)> = objective_columns
        .par_iter()
        .map(|y| run_tree_metric_for_objective(metric, x_matrix, y))
        .collect();
    // ...
}
```

### スレッドセーフ性確認事項 🔵

| リソース | アクセス方法 | スレッドセーフ性 |
|---------|------------|----------------|
| `metric: &M` | 不変参照のみ (`&self`) | `M: Sync` で保証 |
| `x_matrix: &[Vec<f64>]` | 不変参照 | `&[_]` は `Sync` |
| `objective_columns` | `par_iter()` で要素ごとに分配 | 各スレッド独立 |
| LightGBM Booster（訓練） | 目的変数ごとに独立インスタンス作成 | REQ-101: インスタンス独立でスレッドセーフ |

### 呼び出し元の変更確認 🔵

`run_tree_metric_for_all_objectives` の呼び出し元:
- `sensitivity/analysis/full.rs` — `RfAnovaMetric`、`MdiMetric`、`ShapMetric`、`PermutationMetric` を渡している
- `sensitivity/analysis/selected.rs` — `RfAnovaMetric` を渡している

`RfAnovaMetric`・`MdiMetric`・`ShapMetric`・`PermutationMetric` はすべてゼロサイズ構造体（フィールドなし）のため、
`Send + Sync` は自動実装される。コンパイラが確認すれば十分で手動実装は不要。

## エラーハンドリング

- `run_tree_metric_for_objective` は内部で `Option` を返し、失敗時は空のインポータンスを返す設計（既存動作を維持）
- rayon のパニックハンドリング: 各スレッドのパニックはメインスレッドに伝播される（`collect()` 時に `panic!` が再発生）。既存動作と同等。
