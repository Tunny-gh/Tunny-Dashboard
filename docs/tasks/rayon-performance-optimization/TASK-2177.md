## タスク概要

`rust_core/src/sensitivity/permutation.rs` の `compute_from_prepared` において、
現行の「1 つの `x_eval_work` を in-place 共有」設計を
「各スレッドが `x_eval.to_vec()` の独立コピーを保持」設計に変更し、
`(0..p).into_par_iter()` で特徴量ループを並列化する。

LightGBM 推論（`lgbm_mse`）はトレーニングを行わず、既存 Booster の予測のみのため
インスタンス共有しても読み取り専用でスレッドセーフ（REQ-103 設計ヒアリング済み）。

### 変更内容 🔵

**信頼性**: 🔵 *設計文書 architecture.md §4・設計ヒアリング Q2（特徴量ごとに x_eval コピー）より*

```rust
// 変更前
use super::constants::{...};
use super::tree_common::{normalize, permute_column_inplace, prepare_training_data, PreparedData};
use crate::core::lgbm::{lgbm_mse, mse_to_r_squared, train_lgbm_rf, LgbmRfConfig};

pub(super) fn compute_from_prepared(data: &PreparedData) -> Option<(Vec<f64>, f64)> {
    // ...
    let mut x_eval_work = x_eval.to_vec();
    let mut importances = vec![0.0f64; p];
    for feature_idx in 0..p {
        let orig_col: Vec<f64> = x_eval_work.iter().map(|r| r[feature_idx]).collect();
        let mut delta_sum = 0.0f64;
        for repeat_idx in 0..PFI_N_REPEATS {
            // ...
            for (i, row) in x_eval_work.iter_mut().enumerate() {
                row[feature_idx] = orig_col[i];
            }
            permute_column_inplace(&mut x_eval_work, feature_idx, seed);
            let permuted_mse = lgbm_mse(&booster, &x_eval_work, y_eval).unwrap_or(baseline_mse);
            delta_sum += (permuted_mse - baseline_mse).max(0.0);
        }
        for (i, row) in x_eval_work.iter_mut().enumerate() {
            row[feature_idx] = orig_col[i];
        }
        importances[feature_idx] = delta_sum / PFI_N_REPEATS as f64;
    }
    normalize(&mut importances);
    // ...
}

// 変更後
use rayon::prelude::*;
use super::constants::{...};
use super::tree_common::{normalize, permute_column_inplace, prepare_training_data, PreparedData};
use crate::core::lgbm::{lgbm_mse, mse_to_r_squared, train_lgbm_rf, LgbmRfConfig};

pub(super) fn compute_from_prepared(data: &PreparedData) -> Option<(Vec<f64>, f64)> {
    // ...（LightGBM 訓練と baseline_mse 計算は変更なし）

    let mut importances: Vec<f64> = (0..p)
        .into_par_iter()
        .map(|feature_idx| {
            // 各スレッドが x_eval の独立コピーを保持（競合排除）
            let mut x_work = x_eval.to_vec();
            let orig_col: Vec<f64> = x_work.iter().map(|r| r[feature_idx]).collect();

            let mut delta_sum = 0.0f64;
            for repeat_idx in 0..PFI_N_REPEATS {
                let seed = PFI_SEED_BASE
                    + (feature_idx as u64) * (PFI_N_REPEATS as u64)
                    + (repeat_idx as u64);
                for (i, row) in x_work.iter_mut().enumerate() {
                    row[feature_idx] = orig_col[i];
                }
                permute_column_inplace(&mut x_work, feature_idx, seed);
                let permuted_mse = lgbm_mse(&booster, &x_work, y_eval).unwrap_or(baseline_mse);
                delta_sum += (permuted_mse - baseline_mse).max(0.0);
            }
            delta_sum / PFI_N_REPEATS as f64
        })
        .collect();

    normalize(&mut importances);
    let r_squared = mse_to_r_squared(baseline_mse, y_eval);
    Some((importances, r_squared))
}
```

### スレッドセーフ性確認事項 🔵

| リソース | アクセス方法 | スレッドセーフ性 |
|---------|------------|----------------|
| `booster` (LightGBM Booster) | `lgbm_mse` 内部で `&booster` として参照 | LightGBM 推論は読み取り専用でスレッドセーフ |
| `x_eval` | スレッドごとに `.to_vec()` でコピー | 各スレッド独立 |
| `y_eval: &[f64]` | 不変参照 | `Sync` |
| `baseline_mse: f64` | コピー（`f64` は `Copy`） | スレッドセーフ |
| `permute_column_inplace` | スレッドローカルな `x_work` のみ変更 | 安全 |

### メモリコスト 🟡

**信頼性**: 🟡 *性能特性から妥当な推測*

- 追加メモリ = `n_eval × p × 8 bytes × (rayon スレッド数 - 1)`
- `n_eval=160, p=10` の場合: `160 × 10 × 8 = 12.8 KB` × コア数分
- 8 コアで約 100 KB — 許容範囲内

## エラーハンドリング

- `lgbm_mse` が `None` を返す場合: `.unwrap_or(baseline_mse)` で `delta += 0.0` になる（既存動作を維持）
- `p = 0` の場合: `(0..p).into_par_iter()` が空イテレータを返し `importances` が空になる（既存動作を維持）
