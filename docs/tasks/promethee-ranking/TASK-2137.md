## 実装詳細

### 1. PrometheeResult 構造体 🔵

**信頼性**: 🔵 *REQ-PR-002 より*

**実装ファイル**: `rust_core/src/mcdm/promethee.rs`

```rust
#[derive(Debug, Clone, serde::Serialize)]
pub struct PrometheeResult {
    pub phi_plus: Vec<f64>,           // 正フロー [0,1], len = n_trials
    pub phi_minus: Vec<f64>,          // 負フロー [0,1], len = n_trials
    pub phi_net: Vec<f64>,            // 純フロー [-1,1], len = n_trials
    pub ranked_indices_i: Vec<u32>,   // PROMETHEE I 順: Φ+ 降順
    pub ranked_indices_ii: Vec<u32>,  // PROMETHEE II 順: Φnet 降順
    pub duration_ms: f64,
}
```

### 2. compute_promethee 公開関数 🔵

**信頼性**: 🔵 *REQ-PR-001・implementation-guide.md Step 1-2 より*

フロー:
1. `super::validate_inputs()` でバリデーション
2. `super::filter_valid_indices()` で NaN 除外
3. 全 NaN の場合は `zero_result()` を返す
4. `compute_thresholds()`: range_j, p_j = 0.2 × range_j を計算
5. `extract_valid_values()`: 有効試行を行優先フラット Vec に収める
6. `compute_preference_matrix()`: O(n²) で π(a,b) を計算
7. `compute_flows()`: Φ+(i) = Σπ(i,b)/(n-1), Φ-(i) = Σπ(b,i)/(n-1)
8. phi_net[i] = phi_plus[i] - phi_minus[i]
9. `rank_promethee_i()`, `rank_promethee_ii()` でランキング

### 3. linear_preference 補助関数 🔵

**信頼性**: 🔵 *REQ-PR-005・ユーザヒアリング（Linear のみ・q=0 固定）より*

```rust
fn linear_preference(d: f64, p: f64) -> f64 {
    if d <= 0.0 { return 0.0; }
    if p <= 0.0 { return 1.0; }
    if d >= p   { return 1.0; }
    d / p
}
```

d = minimize の場合: vb - va（a の方が小さければ d > 0 → a が優位）

### 4. compute_preference_matrix (O(n²)) 🔵

**信頼性**: 🔵 *REQ-PR-006・architecture.md パフォーマンスより*

行優先フラット Vec<f64> で実装してキャッシュ効率を向上させる。
`π(a,b) = Σ_j weight_j × P_j(d_j(a,b))`

### 5. ランキング関数 🔵

**信頼性**: 🔵 *REQ-PR-007（PROMETHEE I）・REQ-PR-008（PROMETHEE II）より*

- `rank_promethee_i`: valid 試行を Φ+ 降順でソート、タイブレークは Φ- 昇順、NaN 試行を末尾に配置
- `rank_promethee_ii`: valid 試行を Φnet 降順でソート、NaN 試行を末尾に配置

### 6. NaN 処理 🔵

**信頼性**: 🔵 *REQ-PR-004・既存 topsis.rs/vikor.rs パターンより*

- `filter_valid_indices` で NaN 含有試行を除外
- NaN 試行の phi_plus/phi_minus/phi_net = 0.0（初期値のまま）
- ranked_indices では NaN 試行を末尾に配置

## 注意事項

- `compute_preference_matrix` は O(n²) のため行優先フラット Vec で実装してキャッシュ効率を確保する
- `linear_preference` で p=0.0（range=0）の場合は d>0 なら 1.0 を返す（ゼロ除算を防ぐ）
- ランキング関数は `partial_cmp` の unwrap_or で NaN を安全に処理する
- テスト命名は `tc_pr_XXX_NN` の規則に従う（既存 topsis.rs の `tc_1615_XX` 規則を参照）
