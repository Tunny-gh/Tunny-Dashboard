### 1. ビルド品質確認 🔵

**信頼性**: 🔵 *NFR-001・TC-NFR-001-01より*

**実行コマンド**:

```powershell
cd egui-app
rtk cargo build 2>&1 | Select-String -Pattern "warning"
```

**期待結果**: 出力行数ゼロ

**警告が出た場合の対処**:
- `unused import` → 該当ファイルの不要な `use` 文を削除
- `dead_code` → 定数が参照されていない場合は参照箇所を確認
- `unused variable` → 変数名に `_` プレフィックスを追加またはコードを修正

### 6. 問題修正対応フロー 🔵

**信頼性**: 🔵 *移行ステップ設計・dataflow.mdより*

問題が検出された場合の修正手順:

1. **パス更新漏れ** (`render::colormap` 残存):
   - 該当ファイルで `crate::render::colormap` → `crate::theme::colormap` に修正
   - `use crate::render::colormap::` → `use crate::theme::colormap::` に修正

2. **インライン色残存**:
   - 対応する定数名を `chart_colors.rs` で確認
   - `Color32::from_rgb(x, y, z)` → `crate::theme::chart_colors::COLOR_XXX` に置換

3. **ビルドエラー**:
   - エラーメッセージを確認し、型不一致・未解決参照を修正
   - `cargo check` で段階的に確認

4. **テスト失敗**:
   - 失敗したテスト名を確認
   - ColorMap の動作に変更がないことを確認（ファイル移動のみのため通常は変化なし）
