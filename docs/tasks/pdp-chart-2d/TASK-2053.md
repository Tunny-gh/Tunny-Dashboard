## 実装詳細

### 1. GpModel 構造体拡張 🔵

**信頼性**: 🔵 *設計文書 architecture.md より*

`GpModel` にコレスキー因子と観測ノイズを保持するフィールドを追加する。

**実装ファイル**: `rust_core/src/core/kriging/gaussian_process/model.rs`

```rust
pub(crate) struct GpModel {
    pub alpha: Vec<f64>,
    pub x_train: Vec<Vec<f64>>,
    pub log_ls: Vec<f64>,
    pub log_sf: f64,
    pub l: Vec<Vec<f64>>,    // 追加: chol(K_XX + σ_n² I)
    pub log_sn: f64,         // 追加: 観測ノイズ対数スケール
}
```

### 2. train_gp でのフィールド保存 🔵

**信頼性**: 🔵 *設計文書 architecture.md より*

`training.rs` の `train_gp` 関数末尾で、既に計算済みの `l = cholesky(&k)` を `GpModel` に設定する。`cholesky` 関数は既に内部で呼び出されており、計算を再利用するだけでよい。

**実装ファイル**: `rust_core/src/core/kriging/gaussian_process/training.rs`

### 3. predict_variance 実装 🔵

**信頼性**: 🔵 *設計文書 architecture.md より*

GP事後分散の計算式に基づき `predict_variance` を実装する。

**実装ファイル**: `rust_core/src/core/kriging/gaussian_process/inference.rs`

```rust
// var(x*) = k(x*,x*) + σ_n² - ||L^{-1} k(X,x*)||²
// L は chol(K_XX + σ_n² I) として GpModel に保存済み
```

前進代入 `forward_sub(L, k_*)` の実装が必要（または既存の `cholesky_solve` ロジックを参照）。

## 単体テスト要件

### テストケース1: predict_variance_nonnegative 🔵

**信頼性**: 🔵 *設計文書 architecture.md より*

**Given/When/Then**

- When: 任意の `x_test` に対して `predict_variance` を呼び出す

**テストファイル**: `rust_core/src/core/kriging/gaussian_process/inference.rs`

### テストケース2: predict_variance_at_training_point_low 🔵

**信頼性**: 🔵 *設計文書 architecture.md より*

**Given/When/Then**
- Given: 学習データ点 `x_i` を含む `GpModel`
- When: `predict_variance(model, x_i)` を呼び出す
- Then: 結果が観測ノイズ程度に小さい（`σ_n²` のオーダー）

**テストファイル**: `rust_core/src/core/kriging/gaussian_process/inference.rs`

### テストケース3: predict_variance_decreases_near_data 🔵

**信頼性**: 🔵 *設計文書 architecture.md より*

**Given/When/Then**

- Then: 学習点から離れるほど分散が大きくなる傾向がある

**テストファイル**: `rust_core/src/core/kriging/gaussian_process/inference.rs`
