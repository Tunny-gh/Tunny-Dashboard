### 6. フィルタ不一致警告（REQ-002-E） 🟡

**信頼性**: 🟡 *REQ-002-E の「ユーザーへの警告」実装方法は妥当な推測*

```rust
fn apply_filter_with_validation(
    loaded: &FilterSnapshot,
    app_state: &mut AppState,
) {
    let current_keys: std::collections::HashSet<_> = app_state.filter_ranges.keys().collect();
    let loaded_keys: std::collections::HashSet<_> = loaded.filter_ranges.keys().collect();
    let mismatched: Vec<_> = loaded_keys.difference(&current_keys).collect();

    // 一致するキーのみ適用
    for (k, v) in &loaded.filter_ranges {
        if current_keys.contains(k) {
            app_state.filter_ranges.insert(k.clone(), *v);
        }
    }

    // 不一致がある場合は警告フラグを立てる（UI 側でトースト表示）
    if !mismatched.is_empty() {
        app_state.show_filter_mismatch_warning = true;
        // warning_message に不一致の軸名を格納
    }
}
```

## 単体テスト要件

### テストケース 1: `apply_filter_with_validation` — 不一致軸スキップ 🔵

**信頼性**: 🔵 *REQ-002-E より*

**Given**: `app_state.filter_ranges` に `{"x1": (0.0, 1.0)}` が存在し、`loaded.filter_ranges` に `{"x1": (0.2, 0.8), "x2": (0.0, 1.0)}` が含まれる
**When**: `apply_filter_with_validation()` を呼ぶ
**Then**: `x1` の範囲が `(0.2, 0.8)` に更新され、`x2` は無視される

### テストケース 2: `build_session_snapshot` のフィールド確認 🔵

**信頼性**: 🔵 *REQ-004-B より*

**Given**: 各フィールドが設定済みの `AppState` と `LayoutState`
**When**: `build_session_snapshot(app_state, layout_state)` を呼ぶ
**Then**: `tradeoff_weights`・`layout_mode`・`pinned_trials` が含まれる `SessionSnapshot` が返る
