## タスク概要

D&Dペイロード型を `PanelItem` から `DragPayload` に移行する。右パネルのドラッグソースとグリッドのドロップゾーンを DragPayload に対応させ、新規配置と移動の両方を処理できるようにする。このタスクでは右パネルからの新規配置のみを対応し、セル間移動のドラッグソースは次タスクで実装する。

## 実装詳細

### 1. 右パネルのドラッグソース変更 🔵

**信頼性**: 🔵 *設計文書 architecture.md より*

**実装ファイル**: `egui-app/src/ui/right_panel.rs`

```rust
// 変更前
ui.dnd_drag_source(drag_id, item.clone(), |ui| { ui.label(item.label()); });

// 変更後
ui.dnd_drag_source(drag_id, DragPayload::NewWidget(item.clone()), |ui| {
    ui.label(item.label());
});
```

`use crate::state::layout_state::DragPayload;` のインポートを追加。

### 2. グリッドのドロップゾーン変更 🔵

**信頼性**: 🔵 *設計文書 architecture.md・dataflow.md より*

**実装ファイル**: `egui-app/src/ui/grid_canvas.rs`

```rust
// 変更前
let (inner_resp, payload) = child_ui.dnd_drop_zone::<PanelItem, _>(...);
if let Some(dropped) = payload {
    pending_drops.push((r, c, (*dropped).clone()));
}

// 変更後
let (inner_resp, payload) = child_ui.dnd_drop_zone::<DragPayload, _>(...);
if let Some(dropped) = payload {
    let item = (*dropped).item().clone();
    pending_drops.push((r, c, item));
}
```

`DragPayload::MoveFromCell` の場合も `GridLayout::place()` が内部で元セルをクリアするため、同じ `pending_drops` 処理で対応可能。

### 3. ホバー判定の更新 🔵

**信頼性**: 🔵 *既存コード分析より*

`has_any_payload` は型なしチェックのため変更不要。ただし `dnd_drop_zone` の型パラメータを `PanelItem` から `DragPayload` に変更するため、`DragPayload` 型のペイロードのみが受け入れられる。
