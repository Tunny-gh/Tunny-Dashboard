## 実装詳細

### 1. DLL の `libs/` への移動 🔵

**信頼性**: 🔵 *ユーザヒアリング（Q2: libs/ 配置選択）より*

リポジトリルートに配置されている DLL を `libs/` に移動する。

**操作対象**:
```
{workspace_root}/lib_lightgbm.dll   →  {workspace_root}/libs/lib_lightgbm.dll
{workspace_root}/lib_lightgbm.dylib →  {workspace_root}/libs/lib_lightgbm.dylib
```

実行コマンド（Git 管理下のため `git mv` を使用）:
```bash
mkdir -p libs
git mv lib_lightgbm.dll libs/lib_lightgbm.dll
git mv lib_lightgbm.dylib libs/lib_lightgbm.dylib
```

### 2. `rust_core/build.rs` の新規作成 🔵

**信頼性**: 🔵 *architecture.md ビルド設定セクション + ユーザヒアリングより*

**実装ファイル**: `rust_core/build.rs`

```rust
fn main() {
    let manifest_dir = std::path::PathBuf::from(env!("CARGO_MANIFEST_DIR"));
    // rust_core/Cargo.toml からワークスペースルートの libs/ を指す
    let libs_dir = manifest_dir.parent().unwrap().join("libs");
    println!("cargo:rustc-link-search=native={}", libs_dir.display());
    println!("cargo:rerun-if-changed=build.rs");
}
```

**補足**: `manifest_dir` は `rust_core/` を指す。`.parent()` でワークスペースルートを取得し、`libs/` を結合する。

### 3. `rust_core/Cargo.toml` への lightgbm 依存追加 🟡

**信頼性**: 🟡 *lightgbm-rs クレートのバージョンはビルド確認後に固定（設計文書 残課題より）*

**実装ファイル**: `rust_core/Cargo.toml`

```toml
[dependencies]
faer = "0.24.0"
serde = { version = "1", features = ["derive"] }
serde_json = "1"
lightgbm = "*"   # ← 追加（バージョンはビルド確認後に固定）
```

**注意**: `lightgbm` クレートは LightGBM v3.x の `predict_contrib` API を必要とする。ビルド確認後に適切なバージョンを `*` から固定する。

### 4. WASM ビルド設定の削除確認 🔵

**信頼性**: 🔵 *要件定義書 REQ-201 + ユーザヒアリング（Q6: WASM 廃止確認）より*

`rust_core/src/lib.rs` および関連ファイルに `#[cfg(target_arch = "wasm32")]` 等の WASM 向けコードがある場合は削除する。

確認コマンド:
```bash
grep -r "wasm32\|wasm-pack\|wasm_bindgen" rust_core/src/
```

### 5. ビルド確認 🔵

**信頼性**: 🔵 *REQ-401 + NFR-201 より*

```bash
rtk cargo check -p tunny-core
```

エラーが出た場合は以下を確認:
- `libs/` パスが正しいか
- `lightgbm` クレートのバージョンが利用可能か
- Windows の場合 `lib_lightgbm.lib` インポートライブラリが必要か（GNU toolchain なら不要）

## 注意事項

- `git mv` を使って DLL を移動することで Git 履歴を保持する
- `lib_lightgbm.lib`（Windows インポートライブラリ）が存在しない場合、GNU toolchain（`x86_64-pc-windows-gnu`）なら DLL のみで動作する可能性がある。MSVC toolchain の場合は `.lib` が必要になる場合があるため、ビルドエラーが出た際に確認する
- `lightgbm` クレートのバージョンは `*` でビルドが通った後、`Cargo.lock` に記録された実際のバージョンを `Cargo.toml` に固定すること
