### 4. COMPLETE(state=1)検出時のTrialRowV2構築 🔵

**信頼性**: 🔵 *既存 append_journal_diff の op_code=6 処理フロー・PendingTrial構造より*

既存の `append_journal_diff` の `op_code=6` (complete) 処理を拡張する。`state_val == 1` (COMPLETE) を検出した際、`PendingTrial` から `TrialRowV2` を構築する:

- `pending.values` → `TrialRowV2.objectives`
- `pending.param_display` → `TrialRowV2.params`
- `pending.param_category_label` → `TrialRowV2.param_categories`
- `pending.user_attrs_numeric` → `TrialRowV2.user_attrs_numeric`
- `pending.user_attrs_string` → `TrialRowV2.user_attrs_string`
- `pending.constraint_values` → `TrialRowV2.constraint_values`
- `pending.study_idx` → `TrialRowV2.study_id`

### 5. パラメータdistributionデコード処理 🔵

**信頼性**: 🔵 *既存 decode_param_value・extract_categorical_label 関数の再利用より*

既存の `decode_param_value` と `extract_categorical_label` をそのまま再利用する。新しい関数の作成は不要:

- `decode_param_value(internal, distribution)` → Log変換の逆変換、IntDistribution のstep/low 補正

### 6. find_consumed_bytes の再利用 🔵

**信頼性**: 🔵 *既存 find_consumed_bytes 関数の再利用より*

不完全行（最後の `\n` 以降）をスキップする既存ロジックをそのまま再利用:

```rust
fn find_consumed_bytes(data: &[u8]) -> usize {
    match data.iter().rposition(|&b| b == b'\n') {
        Some(pos) => pos + 1,
        None => 0,
    }
}
```

## thread_local! 状態の設計 🔵

**信頼性**: 🔵 *既存 `append_journal_diff` の thread_local! パターンより*

`append_journal_diff_v2` は既存の `STATE` thread_local! を共有するのではなく、新規の thread_local! を定義する:

```rust
/// v2用のパーサー状態
struct LiveUpdateStateV2 {
    next_trial_id: u32,
    pending: HashMap<u32, PendingTrial>,
    /// Study毎の完了トライアル数カウンタ
    study_completed_counts: HashMap<u32, usize>,
}

thread_local! {
    static STATE_V2: RefCell<LiveUpdateStateV2> = RefCell::new(LiveUpdateStateV2::default());
}
```

**理由**: 既存の `append_journal_diff` のテストと状態を分離し、互いに影響を与えないようにする。
