- **REQ-LU-401**: スレッドの安全な開始・停止ライフサイクルを提供する
- **REQ-LU-404**: `SyncSender<AppMessage>`経由でUIスレッドに通知を送信する

## 実装詳細

### 1. live_update_poller.rs 新規作成 🔵

**信頼性**: 🔵 *architecture.md DD-01「ポーリングスレッド構造」より*

**実装ファイル**: `egui-app/src/io/live_update_poller.rs`

新規モジュールファイルを作成する。既存の`study_worker.rs`が`OnceLock`とコマンドチャネルを使用しているのに対し、本モジュールは`AtomicBool`による停止信号と`AtomicU64`による間隔制御を使用する、よりシンプルなパターンを採用する。

### 2. LiveUpdatePoller 構造体の定義 🔵

**信頼性**: 🔵 *architecture.md DD-04「LiveUpdatePoller構造体」より*

```rust
/// ライブアップデートのポーリングスレッドを管理する
pub struct LiveUpdatePoller {
    /// スレッド停止信号（trueで停止要求）
    stop_signal: Arc<AtomicBool>,
    /// ポーリング間隔（ミリ秒）
    interval_ms: Arc<AtomicU64>,
    /// ポーリングスレッドのJoinHandle
    thread_handle: Option<JoinHandle<()>>,
}
```

### 3. start_poller 関数の実装 🔵

**信頼性**: 🔵 *architecture.md DD-01「スレッド起動フロー」・既存app.rsのspawn_taskパターンより*

```rust
/// ポーリングスレッドを起動し、LiveUpdatePollerを返す
pub fn start_poller(
    context: LiveUpdateContext,
    tx: SyncSender<AppMessage>,
    interval_ms: u64,
) -> LiveUpdatePoller
```

- `stop_signal`と`interval_ms`を`Arc`でラップし、スレッドと共有
- `std::thread::spawn`でポーリングスレッドを起動
- 既存の`app.rs`における`spawn_task(tx, move || { ... })`パターンを参考にする

### 4. ポーリングループの実装 🔵

**信頼性**: 🔵 *dataflow.md フロー2「ポーリング→差分検出→メッセージ送信」より*

ポーリングスレッド内のループ処理:

1. `std::thread::sleep(Duration::from_millis(interval))` で待機
2. `stop_signal.load(Ordering::Relaxed)` で停止確認 → trueならbreak
3. `fs::metadata(&file_path)` でファイルサイズを取得
4. 前回サイズと比較 → 変化なければループ先頭に戻る
5. 変化があれば差分バイト数を計算し、`File::open` + `Seek::seek` + `Read::read` で差分を読み込む
6. `append_journal_diff_v2` に差分バイトを渡す
7. `tx.send(AppMessage::LiveUpdateDone)` でUIスレッドに通知
8. 前回サイズを更新してループ継続

### 5. stop_poller 関数の実装 🔵

**信頼性**: 🔵 *REQ-LU-401「安全な停止」より*

```rust
/// ポーリングスレッドに停止信号を送り、終了を待機する
pub fn stop_poller(poller: &mut LiveUpdatePoller)
```

- `stop_signal.store(true, Ordering::Relaxed)` で停止要求
- `thread_handle.take()` でJoinHandleを取得し、`join()` でスレッド終了を待機
- `join()`の結果はログ出力のみ（ポーリングスレッド内でのpanicは上位で処理）

### 6. update_interval 関数の実装 🔵

**信頼性**: 🔵 *REQ-LU-005「動的間隔変更」より*

```rust
/// ポーリング間隔を動的に変更する
pub fn update_interval(poller: &LiveUpdatePoller, new_interval_ms: u64)
```

- `interval_ms.store(new_interval_ms, Ordering::Relaxed)` で間隔を更新
- スレッドは次回ループ冒頭で最新値を読み取るため、即座に反映される

### 7. mod.rs へのモジュール登録 🔵

**信頼性**: 🔵 *標準的なRustモジュールパターンより*

**実装ファイル**: `egui-app/src/io/mod.rs`


## 単体テスト要件

### テストケース1: start_pollerでスレッドが起動しLiveUpdatePollerが返される 🔵

**信頼性**: 🔵 *REQ-LU-401・スレッド起動の基本動作より*

**Given**: 有効な`LiveUpdateContext`と`SyncSender<AppMessage>`がある
**When**: `start_poller`を呼び出す
**Then**: `LiveUpdatePoller`が返され、内部の`thread_handle`が`Some`である

**テストファイル**: `egui-app/src/io/live_update_poller.rs` (#[cfg(test)] mod tests)

### テストケース2: stop_pollerでスレッドが正常終了する 🔵

**信頼性**: 🔵 *REQ-LU-401・停止ライフサイクルより*

**Given**: 起動済みの`LiveUpdatePoller`がある
**When**: `stop_poller`を呼び出す
**Then**: スレッドが終了し、`thread_handle`が`None`になる

### テストケース3: ファイルに追記がある場合LiveUpdateDoneメッセージが送信される 🔵

**信頼性**: 🔵 *REQ-LU-002・REQ-LU-003・dataflow.md フロー2より*

**Given**: ポーリング対象のファイルが存在し、ポーラーが起動している
**When**: ファイルにデータが追記される
**Then**: 受信側のチャネルから`AppMessage::LiveUpdateDone`が取得できる

### テストケース4: ファイルサイズが変化しない場合メッセージが送信されない 🔵

**信頼性**: 🔵 *REQ-LU-002・差分検出の基本仕様より*

**Given**: ポーリング対象のファイルが存在し、内容が変化しない
**When**: ポーリング間隔分の時間が経過する
**Then**: 受信側のチャネルにメッセージが送信されない

### テストケース5: stop_signal=trueでスレッドが自ら終了する 🔵

**信頼性**: 🔵 *REQ-LU-401・停止信号の動作確認より*

**Given**: 起動済みの`LiveUpdatePoller`がある
**When**: 外部から`stop_signal.store(true)`を設定する
**Then**: スレッドがループを抜けて自ら終了する

### テストケース6: update_intervalで間隔が動的に変更される 🔵

**信頼性**: 🔵 *REQ-LU-005・動的間隔変更より*

**Given**: 起動済みの`LiveUpdatePoller`がある（初期間隔: 1000ms）
**When**: `update_interval`で500msに変更する
**Then**: ポーリングサイクルが500ms間隔に切り替わる

**テスト方法**: テスト用の小さなファイルで2サイクル分の時間を計測し、間隔変更後にサイクル時間が短縮されることを確認する。
