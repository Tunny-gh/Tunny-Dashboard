### 1. LiveUpdateDoneメッセージ拡張 🔵

**信頼性**: 🔵 *dataflow.md フロー3・architecture.md DD-03 より*

**実装ファイル**: `egui-app/src/messages.rs`

```rust
// 変更前
LiveUpdateDone {
    new_trial_count: usize,

    new_indices: Vec<u32>,

LiveUpdateDone {
    new_trial_count: usize,
    pareto_updated: bool,
    new_indices: Vec<u32>,
    // 新規フィールド
    new_trial_rows: Vec<TrialRow>,           // 新規パース済みトライアルデータ
    updated_study_counts: Vec<(u32, usize)>, // (study_id, new_completed_trials)
    consumed_bytes: u64,                     // 消費したバイト数

```

### 2. MessageHandler LiveUpdateDone分岐の実装 🔵

**信頼性**: 🔵 *dataflow.md フロー3・REQ-LU-007 より*

**実装ファイル**: `egui-app/src/message_handler.rs`

現在のTODOプレースホルダーを以下の処理で置き換える:

```rust
AppMessage::LiveUpdateDone {
    new_trial_count,
    pareto_updated: _,
    new_indices: _,
    new_trial_rows,
    updated_study_counts,
    consumed_bytes: _,
} => {
    if let Some(study) = &mut state.current_study {
        // 1. 新規TrialRowをtrial_rowsに追加
        study.trial_rows.extend(new_trial_rows);

        // 2. Paretoランク全再計算
        let all_ranks = tunny_core::pareto::compute_pareto_ranks(&study.trial_rows);
        study.pareto_indices = all_ranks;

        // 3. GPUバッファ再構築
        // (study selection flowと同様のバッファビルド処理)
        study.gpu_data = build_gpu_buffers(&study.trial_rows, &study.pareto_indices);
    }

    // 4. all_studiesのcompleted_trials更新
    for (study_id, new_count) in updated_study_counts {
        if let Some(meta) = state.all_studies.iter_mut().find(|m| m.id == study_id) {
            meta.completed_trials = new_count;
        }
    }

    // 注意: filter_ranges, selected_indices, is_loading は変更しない
}
```

### 3. TrialRowV2→TrialRow変換とtrial_rows追加 🔵

**信頼性**: 🔵 *既存study selection flowのパターンより*

新規パースされた`TrialRowV2`（LogParser出力）を既存`TrialRow`型に変換し、`current_study.trial_rows`の末尾に追加する。変換ロジックは初期ロード時の変換処理と同一。

### 4. Pareto全再計算 🔵

**信頼性**: 🔵 *tunny_core::pareto::compute_pareto_ranks 既存APIより*

`compute_pareto_ranks`に全トライアル（既存＋新規）を渡し、Paretoランクを再計算する。結果で`study.pareto_indices`を更新する。

### 5. GPUバッファ再構築 🔵

**信頼性**: 🔵 *既存GPUバッファビルド処理の再利用より*

positions, colors, sizes の各GPUバッファを全トライアル分で再構築する。study selection flow のバッファビルド処理と同じロジックを使用する。

### 6. ユーザー操作状態保持 🔵

**信頼性**: 🔵 *REQ-LU-006 より*

以下のAppStateフィールドはLiveUpdateDone処理で一切変更しない:
- `filter_ranges` — ユーザー設定フィルター範囲
- `selected_indices` — ユーザー選択状態
- `is_loading` — ローディング表示なし

### 7. all_studies メタデータ更新 🔵

**信頼性**: 🔵 *REQ-LU-008 より*

`updated_study_counts`に基づいて`all_studies`内の該当`StudyMeta`の`completed_trials`を更新する。
