## タスク概要

現在の `optimize_hyperparams` は L-BFGS の各イテレーションで `neg_lml`（LML 計算）と `log_ml_gradient`（勾配計算）を別々に呼び出しており、それぞれが独立した Cholesky 分解と K^{-1} 計算を行っている。これにより 1 イテレーションあたり ~4×O(N³) の計算量が発生している。

本タスクでは `log_ml_with_gradient(x, y, params) -> (f64, Vec<f64>)` を実装し、1回の Cholesky 分解で LML 値と勾配ベクトルを同時に計算する。これにより 1 イテレーションあたりの計算量を ~2×O(N³) に削減する。

**実装ファイル**: `rust_core/src/kriging.rs`

```rust
/// LML 値と勾配ベクトルを1回の Cholesky 分解で同時計算する
/// 
/// # 引数
/// - `x`: 訓練データ (n_samples × n_dims のフラット配列, 列優先)
/// - `y`: 目的関数値 (n_samples,)
/// - `params`: ハイパーパラメータ [log_ls0, log_ls1, log_sf, log_sn]
/// 
/// # 戻り値
/// `(lml_value, gradient_vec)` — LML 値（最大化対象）と 4 次元勾配ベクトル
pub fn log_ml_with_gradient(
    x: &[f64],
    y: &[f64],
    params: &[f64],
) -> (f64, Vec<f64>) {
    let n = y.len();
    // 1. カーネル行列構築（1回のみ）
    let k = build_kernel_matrix(x, params, n);
    // 2. Cholesky 分解（1回のみ）
    let l = cholesky(&k, n);
    // 3. alpha = L^{-T} L^{-1} y の計算
    let alpha = compute_alpha(&l, y, n);
    
    // LML 値: -0.5*(y^T alpha) - sum(log(diag(L))) - n/2*ln(2π)
    let data_fit: f64 = y.iter().zip(alpha.iter()).map(|(yi, ai)| yi * ai).sum();
    let log_det: f64 = (0..n).map(|i| l[i * n + i].ln()).sum();
    let lml = -0.5 * data_fit - log_det - 0.5 * n as f64 * std::f64::consts::LN_2 * std::f64::consts::PI.ln();
    
    // 4. K^{-1} 計算: K^{-1} = L^{-T} L^{-1}（N回の前進・後退代入）
    let k_inv = compute_k_inv(&l, n);
    
    // 5. W = alpha alpha^T - K^{-1} の計算
    // 6. 各ハイパーパラメータの偏微分: 0.5 * trace(W * dK/dθ)
    let grad = compute_gradient_from_w(x, params, &alpha, &k_inv, n);
    
    (lml, grad)
}
```

アーキテクチャ設計の通り、`optimize_hyperparams` 内で `neg_lml` + `log_ml_gradient` の2回呼び出しを `log_ml_with_gradient` の1回呼び出しに置き換える。

## 注意事項

- `compute_k_inv` は N×N の K^{-1} を計算するため、N=500 で ~250KB のメモリを使用する。N=1000 以上では ~8MB になる点に注意。
- Armijo 線探索内での評価は勾配不要のため、既存の `neg_lml` をそのまま使用すること。
- `log_ml_with_gradient` の戻り値は `(lml_value, gradient)` だが、L-BFGS では最小化のため `-lml_value` として使用すること。
