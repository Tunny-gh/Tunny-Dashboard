## 実装詳細

### 1. GPU バッファ構築での feasibility 対応 🟡
**信頼性**: 🟡 *要件定義書 REQ-CAV-050〜051 より（GPU バッファ構造は実装時に確認が必要）*

**実装ファイル**: `egui-app/src/ui/widgets/pareto_3d.rs` および `egui-app/src/render/gpu_buffer.rs`

3D チャートは wgpu でレンダリングされ、頂点バッファに色情報を含む。実装方針:
- `StudyView.numeric_column("is_feasible")` から feasibility を取得
- GPU バッファ構築時に infeasible 頂点の色を `COLOR_INFEASIBLE` に対応する RGBA に変換

```rust
// GPU バッファ構築ループ内（概要）
let feasible = is_feasible_col
    .and_then(|c| c.get(i))
    .map(|&v| v > 0.5)
    .unwrap_or(true);

let vertex_color = if feasible {
    existing_pareto_color(rank)
} else if self.show_infeasible {
    // COLOR_INFEASIBLE を wgpu 用 [f32; 4] に変換
    [56.0/255.0, 56.0/255.0, 56.0/255.0, 80.0/255.0]
} else {
    continue; // バッファから除外
};
```

注意: GPU バッファの具体的な実装は `pareto_3d.rs` のコード構造を確認してから判断する（🟡 実装時に調整が必要な可能性あり）

### 3. GPU バッファ再構築トリガー 🟡
**信頼性**: 🟡 *設計文書 architecture.md より（再構築トリガーの詳細は実装時に確認が必要）*

`show_infeasible` 変更時に GPU バッファを再構築する必要がある。既存の再構築ロジック（データ更新や Study 切替時のトリガー）に条件を追加する。

実装方針の候補:
- `show_infeasible` の変更を検出して `dirty` フラグを立てる
- 毎フレーム `show_infeasible` の前回値と比較し、変化があれば再構築する

## 注意事項
- TASK-2346 の完了（`show_infeasible` フィールド追加）が前提。必ず TASK-2346 完了後に着手すること
- `pareto_3d` は GPU リソース（wgpu バッファ等）を保持しているため、Study 切替時（message_handler.rs）では `Default::default()` でなく `show_infeasible` フィールドのみをリセットする（TASK-2346 で対応済み）
- GPU バッファ構築の具体的な API（`gpu_buffer.rs` の構造体・メソッド）は実装開始前に必ず確認すること（🟡 項目）
- premultiplied alpha の変換: `Color32::from_rgba_premultiplied(56, 56, 56, 80)` を wgpu の `[f32; 4]` 形式に変換する際は `[56.0/255.0 * (80.0/255.0), ...]` ではなく `[56.0/255.0, 56.0/255.0, 56.0/255.0, 80.0/255.0]` であることに注意（wgpu は non-premultiplied を期待する場合がある）
