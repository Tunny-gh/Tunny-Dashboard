## 実装詳細

### 1. 描画ループへの feasibility チェック追加 🔵
**信頼性**: 🔵 *要件定義書 REQ-CAV-040〜041 + 設計文書 architecture.md より*

**実装ファイル**: `egui-app/src/ui/widgets/pareto_2d.rs`

`show()` メソッドの描画ループ（`for i in displayed {...}` 部分）に以下を追加:
- ループ前に `let is_feasible_col = view.numeric_column("is_feasible");` を取得
- `let has_constraints = ctx.meta.has_constraints;` を取得
- ループ内で `let feasible = is_feasible_col.and_then(|c| c.get(i)).map(|&v| v > 0.5).unwrap_or(true);`
- `!feasible` の場合: `show_infeasible` が false ならスキップ、true なら `infeasible_pts` に追加
- feasible の場合: 従来の Pareto ランク分類ロジックをそのまま実行

```rust
// ループ前
let is_feasible_col = view.numeric_column("is_feasible");
let has_constraints = ctx.meta.has_constraints;

// ループ内
let feasible = is_feasible_col
    .and_then(|c| c.get(i))
    .map(|&v| v > 0.5)
    .unwrap_or(true);

if !feasible {
    if self.show_infeasible {
        infeasible_pts.push(/* point */);
    }
    continue;
}
// 以降は従来の Pareto ランク分類ロジック
```

## 注意事項
- TASK-2346 の完了（`show_infeasible` フィールド追加）が前提。必ず TASK-2346 完了後に着手すること
- `infeasible_pts` は既存の `non_pareto_pts` / `pareto_pts` と独立した Vec として管理し、描画順序を明示的に制御すること
